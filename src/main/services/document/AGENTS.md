# src/main/services/document — DOX child contract

Parent: `../AGENTS.md` (agent-runtime rail). Delegation targets have their own docs: `../desktop/AGENTS.md` (GUI automation) and `../browser/AGENTS.md` (Playwright MCP); the graph that mounts this subgraph is `../langgraph/AGENTS.md`.

## Purpose

Office-document generation: classify a request as read / create / modify, plan format-specific subtasks, produce real `.docx` / `.pptx` / `.xlsx` files on disk with `docx`, `pptxgenjs` and `xlsx`, verify the written bytes by re-parsing them, and delegate data-gathering steps to the browser or desktop subtrees. Hierarchical LangGraph only — there is no flat loop and no tool registry here.

## Local Contracts

- **The pipeline is fixed**: `memoryRetrieve` → `classifyAction` → `planner` → `executeAction` | `delegateToBrowser` | `delegateToDesktop` → `verifier` → `recovery` → `memoryStore` → END. Nodes registered `:602-610`, edges `:613-672`, compile `:674`. Node call sites: memory `:167`, planner `:196` (after `validatePlan:198`), executor `:235`, verifier `:315`, recovery `:334`, store `:422`. Seven routers (`:434-597`) are pure string-returning functions paired with the explicit mapping objects in each `addConditionalEdges` call — add the branch AND the mapping.
- **`classifyAction` is a regex pre-gate and the `read` branch is a dead end.** `:181-185` maps read/modify verbs to `DocumentActionType`, default `create`; `:188` sets `planStatus: 'executing'` for `read` and the router sends `read` straight to `executeAction` (`:436-438`). But only the planner produces subtasks, so a read-classified task arrives with `subtasks: []`, trips the no-subtask guard (`:216-222`) and returns `subtaskError: 'No subtask available'`. Document *reading* is not wired end-to-end in this subtree; `../utils/document-loader.ts` is only reached from `document-verifier.ts:47`. Do not document a read path as working.
- **Only `executeDocumentSubgraph` (`:689`) is public**, returning `DocumentSubgraphResult` (`:680-687`: `finalResponse`, `filePath`, `actions`, `executionTrace`, `planStatus`, `uiPayloads`). The caller types it structurally (`../../langgraph/research-agent.ts:1175`), so changing that shape breaks the graph node, not this folder.
- **State has 19 annotations (`:36-115`) and almost no real reducer.** Every field but two is `(_state, update) => update` — last write wins. Only `crossAgentContext` (`:98-110`, four arrays merged element-wise) and `uiPayloads` (`:113`, `appendArray` at `:31`) accumulate. Accumulating lists (`actions`, `executionTrace`) must therefore be returned explicitly by each node, and `uiPayloads` is never populated by any document node, so it leaves the graph empty.
- **TRACE DEFECT — `traceNode` (`:120-161`) records by mutation, not by return.** It writes `state.executionTrace = [...]` (`:142` success, `:157` failure) and returns only the node's own partial; LangGraph applies returns, never mutations, so the per-node timeline never reaches state and `executeDocumentSubgraph` hands back the initial `[]` (`:708`, `:740`). Fix by returning the entry through an append reducer — do not copy the mutation pattern into a new node.
- **Entry is the graph, not this folder.** `documentSubgraph` is a node of AskGraph (`../../langgraph/research-agent.ts:240`), reached through `routeAfterClassify` (`:415-417`); `documentSubgraphNode:1142` guards on intent (`:1144`) and calls `executeDocumentSubgraph(taskWithHistory, sessionId)` (`:1178`). Nothing else in the repo imports this subtree except `research-agent.ts:9` and `state.ts:5` (types only).
- **Delegation is one-directional — do not document a cycle.** This folder calls out: `document-delegation.ts:13` → `../desktop/desktop-subgraph` (invoked `:159`) and `:12` → `../browser/browser-subgraph` (invoked `:61`). Each delegate gets a fresh session id (`doc-desktop-delegate-${Date.now()}`, `:147`), the prior document results are prefixed as `DOCUMENT CONTEXT` from `crossAgentContext.documentResults` (`:151-156`), and the outcome lands in `delegateResults` (`DocumentDelegationResult`, `types.ts:81`). The desktop subgraph imports only `executeBrowserSubgraph` (`../desktop/desktop-subgraph.ts:9`, node `:267`); it has **no** edge back into `document/`. A desktop→document handoff does not exist yet.
- **Format choice is regex order.** `detectFormat` (`document-planner.ts:57-59`) tests pptx → xlsx → docx and must stay in that order ("table"/"chart" would otherwise swallow decks); the fallback plan wraps the whole task as one subtask defaulting to `docx` (`:195-208`) with a generated postcondition (`:205`). The planner's Zod stamps `format` as an enum (`:20`) and `contentSpec` as a free record (`:21`); `requiresBrowser` / `requiresDesktop` on each subtask are what the routers read.
- **`contentSpec` has no parser — this is the live defect to respect.** The planner emits it as `z.record(z.string(), z.unknown())` (`document-planner.ts:21`) and the executor reads it through raw `as` casts: docx `sections` (`document-executor.ts:101`), pptx `slides` (`:172`), xlsx `sheets` (`:245`), with `title` fallbacks at `:96,164,239`. `document-tools.ts` describes the shapes you *wish* were enforced; it is imported by nothing, so it is aspirational, not the contract. Either wire those schemas into the executor or leave the casts — never add a third, undocumented shape.
- **Writes go only to `~/Documents`.** `getDocumentsFolder()` (`:38-42`) is the sole output root, exported at `:328` and used by the verifier and memory paths; there is no user-chosen path. Names are sanitised (`:47-55`: allowlist `[a-zA-Z0-9\s\-_().,]`, spaces→`_`, 80-char cap, `'document'` fallback).
- **The collision counter is dead code — files overwrite.** In `uniqueFilePath` (`:60-86`) the first `try` block contains only comments and an unconditional `break` (`:69`), so the `while (true)` exits on iteration one and the `statSync`/`_N` renaming branch (`:74-81`) never runs. Fix it (delete `:65-72`) before citing `:60-86` as collision-safe.
- **Cross-agent research reaches the writer through one injection.** `executeActionNode` builds `contextStr` from `crossAgentContext.browserResults` (`:230-233`) and passes it as the third argument of `executeDocumentSubtask` (`:235`); the executor stamps it into `contentSpec.researchContext` only when that key is absent (`:300-306`). Drop that guard and delegated research data silently disappears from the generated file. `documentFilePath` (state `:94`) is what the verifier then opens (`:315`) and what `memoryStore` records (`:422`).
- **Format-specific write rules.** docx needs `Packer.toBuffer` before `fs.writeFile` (`:140-141`); pptx writes by path through `pres.writeFile({fileName})` (`:216`); xlsx truncates sheet names to 31 chars (`:266`) and still writes one sheet containing the task text when the spec is empty (`:272-273`). Every writer falls back to the first 40 characters of the subtask description for the file name (`:96,164,239`).
- **Library binding contract**: `docx` static ESM import (`:19-26`) → `Packer.toBuffer` + `fs.writeFile` (`:140-141`); `pptxgenjs` is CJS and MUST go through `createRequire(import.meta.url)` (`:29-31`), `new PptxGenJS()` `:169`, `pres.writeFile({fileName})` `:216`; `xlsx` is required the same way (`:34`) and written with `xlsx.writeFile(workbook, filePath)` (`:277`, sheet build `:244-273`, 31-char sheet names `:266`). Do not convert these to static imports — the build is ESM-only main.
- **Every read goes through `../utils/document-loader.ts`** — never a second parser: `unzipper:2`, `pdf-parse:11`, `mammoth:12`, `xlsx:13`, per-format size caps `:22-31` (5 MB office, 10 MB PDF). `document-verifier.ts` imports `extractDocument` (`:12`) and calls it at `:47`; that is currently its only consumer in this subtree.
- **Memory writes into the desktop tables.** `DocumentMemory.store` (`document-memory.ts:45`) maps `steps[].action` onto the shared `tool` column (`:51-56`) and calls the same `db.saveTrajectory` (`:48`) as `../desktop/desktop-memory.ts`; table/migration ownership is `../database/AGENTS.md`. The generated `filePath` is not persisted, so a later turn cannot re-open yesterday's file from memory — retrieval is keyword match on `taskDescription` (`retrieve:18`, limit 3, `formatContext:73`).
- **Verification is re-parse, not trust-the-LLM** (`document-verifier.ts:20-120`): file exists +0.2 (`:36`), format parses +0.2 (`:56`), postcondition key terms present +0.3 (`:83`), structure matches spec +0.3 or partial +0.15 (`:106,109`), pass at `score >= 0.6` (`:112`); unparseable file (`:52`) or too few key terms (`:85`) fail early and short.
- **Recovery ladder** (`document-recovery.ts:44-95`): `recoveryCount >= 3` forces `abort` (`:47-51`); 0 → `retry`, 1 → `replan`, then `llmAnalyze` (`:95`); `delegate_elsewhere` is chosen when the failure needs browser or desktop work (`:59,69`) and routes through `delegateRouterBrowser:553` / `delegateRouterDesktop:576`.
- **`ui-detector.ts` is a byte-identical clone** of `../desktop/ui-detector.ts` except `SOURCE_NODE` (`:3`; verified by diff), and a third copy sits in `../browser/`. All three are dead. If you adopt it, collapse to one module taking `sourceNode` as an argument; never add a fourth.
