# src/main/services/web — DOX child contract

Parent: `../AGENTS.md` (agent-runtime rail). Local contract wins local detail; parents win repo-wide rules.

## Purpose

The web substrate: web search and URL fetching, with no Electron, no LangChain and no zod in the tree.

It exists because the old web path was one 111-line file inside the AskGraph (`langgraph/tools.ts`, now deleted) that scraped DuckDuckGo with two fragile regexes and fell back to Tavily, and it had **no fetch capability at all** — the agent ranked pages it had never read. This folder is the replacement, and it is deliberately a separate boundary: the same three functions (`searchWeb`, `fetchWebPage`, `formatSearchForModel` / `formatFetchForModel`) are importable from a Pi tool, from an MCP server, or from a unit test with no mocks, which is impossible for anything that imports `research-agent.ts` (deleted with the graph; it dragged `electron`'s `app.getPath` in through the browser/desktop/document agents).

The design is reverse-engineered from the **oh-my-pi** coding agent (`github.com/can1357/oh-my-pi`): a provider chain in registry order, a normalised result shape, model-facing prose rather than JSON, a reader chain for HTML, and hard budgets on every output. The divergences from it are in Local Contracts and are all deliberate.

## Local Contracts

- **THE CHAIN IS LIVE-VERIFIED, NOT ASSUMED.** Measured 2026-10-15 with no key configured, in this order:

| Rung | Live result | What it costs |
|---|---|---|
| `exa` (`mcp.exa.ai/mcp`, keyless) | **works** - 5 sources in 0.7-2.3s, real `Published` dates | none |
| `parallel` (`search.parallel.ai/mcp`, keyless) | **works** - 4 sources in ~1.2s, excerpts but no dates | their metered free tier |
| `searxng` (pool of public instances, keyless) | **works from some IPs, zero from this one** - 2 of 20 instances served JSON, then both went 429; a later sweep of **0 of 71** graded instances served JSON at all | 6s bounded when it cannot work |
| `marginalia` (keyless) | **works, then soft-throttles** - repeatable 200s with relevant results; after ~5 requests it answers 200 with a 1 KB empty page | ~0.6s when throttled |
| `duckduckgo` (HTML) | **intermittent** - answers, then hard-blocks the IP with HTTP 202 for a while, then recovers unbidden | the rung that fails most often |
| `tavily` / `brave` | skipped, no key | opt-in |

  The pattern across every keyless engine is the same, and it is the most important thing to know about this folder: **they all rate-limit by IP**, so a working rung is not a reliable rung. The chain is a best-effort ladder, not a redundancy strategy, and every rung below the first is expected to fail regularly.
- **The SearXNG rung is a pool, ordered by observed success.** No single public instance can be relied on: measured, 2 of 20 served JSON from one IP and then 0 of 71. `searxng.ts` walks up to twelve instances - the two that actually answered first, then the `searx.space` grade order - under a **6s whole-pool budget** with a 4s per-instance cap composed beneath it. The budget was cut from 12s to 6s *after measuring the failure*: a pool that cannot reach one JSON-enabled instance cost 11.1s of a 120s turn to report the same failure twice as fast. Most instances disable the JSON format and answer HTML with a 200; the parser throws `does not serve JSON` and the walk continues, so that is the common case rather than an edge case.
- **The fallback path is proven live, end to end.** Running the chain from rung 3 (`searxng`, `marginalia`, `duckduckgo`) for "old operating system archive": searxng exhausted 8 instances in 6.0s, marginalia returned an empty page, **DuckDuckGo answered with 4 relevant results**, and both failures reached the model as `Note:` lines naming the instance errors. That is the whole chain policy doing its job against the real internet.
- **Evaluated and NOT shipped, with the reason, so nobody re-researches them.** *Vertical* search APIs all answer keyless and are genuinely useful - GitHub repositories, Wikipedia, Stack Exchange (30 hits), Hacker News Algolia, OpenAlex, Crossref and archive.org were each measured working - but in a sequential first-usable-wins chain they are **unreachable**, because `exa` answers everything first. Wiring them would be speculative surface: code no query can reach. They are worth wiring only if the chain grows query-aware routing. *Dead keyless general engines:* Startpage (200 with a result-less 22 KB shell), Mojeek (`<title>Captcha</title>`), Mwmbl (timeout), Right Dao (no JSON), Stract (404 on both API paths), Wiby (timeout), Teclis (400), Alexandria (unreachable), Marginalia's own API host (timeout - the HTML endpoint is the one that works), Firecrawl keyless (403), and `s.jina.ai` search (401, key required; its *reader* at `r.jina.ai` is still keyless).
- **The chain is a sequential fallback with first-usable-wins, not a fan-out.** `searchWeb` walks `SEARCH_PROVIDERS` in order, skips a provider whose `isAvailable()` is false (keyed providers, credential absent — skipped *silently*, not reported as a failure), and returns the first response with at least one source. Every clause is tested in `search/index.test.ts`.
- **A provider failure is a note, not a throw.** Failures accumulate as `` `${id}: ${message}` `` and ride back in `response.notes` for the model to read. A provider that returns zero sources is treated as a **failure**, because "zero results" and "bot-walled" are the same shape at the API boundary and must not silently end the chain. Total failure returns `provider: 'none'` with `all providers failed: ...` in the notes; `formatSearchForModel` renders it as `Error: web search failed. …`. Nothing here throws except a caller abort.
- **A caller abort is not a provider failure.** `runProvider` rethrows when `req.signal.aborted`, so a cancelled turn stops the chain instead of walking the rest of it and then handing the model a fabricated error. `withTimeout` keeps our budget abort distinguishable from the caller's, which is the whole reason it exists instead of `AbortSignal.timeout`.
- **An exhausted budget reads as a provider failure, and says so.** `timed out after 20000ms` — tested with fake timers. The budget is **20s per provider, not the 60s** the design being modelled uses, and that is a deliberate divergence: this chain is walked from inside an Ask turn with 120s total for search, three page fetches, synthesis and streaming, so seven providers at 60s is a turn that dies on the clock before it reaches the model.
- **Search output is prose, not JSON.** `formatSearchForModel` emits `Note:` lines, then `## Sources (<provider>)`, then `[n] title (publishedDate)` / url / snippet clipped to `MAX_SNIPPET_CHARS` (240). The old tool returned a JSON string that the node re-parsed; that round trip is deleted.
- **Recency is a closed vocabulary** (`day | week | month | year`), mapped per provider (`df=d/w/m/y`, `freshness=pd/pw/pm/py`, `time_range`). The `search_web` tool (`../pi/tools/web-tools.ts`) exposes it as a typed optional argument, which replaced the old `` `${query} 2025 2026` `` string hack in the deleted `externalSearchNode`. Absolute `after:`/`before:` bounds always beat `recency`, and a malformed date is dropped rather than trusted.
- **A provider with no freshness knob gets `recencyHint`, not silence.** Exa and Parallel have no date parameter, and the post-filter cannot cover for them: most of their sources carry no date, and an undated source passes a date bound by design. So the window rides in the query as words — `today`, `this week`, `this month`, or the **computed** current year (`recencyHint`), never a hardcoded one. Silent no-ops are worse than an imprecise hint.
- **`publishedDate` is always `YYYY-MM-DD` or absent.** Providers disagree wildly (Brave: a full ISO timestamp; Exa: `2026-10-11T00:00:00.000Z`; Tavily: a date; Parallel and DuckDuckGo: usually nothing), so `normalizePublishedDate` reduces all of them and **drops** anything unparseable — an invented date is worse than a missing one. The model reads this field and the date filter compares it; one shape is the only honest contract.
- **A constraint that matches nothing is relaxed, not obeyed.** `applyQueryConstraints` drops the dimension, keeps the engine's sources and emits a note. A model that asked for `site:` and got nothing must still get an answer. An **absent** directive must never filter at all: `[].every()` is `true` but `[].some()` is `false`, so an unguarded `filetype` check empties the result set of every plain query. That was a real bug the tests caught; `buildDimensions` only emits a dimension the query asked for.
- **An undated source passes a date bound.** Most engines omit dates; dropping those sources would empty the set.
- **Every outbound URL passes `checkFetchUrl`, twice.** Once on the model's string, once on `response.url` after redirects — following a redirect is how an allowed literal becomes a request for `169.254.169.254`.
- **This is the one deliberate security divergence from the design being modelled.** oh-my-pi has **no** SSRF rule at all (verified by reading its `tools/fetch.ts`, `web/scrapers/**` and `internal-urls/**`: no private-IP block, no protocol allowlist, no redirect cap). Here the rule is local: `http`/`https` only, no embedded credentials, ≤2048 chars, and loopback / RFC1918 / CGNAT / link-local / `metadata.google.internal` all blocked. The reason is that this app runs on a desktop with a real LAN, where a router admin page, a NAS UI and an Ollama server are one fetch away and all answer unauthenticated GETs. **Note the difference from `src/main/ipc/api-config-guard.ts`, which deliberately allows loopback**: a user pointing their palette at `http://localhost:11434/v1` is the feature; a search result naming `localhost` never is.
- **The fetch pipeline order is the contract:** `<url>.md` sibling (llms.txt convention, free and exact) → `Accept: text/markdown` negotiation on the URL → content-type dispatch (JSON pretty-printed, other text passthrough) → reader chain for HTML → raw HTML when every reader declines. The `method` on the result says which rung produced the text, so a model can weigh a weak extraction.
- **Two budgets, and they are not the same thing.** `MAX_RENDERED_CHARS` (500k) is an absolute cut so a pathological page cannot occupy the process; `options.maxChars` (default `DEFAULT_MAX_FETCH_CHARS`, 12k) is the caller's model head. `truncated` is set by either, and `notes` says so. Separately, `FETCH_TIMEOUT_MS` (30s, or `options.timeoutMs`) bounds the **whole pipeline**, because `loadPage` has no timeout of its own and a server trickling one byte per second would otherwise hold an Ask turn open until the pump's `ASK_PUMP_TIMEOUT_MS` (120 s, `src/main/ipc/chat-handlers.ts`) killed it. It is reported as `timed out after Nms`, not as a bare abort.
- **A `catch` must distinguish "this step declined" from "the caller stopped".** `tryUrlMarkdown` treats a 404 as an expected miss and returns `null`; if it also swallowed an abort, the pipeline would continue on a dead signal and every later fetch would wait for an abort that had already fired. Same rule in `renderHtml` (rethrow on `signal.aborted`) and in `searchWeb` (a caller abort rethrows rather than becoming a provider failure). This is the single most repeated bug class in this folder's history — see Verification.
- **Reader order is local-first, and the rescue rung is live.** Local extraction is free and instant; a remote reader is a second round trip with its own latency, so `jinaReader` runs only when `isUsableReaderOutput` rejects the local output. That gate is two checks, not one: >100 non-whitespace characters **and** not JS-gated **and** not >70% short lines — a page of nav menu passes "has content" and fails "is navigation". If no reader clears it, the best low-quality attempt is returned anyway with a note, because handing back "please enable JavaScript" is useless but a nav menu plus a note is honest. **Verified live both ways:** the local extractor handles electronjs.org docs, Wikipedia and `example.com` unaided, and `r.jina.ai` returned **30 127 characters** of clean markdown for a page that is nothing but `<div id="root">` plus a script tag — reached automatically when the caller passed the bare host `electronjs.org`, whose homepage is mostly nav.
- **Transport rules, each one load-bearing.** UA rotation across three agents (`Chrome` → `TextBot` → `curl/8.0`) but **only** on 429/403/503 — a 404 is a missing page, not a bot wall, and rotating three agents to learn that three times is three requests for a fact the first one already gave. `Accept-Encoding: identity` so the charset sniff sees real bytes. One `Retry-After` retry capped at 10s. The 50 MiB cap is applied **while streaming**, because checking `content-length` after `arrayBuffer()` is the check that arrives too late. Charset: header, then `<meta charset>` over the first 2 KiB, then UTF-8, with a `TextDecoder` throw caught rather than propagated.
- **`javascript:` and `data:` hrefs never survive extraction.** `htmlToMarkdown` drops the link and keeps the text; model-authored URLs are untrusted input in an app that holds `command:execute`.
- **Adding a provider is one file plus one array entry.** Provider modules export a parser (unit-testable without a socket), an async `search`, and a `SearchProvider` object whose `isAvailable()` gates on the credential. Do not add a second priority list, and do not add a provider without a test for its parser.
- **The pipeline's first rung is real, not theoretical.** `react.dev` serves `<page>.md` siblings (the llms.txt convention), so `https://react.dev/reference/react-dom/components/link` returned clean markdown from the `<url>.md` probe in one hop. That rung is also why a 404 is a *silent* miss: the probe costs one fast request and normally answers 404 in under a second.
- **No caching, no telemetry, no rate limiter** — the same non-goals as the design being modelled. Every call re-fetches. Adding a cache means adding invalidation.
- **Logger name is `Search`, and this folder owns it** (`createLogger("Search")` in `search/index.ts` and `fetch/index.ts`, registered to `LOG_SEARCH` in `SUBSYSTEM_ENV_VARS`). Deleting `../langgraph/tools.ts` orphaned that registry row and `logger.test.ts` failed immediately — the test that catches a registry entry whose call site is gone, which is exactly what it is for. Introducing any other subsystem name here needs its own row or the same test fails and its output is suppressed in production.

## Work Guidance

- Add a search provider: write `search/<id>.ts` exporting a **parser** (unit-testable with no socket) and a `SearchProvider` object whose `isAvailable()` gates on the credential, append it to `SEARCH_PROVIDERS`, and add a fixture test to `search/providers.test.ts` built from a **real captured response**, not invented markup — a hand-written fixture keeps passing after the provider changes theirs, which is the only failure mode that matters here. **Re-measure the engines above before assuming any of them still answer.**
- Add a reader: one entry in `READERS` (`fetch/reader.ts`) returning `string | null`, where `null` means "this reader declines, try the next". It must clear `isUsableReaderOutput` to be accepted.
- Add a content type: extend the dispatch in `resolveContentType` (`fetch/index.ts`) and add a `FetchMethod` member. Anything that is not HTML falls through as text today.
- Recency vocabulary is closed in `types.ts`. Adding a member means mapping it in every provider that advertises freshness and in the engines that do not.
- Karpathy cap applies (max 50 lines per function). `fetchWebPage`, `renderHtml` and `attemptLoad` are split at their natural boundaries — policy in one, transport in one — and the split is deliberate; do not re-inline them.
- Consumers must not re-implement any of this. A second DuckDuckGo regex pair or a second truncation constant is the exact drift this folder exists to end.
- The upstream design has more providers than are implemented here (Perplexity, Anthropic, Gemini, Codex, OpenAI, xAI, Firecrawl, Jina-search, Kagi, Kimi, TinyFish, Synthetic, Ollama, Z.AI, SearXNG, a cross-engine `public` aggregator, and grounded-model search). They were left out to keep the subtree reviewable; each one is one file plus one array entry if wanted. **`public`-style parallel fan-out with consensus ranking is the one omission with a real behavioural cost** — a single engine's ranking decides the order today.
- **Nothing exported here has no caller.** An audit of every `export` in this subtree against the rest of `src/` removed fifteen of them (the `search*` provider functions, `tavilyKey`, `braveKey`, `USER_AGENTS`, `decodeBody`, `MAX_PAGE_BYTES`, `MAX_RETRY_AFTER_MS`, `REMOTE_READER_TIMEOUT_MS`, `FETCH_TIMEOUT_MS`, `SEARCH_TIMEOUT_MS`, `MAX_SNIPPET_CHARS`) plus five unused type exports and one function with no caller at all (`getSearchProvider`). If you add a constant "for documentation", it is not documented by being exported.
