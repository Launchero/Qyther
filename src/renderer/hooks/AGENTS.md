# src/renderer/hooks — Hook contracts

Parent rail: `../AGENTS.md`. This doc owns the 24 non-test files in `src/renderer/hooks/` (six more `.test.tsx`/`.test.ts` harnesses sit beside them). The bridge surface, provider order and dead-file list are the parent's; this doc controls hook-level contracts — re-entrancy, listener cleanup and `electronAPI` call discipline.

## Purpose

Hold every reusable behaviour the palette needs: global keyboard navigation, window-mode sync, search/filter, IPC-backed fetching, streaming chat state, focus routing, surface reveal. These are the only renderer modules that legitimately call `window.electronAPI` outside `App.tsx` and `utils/`.

## Local Contracts

- **`useKeyboard` is mounted exactly once.** `App.tsx:157` is its only call site (`App.tsx:3` its only import). A second instance registers a second `document` `keydown` listener and double-executes Enter and `1`–`9`. Never call it from a component.
- **Props are mirrored into refs, so the listener registers once.** Fifteen values/callbacks are copied every render (fourteen state/callbacks plus App-owned `isModalOpen`); `handleKeyDown` reads only refs and depends solely on `setSelectedIndex`, so the `document` listener attaches a single time. Consequence: the `setSelectedIndex` you pass must be stable — the plain `useState` setter from `useSearch` is; wrapping it in a lambda is harmless here only because it lands in a ref, but never read closure state in the handler. New branches read `dialogOwnsKey(isModalOpenRef.current)` — the App-owned controlled-dialog flag OR the DOM backstop — never a fresh `isDialogOpen()` alone and never closure state.
- **IME bail comes first.** `event.isComposing` returns at `:82` before any branch — mandatory for CJK input on Windows. No new key branch may be placed above it.
- **Ordering is load-bearing.** Tab mode-cycle, `Cmd/Ctrl+Shift+Enter` ask-about and the `Cmd/Ctrl+N|P|K` block run deliberately **before** the blanket `if (hasModifier) return` guard. The `Ctrl+Shift+Q` quit and the file-mode `Ctrl+Shift+C/F` direct actions sit in that same pre-guard band (the C/F pair additionally bails when a dialog is open or `searchMode` is not `file`, since AI mode owns `Ctrl+Shift+C` for copying the last response). `Cmd/Ctrl+/` and `Cmd/Ctrl+,` are placed *after* the `!isTextInput` block on purpose: help and settings must also toggle while the user is typing, and no editor in this palette binds them. Hoisting the modifier guard kills all of the above.
- **Caret keys belong to the field.** `isCaretKey` (`:11-13`, applied at `:150`) bails on Home/End inside an input or textarea, so the caret is never stolen from a partially typed line. `j`/`k` are skipped entirely inside any text input (`:156`), and plain text inputs only intercept Enter (`:211-214`).
- **Textarea navigates only at list boundaries** (`:161-176`): `ArrowUp` only when `selectionStart === 0`, `ArrowDown` only at `value.length`; otherwise caret movement wins.
- **Every index change is wrapped in `startTransition`** (`:115-201`, plus the Vim branch at `:233,239`) so typing stays responsive while the result list is large. New navigation branches follow the same wrapper.
- **Escape is graded, three tiers, in this order**: (1) a surface owns the key — `dialogOwnsKey(isModalOpenRef.current)` tests App-owned `isModalOpen` (action panel, settings, shortcuts) first and `isDialogOpen()` (`ESCAPE_OWNERS` selector list `[role="dialog"], [role="alertdialog"], [role="menu"], [data-radix-popper-content-wrapper]`) second, and the handler returns **without** `preventDefault`, so Radix closes its own surface and the window stays visible. The state flag exists because a live drive measured tier-1 missing an open ActionPanel (title-stamp probe: `tier-past-tier1` with the dialog mounted, query cleared, window stayed) — the DOM query remains the backstop for Radix-managed surfaces App never sees. The selector list exists because a Radix `DropdownMenu` carries `role="menu"` and a `Tooltip` carries none: with only `[role="dialog"]` tested, tier 1 missed the chat-history menu and Escape hid the whole OS window with the menu still open. (2) otherwise a non-empty query — `preventDefault()` + `onClearQueryRef.current()`; (3) otherwise — `preventDefault()` + `await onCloseRef.current()`, which is `window.electronAPI.window.hide()` (`App.tsx`). Tier (1) is a whole-document `[role="dialog"]` query, and Radix `Popover` content carries that role at runtime — the harness's `dialog` read (`scripts/harness/cdp.mjs` `READS.state`) now measures exactly this predicate instead of looking for the shortcuts-help text, which is now its own `helpOpen` field. And the ladder presupposes the keydown exists: it is a `document` listener, so if the palette window is not the OS foreground window — detached DevTools is the same process and can hold the foreground — no tier is reached at all, and the measured symptom is Escape doing nothing while the app is perfectly healthy.
- **Tier 1 tests for a MOUNTED `[role="dialog"]`, not an open one — and a hidden window can strand one.** Radix `<Presence>` keeps closing content mounted until `animationend` so the exit can play, and a hidden Electron document may never deliver that event. Measured A/B in the running app: closing the shortcuts dialog while the window was hidden left `role="dialog"` + its full-viewport overlay mounted with `data-state="closed"`, `opacity: 1`, and `document.elementFromPoint()` over `#search-input` returning the overlay instead of the input — clicks hit nothing and Escape became a no-op, because tier 1 kept firing and returning. Showing the window let the paused animation finish and the node unmounted; closing while visible unmounted cleanly within one sample. So the strand is self-healing on the next summon and is not a permanent freeze, but do not "fix" it by unmounting overlays eagerly: that would cut off every exit animation. If it ever needs a real fix, the seam is `isDialogOpen()` — it should test for a dialog whose state is open, not for any mounted node.
- **A child's `stopPropagation` cannot intercept this handler — do not rely on it.** `useKeyboard` listens on `document`; `useMCPKeyboardShortcuts.ts` listens on `window`, which is *later* in the bubble path, so a `window`-level `stopPropagation()` runs too late to prevent the document listener from firing — which is why that hook carries no Escape branch at all. The `dialogOwnsKey` check is the backstop that holds for every modal the palette can open; a new modal must be Radix-shaped (carry `role="dialog"`) or App-tracked (folded into `isModalOpen`) or it will close the palette with it.
- **OS modifier comes from `utils/shortcuts.ts` only.** `usesMetaKey()` (`:30`) picks `metaKey` vs `ctrlKey` (`useKeyboard.ts:90`); `getAriaKeyshortcuts()` (`:43`) renders the display string through `components/common/ShortcutKeys.tsx`. Never branch on `navigator.platform` inside a hook.
- **`useFocusManager` is the single owner of show/mode focus routing.** It replaced the per-component listeners that used to sit in `SearchBar.tsx` — the header unmounts `SearchBar` in Ask mode, so a listener there could never focus the Ask textarea. Contract: `resolveTargetName` (`:18-20`) picks `'searchbar'` for file mode and `'unified-command'` for ai mode against what is actually mounted; `requestFocus()` (`:65-72`) sets `pendingFocusRef` and `registerInput` (`:74-86`) satisfies it the moment the target mounts — this is what survives both the 150 ms debounced compact→expanded IPC (`useWindowMode.ts:13`) and Ask mode's early returns in `AskModeExpanded`. Park/restore only accepts a live, connected, editable element (`isRestorableFocus` `:28-37`); `<body>` is rejected because focusing it is a no-op that would swallow the whole summon. The `electron-window-will-hide` / `electron-window-shown` listeners and their unsubscribe live at `:90-112`, and `:116-118` re-asserts focus when `(searchMode, windowMode)` actually lands. **Do not add a second focus-routing listener elsewhere** — `useWindowReveal` is the only other holder of an `electron-window-shown` listener and it moves pixels, never the caret; a third listener in this tree is the bug the pre-refactor `SearchBar` version was.
- **`useWindowReveal` owns the summon animation, and only that.** The clock is **`document.visibilitychange`**, not `electron-window-shown`: main calls `show()` and only *then* sends the IPC (`src/main/windows.ts:145-149`), so arming on that event started the fade one round trip after the window was already on screen — measured as 4 sampled frames below 0.1 opacity (34-67 ms) of an always-on-top palette you could click but not see. Visibility flips in the same frame the window appears. The IPC event remains as a **guarded** fallback (`:11-12` derive `fallbackGuardMs = motionDurationMs('--duration-150',150) + motionDurationMs('--duration-100',100)` — 250 ms when the tokens resolve, i.e. longer than `--animate-palette-reveal`'s 150 ms, and read from the same scale rather than restated): re-adding the class mid-animation resets opacity to 0 and makes the invisible window *longer*, so a fallback that fires during a running fade is suppressed. Both must stay: a summon that changes no visibility state has only the IPC to react to. The restart itself is a DOM operation — remove the class, force reflow with `void offsetWidth`, re-add in the same turn — never React state, because a class toggled across two commits paints one frame of fully-visible palette first, which reads as a blink. It adds the class on mount so the first `ready-to-show` reveal animates too, and clears it on `animationend` where `event.target === surface` (child animations bubble here, and `.view-enter`/`typingDots` ending must not cancel a running reveal). No `prefers-reduced-motion` branch: under reduced motion the shorthand resolves to `none`, so the card simply paints at `opacity: 1`, which is the fail-safe direction. Dismiss is **not** animated by design — the decision and its reasoning are recorded in `src/main/AGENTS.md`. Pinned by `useWindowReveal.test.tsx`, which fakes `performance.now()` and counts class *additions* through a `MutationObserver` (mutation-checked: dropping the visibility listener fails two tests, dropping the fallback guard fails the no-restart test). **What this did not fix:** the trace still reports `minOpacity 0` and 4 frames under 0.5 (~64 ms) before and after — that span is the 150 ms entrance ramp itself, not the round trip, so removing the round trip moved the start earlier without shortening the ramp. Only changing the keyframe's starting opacity, or deferring `show()`, would alter that, and both are decisions the design brief rules out (entrance-only fade, instant summon).
- **`useWindowMode` holds no authority over the window.** The mode value is written in exactly one function (`adopt`, `:53`) and its only two inputs are main's mount snapshot and main's `window:modeChanged` push. The bug class this removed: the hook used to `setWindowMode(targetMode)` *before* awaiting `window:setMode`, so the palette laid out for a geometry main had not agreed to, main's echo was then discarded by `mode !== windowMode` (the renderer had already guessed it), and a third writer — a `visibilitychange` handler that re-fetched and overwrote the mode on every summon — clobbered anything still in flight. All three are gone. A hook that wants a different mode **requests** it and waits for the push; that is also why the tween's `window:animationFrame` clock and this hook can never disagree about the height.
  - `announcedExpanded` (`:39`) is policy, not state: it records "main moved the window without being asked", which is what mutes auto-collapse (so `Alt+Shift+M` survives an empty query). It must **not** be set when the push is the echo of this hook's own request — hence `requestedRef` (`:50`), cleared on every adoption, compared in `adopt`. Mutation-checked both directions: dropping the echo guard makes "collapses again after its own auto-expand" red, and re-adding the visibility resync makes "never re-fetches the mode on a visibility change" red. Verified live on the shipped app: a compact → type 5 chars → expanded → clear → compact round trip settles back to compact each time (measured when the compact ask was 100 → realized 103, expanded → 603; the compact ask is now 72).
  - `isManuallyExpanded`, `setWindowMode`, `toggleMode` and `setIsManuallyExpanded` were returned to `App.tsx` and read by nobody (`App.tsx:85` takes only `windowMode`/`isCollapsing`); they are deleted, not dormant. A renderer-side toggle would be a second owner of the mode, which is the thing this hook must not become — `Alt+Shift+M` in main is the toggle.
- **`useExternalLinkHandler` is the only renderer path that turns an `<a href>` into `url:open`.** It installs a `document` **capture-phase** click listener (`:11-22`) because the host window denies new windows and blocks navigation, so a plain anchor is a dead click. Capture phase is required — a component that `stopPropagation`s its own click never reaches a bubble listener. Every URL passes `safeExternalUrl` (`../utils/externalUrl.ts:5-13`, http/https only) before it reaches the bridge; the rejection is logged, never thrown. Mounted once at `App.tsx:173`.
- **Tokens are committed once per animation frame, never once per chunk.** `chat:stream-chunk` appends to `pendingChunksRef` (`useChatSession.ts:206`) and `scheduleChunkFlush` (`:229`) arms one `requestAnimationFrame`; `flushPendingChunks` (`:209`) is the only writer of streamed text into `messages`. Two rules follow from that and both are load-bearing: the terminal chunk calls `flushPendingChunks()` **before** its own `setMessages`, because the completion path reads `lastMsg.content` and a stranded buffer would silently truncate the answer; and the listener's cleanup cancels the frame and drops the buffer, so an unmount cannot commit into a dead tree. There is no timer fallback on purpose — rAF stops while the palette is hidden, which is the correct place to accumulate. `useChatSession.test.tsx` proves both halves by holding five chunks in one `act()` with no frame and asserting zero renders, then one render with the whole string.
- **`on*` listeners return an unsubscribe; store and return it.** Pattern at `useChatSession.ts:238-401`: `const cleanup = window.electronAPI.chat.onStreamChunk(…)` then `return cleanup`. A `useEffect` that subscribes without returning the cleanup leaks one listener per StrictMode double-mount.
- **Async IPC needs two guards**: a rejection handler on the call (`App.tsx:219`, `useWindowMode.ts:69-81,116-118`) and a mounted/latest check before `setState` (`useFileSearch.ts:101-112,114-125`). Unhandled rejections here surface as a dead palette with no error UI.
- **The mounted guard has one name and one shape: `isMountedRef`.** Declared as a ref, set `true` in a mount effect, flipped `false` in that effect's cleanup, and checked before every `setState` — including the `finally` of a `try` that clears a loading flag, which is the one people forget. `useFileSearch.ts:101-112` is the reference implementation and the pattern to copy; it is now also used by `useMCP.ts`, `MCPToolModal.tsx` and `App.tsx` (whose `useIsMounted()` + module-scope `loadAppList`/`loadMcpCount` helpers exist because `App.tsx` is at the 50-line ceiling and must extract rather than gain an effect block). **Do not reach for an `AbortController` in the renderer** — no `electronAPI` call is cancellable, so a guard can only mean "do not start more work", never "stop work in progress".
- **A timer or frame is a resource: it lives in a ref and it is cleared twice.** Discarding the id of a `setTimeout`/`requestAnimationFrame` means it fires after unmount. The contract: hold the handle in a `useRef` beside the state it clears, `clearTimeout`/`cancelAnimationFrame` on **re-arm** (so rapid transitions do not stack timers — `useWindowMode.ts`'s collapse flash and `useCommandExecution.ts`'s marker both re-arm), and again in an unmount cleanup effect. Current holders: `CodeBlock.tsx` `copyTimerRef`, `useCommandExecution.ts` `markerTimerRef`, `useWindowMode.ts` `collapseTimerRef` + `debounceTimerRef`, `useFocusManager.ts` `rafIdRef`. `useChatSession.ts` is the exemplar for the frame-paced variant and stays unchanged by this rule.
- **A backoff wait between IPC attempts must be abortable by teardown, not merely awaited.** No IPC call is cancellable, so the fix is to stop *starting* the next one: `sleepWhileMounted` (`useFileSearch.ts:95`) resolves `false` as soon as the hook tears down and the retry loop breaks on it. Its comment ("IPC calls cannot be cancelled") stays true — do not let a future change rewrite it as if the invoke itself were aborted.
- **A poller needs an in-flight guard.** A `setInterval` whose async tick can outrun its own interval fires overlapping requests and dispatches stale answers into a reducer. One outstanding request maximum, and a tick that arrives while one is in flight **skips rather than queues** — `AskModeExpanded.tsx:119-131` is the pattern. Subscribing once and polling forever is not a lifecycle strategy: `browser:cleanup` and the session manager's inactivity check exist to bound the session from the other end.
- **Debounce lives in the hook, not the component.** `useFileSearch` owns its timer ref and clears it on unmount; `useDebounce.ts` is dead — do not "share" it back in.
- **`useBrowserState` holds no state.** Keep the reducer pure and let the consumer own the `useReducer`; never add a `useState` to it.

## Work Guidance

- Shape: `export function useX(…)` named export only; an options bag once a hook takes more than three arguments (`useWindowMode.ts:7-10`, `useCommandExecution.ts:9`).
- Call `window.electronAPI` and map the wire shape into a renderer type at the hook boundary (see `useMCP`, `App.tsx:49-56`) so components never receive a payload straight off IPC.
- Log through `utils/debugLogger` with a `[useX]` prefix; never `console.*`.
- Import view types from their owners: `SearchResult` from `../components/ResultsList`, `SearchMode` from `../components/ModeTabs` (`useKeyboard.ts:3-4`, and the same pair at `useFocusManager.ts:2`). `../types/commandPalette.ts:5` is a re-export, not a second home.
- Put a hook here when behaviour is shared by two or more components or encapsulates one IPC channel; single-use behaviour stays in the consuming component. A `window`/`document` listener that routes palette state (show, hide, mode, clicks) belongs in one of these hooks, not in a component that can unmount — that is exactly how `useFocusManager` and `useExternalLinkHandler` are shaped.
- Root caps apply: 50 lines per function. `handleKeyDown` (`useKeyboard.ts:80-270`) is not one 190-line function only because its branches bail early; the two predicates that guard Escape and Home/End were extracted to module scope (`:11-13`, `:21-23`) and that is the required pattern for any new condition — extract a named helper above the hook, do not nest another `if`.

## Verification

- `useChatSession` is covered four ways. `chatTranscriptFolds.test.ts` drives the two exported transcript folds as pure functions — no mount, no `electronAPI` stub — and is mutation-checked: rewriting a fold to push into the message's own array in place turns the no-mutation and new-array tests red. `useChatSession.test.tsx` mounts the hook with `react-dom/client` (`@testing-library/react` is **not** installed and must not be assumed) and now proves three things: `listSessions` stays referentially stable across 20 parent re-renders (mutation-checked — reverting the `useCallback` hangs the test to its timeout), **and** an Ask-mode mount costs zero `chat:listSessions` IPC calls because the list arrives on the `chat:sessions-changed` push (mutation-checked — deleting the subscription effect reddens it), **and** five chunks delivered inside one `act()` with no frame produce zero renders and zero text while a single later frame produces one render holding the whole string, with a second case proving the terminal chunk drains the buffer when main sends no `fullContent` (mutation-checked — replacing `scheduleChunkFlush()` with an immediate flush reddens the buffered test). `AskModeExpanded`'s `loadHistory` callback and its `useEffect(loadHistory, [loadHistory])` are deleted outright, so the loop shape cannot come back from the component side either. `useKeyboard.escape.test.tsx` pins the Escape ladder in isolation (tier-1 via each signal independently, tier-2 clear-once, tier-3 hide-once) with react-dom/jsdom and no new dependency. `useSearch` remains the cheapest next test to write.
- **`useWindowTween.test.tsx` is wall-clock sensitive and will flake under machine load** — measured, not predicted: one full-suite run on a box carrying ~48 `node`/`electron` processes failed "reports a frame for every animation frame once a mode is announced", and three consecutive runs then passed 305/305.
