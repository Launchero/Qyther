Parent: `src/renderer/AGENTS.md` (`../../AGENTS.md`) and the root `AGENTS.md` rail (`../../../../AGENTS.md`). Token/layer rules belong to `../../styles/AGENTS.md`; primitive internals belong to `../ui/AGENTS.md`. This doc owns Ask-mode presentation only.

## Purpose

Render the Ask-mode conversation: transcript, welcome state, streaming input bar, browser-agent progress panels, structured generative-UI results, task-metrics transparency, and the connecting/loading surfaces (spinner card, not-configured card, toast). Purely presentational — props in, callbacks out, no IPC, and no unvalidated URL reaching an `href`.

## Local Contracts

- **Props convention**: `export interface XProps` when the parent imports the type (`UnifiedCommandBar.tsx:14`); a plain local `interface XProps` otherwise (`BrowserProgressPanel.tsx:16`, `GenerativeUI/DataTable.tsx:15`, `Transparency/TaskMetrics.tsx:5`). Shared *data* shapes are always exported (`BrowserProgress` `BrowserProgressPanel.tsx:8`, `InlineChatSession` `RecentChatsInline.tsx:5`, `ProgressStage` `GenerativeUI/GenerativeUIProgress.tsx:4`).
- **Declaration form**: `export function X({ a, b = def }: XProps)` — never `React.FC` (`TaskMetrics.tsx:10`, `ChartView.tsx:179` show the destructured-with-defaults shape). Sole `React.FC` occurrence is a map-value type, not a component (`GenerativeUISkeleton.tsx:79`); do not add others.
- **Ordering**: module-level const maps and helper functions sit ABOVE the component. Exemplar `ThinkingSteps.tsx`: `LOADING_MESSAGES` `:11-52`, `getLoadingMessage` `:54`, `getStepBadge` `:58`, `aggregateSteps` ending `:132`, `StepIcon` `:134-193`, component `:195`.
- **Memoisation is the exception**: only `AgentIndicator.tsx:19` uses `React.memo`. `useMemo`/`useCallback` only where computation is real — `ComparisonTable.tsx:37-105`, `ChartView.tsx:180-183`, `UnifiedCommandBar.tsx:83`. Everything else re-renders freely.
- **No IPC here**: zero `window.electronAPI` references in this folder. Chat/session state arrives as props from `../AskModeExpanded.tsx` (the only owner of `../../hooks/useChatSession.ts`, `AskModeExpanded.tsx:2,68`) and `../ChatMessageBubble.tsx`; this folder emits callbacks only. Two narrow exemptions are the current shape, not a pattern to widen: UI-local hooks (`UnifiedCommandBar.tsx:9-10` call `useDragAndDrop` / `useAutoResizeTextarea`) and a type-only import from the hook (`ThinkingSteps.tsx:3` imports `ThinkingStep`).
- **ui/ primitives are composed, never patched**: `progress` + `badge` + `button` (`BrowserProgressPanel.tsx:3-5`), `button` + `badge` where a card needs them. Keep it through the alias.
- **Ask-mode readiness is three states, and each one is a different card.** `AskModeExpanded.tsx` branches on `useChatSession`'s triple before rendering any transcript: `isInitializing` (`:366-375`) renders the `.chat-loading-state` card with `.loading-spinner` under `role="status" aria-live="polite"`; `!isReady` (`:377-409`) renders `.chat-not-ready` under `role="alert"` with `tabIndex={-1} autoFocus`, names the missing env var, and offers "Back to Files"; anything else renders the real UI. The reason string is `chat:initialize`'s `error` field, surfaced through `useChatSession`'s `notReady` (`useChatSession.ts:415-439`, `ChatNotReady` `:87-90`) — never a locally invented message. **"Try again" renders only when main says the failure is retryable** (`AskModeExpanded.tsx:395-399`), because `langChainAgent.initialize()` latches `isInitialized` (`src/main/services/langchain/agent.ts:85`) and returns early on a second call: a missing `API_KEY` cannot be fixed without a restart, so offering retry there would render a dead button. The env-var list (`:387-393`) is likewise suppressed when the cause is a thrown init failure rather than missing configuration. `onExitAskMode` is the escape hatch wired to "Back to Files".
- **Model-authored URLs are untrusted; nothing here renders an `href` without `safeExternalUrl`.** `SourcesPanel.tsx:26` runs every `source.url` through `../../utils/externalUrl.ts` and renders the `<a href>` only when the scheme is http/https (`:41-53`), falling back to a plain `<div className="source-link">` for anything else (`:55`); `ChatMessageBubble.tsx:102` gates `onCitationClick` through the same helper so a `[n]` citation with a `javascript:` URL is inert. This matters because the renderer holds the `command:execute` bridge and the host window denies new windows — an unvalidated scheme executing here is OS execution. `hooks/useExternalLinkHandler.ts` is the backstop, not a licence to skip the gate.
- **DUAL STYLING MODEL — the fork every editor must know.** `ui/` is Tailwind utilities. This folder additionally carries semantic **BEM classes defined in CSS**: `.generative-ui-container` (`../../styles/globals.css:303`), `.generative-ui-title` `:304`, `.generative-ui-fallback` `:384-386`, `.generative-list*` `:389-392`, `.generative-ui-skeleton` `:399`, `.generative-ui-progress` `:468-516`, `.skeleton-table` `:430`, `.shimmer` `:451`; and in `../../styles/ask-mode-perplexity.css`: `.command-bar` `:28`, `.welcome-state` `:428`, `.welcome-logo` `:449`, `.answer` `:613`, `.answer-content` `:1623`, `.error-banner` `:1443`, `.task-metrics-*` `:2134-2209`, `.typing-dot` `:2810`, `.ask-mode-expanded`/`.chat-loading-state`/`.loading-spinner`/`.chat-not-ready*` `:2871-2952`. A new ask-mode component adds its class in **one of those two files** (672 and 2999 lines respectively), never inline, never a new stylesheet — a class that exists in neither renders as raw left-aligned text, which is exactly how the loading state shipped before `:2871-2952` existed. Tailwind utilities and BEM classes are combined in the same `className` — see `ChatMessagesList.tsx:154`.
- **MOTION IN ASK MODE — what animates, what must not.** Every entry here consumes a whole `--animate-*` shorthand; none composes a duration and easing by hand (the `.welcome-fade-out` chain did, shipped against a token that did not exist, and was deleted rather than re-wired — see below). `.welcome-state` `:2823` and `.suggestion-card` `:2828` enter on the welcome; `.recent-search-chip` `:2838` and `.related-question-item` `:2858` stagger `slideUpFade`; `.error-banner-enter` `:2848` + `.error-icon-shake` `:2853` are the error row's slide + shake, and they are the only reason `ChatErrorBanner` is styled at all (see the orphan note). The three `AskModeExpanded` readiness cards carry `.view-enter` and distinct React keys so a card swap actually re-runs it. **Do not put a CSS animation on `.messages-area`**: it is the `@formkit/auto-animate` host and the design system forbids the combination on one element — which is why the welcome→transcript swap is *not* animated from the transcript side, and why `.welcome-fade-out`/`fadeOutUp` were deleted instead of being wired to a deferred-unmount timer that would have to animate that same node. `autoAnimate` is created in `ChatMessagesList.tsx:100` with its duration and easing read from `--duration-200`/`--easing-smooth` via `../../utils/motion.ts`, and the controller **is destroyed on cleanup** — auto-animate 0.10 has no `stop()`; dropping the controller leaves its MutationObserver and timers running against the element on every StrictMode remount. `.generative-ui-container` cross-fades on opacity only (`globals.css:303`) as it replaces the skeleton, because a transform there would fight auto-animate's layout of its ancestors.
- **Streaming output tracks the bottom instantly; only a user-caused jump is smooth.** `ChatMessagesList.tsx:78-90` picks `behavior` from `prefersReducedMotion() || last?.isStreaming`, because each committed chunk re-ran a ~300 ms smooth scroll toward a bottom that had already moved again — the transcript swam and the browser fought itself. There is deliberately **no** `scrollIntoView` in `ChatMessageBubble` any more: its mount-time effect made every bubble of a loading history yank the viewport and duplicated the scroller's job, so it was deleted rather than gated, and its `messageRef` went with it. A streamed answer is also parsed incrementally now: `splitAtSettledBlock` (`../../utils/markdownBlocks.ts`) returns the text up to the last blank line whose parser state is provably clean, the settled half renders through a `React.memo`ed `SimpleMarkdown` that React skips while its text is unchanged, and only the tail re-parses per frame. The cut rules are conservative on purpose (never inside a ``` fence, never straight after a list item) because a wrong cut is a wrong render, not just a lost optimisation; `markdownBlocks.test.ts` pins character-exact rejoin, monotonic settling while a turn streams, and the two refusals.
