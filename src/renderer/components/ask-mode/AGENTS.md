# src/renderer/components/ask-mode — DOX child contract (Ask-mode UI)

Parent: `src/renderer/AGENTS.md` (`../../AGENTS.md`) and the root `AGENTS.md` rail (`../../../../AGENTS.md`). Token/layer rules belong to `../../styles/AGENTS.md`; primitive internals belong to `../ui/AGENTS.md`. This doc owns Ask-mode presentation only.

## Purpose

Render the Ask-mode conversation: transcript, welcome state, streaming input bar, browser-agent progress panels, structured generative-UI results, task-metrics transparency, and the connecting/loading surfaces (spinner card, not-configured card, toast). Purely presentational — props in, callbacks out, no IPC, and no unvalidated URL reaching an `href`.

## Local Contracts

- **Props convention**: `export interface XProps` when the parent imports the type (`UnifiedCommandBar.tsx:14`); a plain local `interface XProps` otherwise (`BrowserProgressPanel.tsx:16`, `GenerativeUI/DataTable.tsx:15`, `Transparency/TaskMetrics.tsx:5`). Shared *data* shapes are always exported (`BrowserProgress` `BrowserProgressPanel.tsx:8`, `InlineChatSession` `RecentChatsInline.tsx:5`, no live shared data shape in this folder since the skeleton and progress components were deleted).
- **Declaration form**: `export function X({ a, b = def }: XProps)` — never `React.FC` (`TaskMetrics.tsx:10`, `ChartView.tsx:179` show the destructured-with-defaults shape). There are now **zero** `React.FC` occurrences in the tree — the last one was a map-value type in the deleted `GenerativeUISkeleton.tsx`; keep it at zero.
- **Ordering**: module-level const maps and helper functions sit ABOVE the component. Exemplar `ThinkingSteps.tsx`: `getStepBadge` `:29`, exported `foldSteps` `:48`, `StepIcon` `:77`, component below them. Its former `LOADING_MESSAGES` / `getLoadingMessage` / `aggregateSteps` block is gone with the step-copy rule below.
- **Memoisation is the exception**: only `AgentIndicator.tsx:19` uses `React.memo`. `useMemo`/`useCallback` only where computation is real — `ComparisonTable.tsx:37-105`, `ChartView.tsx:180-183`, `UnifiedCommandBar.tsx:83`. Everything else re-renders freely.
- **No IPC here**: zero `window.electronAPI` references in this folder. Chat/session state arrives as props from `../AskModeExpanded.tsx` (the only owner of `../../hooks/useChatSession.ts`, `AskModeExpanded.tsx:2,68`) and `../ChatMessageBubble.tsx`; this folder emits callbacks only. Two narrow exemptions are the current shape, not a pattern to widen: UI-local hooks (`UnifiedCommandBar.tsx:9-10` call `useDragAndDrop` / `useAutoResizeTextarea`) and type-only imports of shared boundary types (`ThinkingSteps.tsx` imports `ThinkingStep` from `../../../shared/ipc/thinking-step`, which is not a main-process import).
- **Step copy is derived from the tool registry; this folder holds no name→copy map.** `ThinkingSteps.tsx` renders `step.label ?? step.step`, where `label` is the tool's own declared `label` resolved by `FamilyIndex.displayLabelFor()` and shipped on the step by `pi/ask-events.ts`. Badges key on `step.family`, never on a tool name. `foldSteps()` folds a completion onto the still-open row for the same tool and **keeps repeated calls as separate rows** — the previous `aggregateSteps` deduped by name unconditionally, so three searches rendered as one line and a retry was invisible; it also sorted on a `PHASE_ORDER` list containing no real tool, making the sort a no-op that looked like a contract. What was deleted and must not come back: `LOADING_MESSAGES`, `PHASE_LABELS`, `PHASE_ORDER`, `getLoadingMessage`, and a `getStepBadge` switch keyed on graph-node strings. `families.test.ts` gates this by reading both sources; `ThinkingSteps.test.tsx` pins the fold.
- **No control renders unless its state crosses IPC.** The web-search toggle, the desktop-mode toggle and its progress panel are deleted: `webSearchEnabled` had seven references and every one was in the renderer, `handleToggleDesktopMode` flipped a local reducer and logged, and `desktopState.sessionActive` was never set by anything, so the second `BrowserProgressPanel` could not appear. A toggle that changes no main-process state is worse than no toggle — it teaches the user that this surface lies. Re-adding one requires a typed field in `src/shared/ipc/` and a producer. See `docs/ask-mode-experience-research.md` §5.3 and §6 item 6.
- **ui/ primitives are composed, never patched**: `progress` + `badge` + `button` (`BrowserProgressPanel.tsx:3-5`), `button` + `badge` where a card needs them. Keep it through the alias.
- **Ask-mode readiness is three states, and each one is a different card.** `AskModeExpanded.tsx` branches on `useChatSession`'s triple before rendering any transcript: `isInitializing` (`:366-375`) renders the `.chat-loading-state` card with `.loading-spinner` under `role="status" aria-live="polite"`; `!isReady` (`:377-409`) renders `.chat-not-ready` under `role="alert"` with `tabIndex={-1} autoFocus`, names the missing env var, and offers "Back to Files"; anything else renders the real UI. The reason string is `chat:initialize`'s `error` field, surfaced through `useChatSession`'s `notReady` (`useChatSession.ts:415-439`, `ChatNotReady` `:87-90`) — never a locally invented message. **"Try again" renders only when main says the failure is retryable** (`AskModeExpanded.tsx:395-399`), because `langChainAgent.initialize()` latches `isInitialized` (`src/main/services/langchain/agent.ts:85`) and returns early on a second call: a missing `API_KEY` cannot be fixed without a restart, so offering retry there would render a dead button. The env-var list (`:387-393`) is likewise suppressed when the cause is a thrown init failure rather than missing configuration. `onExitAskMode` is the escape hatch wired to "Back to Files".
- **Model-authored URLs are untrusted; nothing here renders an `href` without `safeExternalUrl`.** `SourcesPanel.tsx:26` runs every `source.url` through `../../utils/externalUrl.ts` and renders the `<a href>` only when the scheme is http/https (`:41-53`), falling back to a plain `<div className="source-link">` for anything else (`:55`); `ChatMessageBubble.tsx:102` gates `onCitationClick` through the same helper so a `[n]` citation with a `javascript:` URL is inert. This matters because the renderer holds the `command:execute` bridge and the host window denies new windows — an unvalidated scheme executing here is OS execution. `hooks/useExternalLinkHandler.ts` is the backstop, not a licence to skip the gate.
- **DUAL STYLING MODEL — the fork every editor must know.** `ui/` is Tailwind utilities. This folder additionally carries semantic **BEM classes defined in CSS**: `.generative-ui-container` (`../../styles/globals.css:354`), `.generative-ui-title` `:355`, `.shimmer` `:496`; and in `../../styles/ask-mode-perplexity.css`: `.command-bar` `:28`, `.welcome-state` `:428`, `.welcome-logo` `:449`, `.answer` `:613`, `.answer-content` `:1623`, `.error-banner` `:1443`, `.task-metrics-*` `:2134-2209`, `.typing-dot` `:2810`, `.ask-mode-expanded`/`.chat-loading-state`/`.loading-spinner`/`.chat-not-ready*` `:2871-2952`. Tailwind utilities and BEM classes are combined in the same `className` — see `ChatMessagesList.tsx:154`.
- **MOTION IN ASK MODE — what animates, what must not.** Every entry here consumes a whole `--animate-*` shorthand; none composes a duration and easing by hand (the `.welcome-fade-out` chain did, shipped against a token that did not exist, and was deleted rather than re-wired — see below). `.welcome-state` `:2823` and `.suggestion-card` `:2828` enter on the welcome; `.recent-search-chip` `:2838` and `.related-question-item` `:2858` stagger `slideUpFade`; `.error-banner-enter` `:2848` + `.error-icon-shake` `:2853` are the error row's slide + shake, and they are the only reason `ChatErrorBanner` is styled at all (see the orphan note). - **Streaming output tracks the bottom instantly; only a user-caused jump is smooth.** `ChatMessagesList.tsx:78-90` picks `behavior` from `prefersReducedMotion() || last?.isStreaming`, because each committed chunk re-ran a ~300 ms smooth scroll toward a bottom that had already moved again — the transcript swam and the browser fought itself. There is deliberately **no** `scrollIntoView` in `ChatMessageBubble` any more: its mount-time effect made every bubble of a loading history yank the viewport and duplicated the scroller's job, so it was deleted rather than gated, and its `messageRef` went with it. A streamed answer is also parsed incrementally now: `splitAtSettledBlock` (`../../utils/markdownBlocks.ts`) returns the text up to the last blank line whose parser state is provably clean, the settled half renders through a `React.memo`ed `SimpleMarkdown` that React skips while its text is unchanged, and only the tail re-parses per frame. The cut rules are conservative on purpose (never inside a ``` fence, never straight after a list item) because a wrong cut is a wrong render, not just a lost optimisation; `markdownBlocks.test.ts` pins character-exact rejoin, monotonic settling while a turn streams, and the two refusals.

## Work Guidance

- New ask-mode component checklist: `interface XProps` → `export function` → helpers above the component → BEM class added in one of the two stylesheets (a class in neither renders unstyled) → token-only values, semantic status pairs (`--success`/`--warning`/`--info`) rather than a raw primitive green/yellow → live-region/`role` markup if it changes state or streams → `safeExternalUrl` on any URL before it reaches `href` or a callback → render it from the app shell, never call IPC from here.
- A new readiness/error surface follows the `AskModeExpanded` pattern: branch before the transcript, one card per state, `role="status"` while working and `role="alert"` when stopped, reason text taken verbatim from the IPC `error` field, and an action button only when the main process says the state is recoverable.
- Keep functions ≤50 lines (root rail); `ThinkingSteps.tsx` and `BrowserProgressPanel.tsx` are the house style for splitting a large panel into module-level helpers.
- Icons come from `@phosphor-icons/react` with a numeric `size` prop — `--icon-size-*` tokens exist (`../../styles/tokens/spacing.css:99-105`) but are wired to almost nothing; `AgentIndicator.tsx:35` consumes one, via `w-[var(--icon-size-xs)] h-[var(--icon-size-xs)]`.
