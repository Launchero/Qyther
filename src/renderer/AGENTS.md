# src/renderer — React palette shell

Parent rail: `../../AGENTS.md`. This doc owns the renderer root, the app-shell components, and the renderer leaf folders. The IPC channel contract is owned by `../main/ipc/AGENTS.md`; hooks, shadcn primitives, ask-mode UI and the token system are owned by their own child docs below and are not restated here.

## Purpose

Render the frameless Alt+Space palette window content and nothing else: a fuzzy command/file palette that expands into the Ask-mode streaming chat. Own provider order, the dual-mode selection rule, app-shell layout, and the single `window.electronAPI` accessor discipline. No business logic, no IO, no Node — every capability crosses the preload bridge.

## Local Contracts

- **Two orthogonal "modes" — never conflate them.** `windowMode` `'compact' | 'expanded' | 'custom'` (`hooks/useWindowMode.ts:5`) is the window geometry, and **main is its only owner**: the value arrives from the mount snapshot and `window:modeChanged` pushes (`:53-91`), never from an optimistic local write; the hook *requests* modes (`:99-124`). `searchMode` `'file' | 'ai'` (`components/ModeTabs.tsx:7`, state held at `App.tsx:82`) is the palette tab. They intersect at exactly one place: `components/CommandPaletteBody.tsx:68` — `searchMode === 'ai' && windowMode === 'expanded'` renders `AskModeExpanded`, otherwise `ResultsList`/`SearchEmptyState`. `CommandPalette.tsx:102-103` hides results and footer in compact.
- **The OS window is the only animator of the palette's height, and main is the only owner of its value.** `CommandPalette`'s container is `h-full` in every mode (`CommandPalette.tsx:142`); it must not gain a `transition-[height]`, a fixed `h-[…]`, or a `min-h-[…]`. Measured before this rule: the card carried `transition-[height] duration-150` plus `min-h-[var(--container-expanded-height)]` in expanded and a fixed 100px in compact, and while the window tweened it disagreed with the window by **-298px mid-expand** (the footer and input were clipped below the frame) and **+444px mid-collapse** — a transparent, still-`alwaysOnTop` slab over the desktop that was taller than the card and swallowed clicks there. Frame-for-frame after the change: 0px difference in both directions. `--container-compact-height`, `--container-expanded-height` and `--container-custom-height` are **deleted**, not dormant: the last consumer was `CommandPalette`'s old size-logging effect, and a token mirror of main's `MODE_CONFIGS` heights is what let a fifth copy of those pixels exist at all. `--container-command-palette` (width) and `--container-header-height` stay, both consumed.
- **A view swap needs a React key.** `CommandPaletteBody` returns one of three branch wrappers (`key="ask"|"empty"|"results"`) and `CommandPaletteHeader` swaps on `key="ask"|"files"`; every branch is a `div` at the same position, so without the key React reuses the node, `.view-enter` never re-applies, and the swap looks un-animated exactly as it did before the animation was authored. Adding a fourth branch means adding a key. `CommandPalette` itself is the exception: its `.palette-revealing` is restarted imperatively by `hooks/useWindowReveal.ts`, never through `className`, because React re-writes the class attribute on every mode change and a keyed-className reveal would re-play the summon each time the window resizes — including mid-typing.
- **`CommandPalette` must work both controlled and standalone.** `:72-74` fall back to local state when `searchMode`/`onSearchModeChange` are absent; `:91-92` do the same for `showShortcuts`. Keep the fallback — the palette is mounted without props in isolation harnesses.
- **Result merge is one memo, in one place** (`App.tsx`): query + `searchMode === 'ai'` → only `baseResults`; query in file mode → calculator result, matching system commands, then `fileResults`, then `baseResults`; a query matching nothing yields the web-search fallback; no query → curated system commands + `baseResults`. `useFileSearch` is disabled outright in AI mode. Change ordering in that memo only, never inside `ResultsList`. System-command definitions and the calculator live in `utils/systemCommands.ts`; execution fans out in `hooks/useCommandExecution.ts` (calculator copies the answer, system rows go through `command:execute`, info-only rows are inert).
- **`handleAskAbout` is the file→AI handoff** (`App.tsx:148-157`): attaches the selected result, seeds the query text, flips `searchMode` to `'ai'`. Fired from `useKeyboard.ts:105-108` and passed down at `App.tsx:238`. It only reaches chat when `windowMode === 'expanded'` (`CommandPaletteBody.tsx:68`) — compact mode is a no-op by design.
- **`onExitAskMode` is the ask-mode escape hatch.** Declared at `AskModeExpanded.tsx:32`, plumbed `CommandPalette.tsx:172` → `CommandPaletteBody.tsx:35,82` → `AskModeExpanded`, where the not-configured card renders it as "Back to Files" (`AskModeExpanded.tsx:400-404`). The source is `onExitAskMode={() => setSearchMode('file')}` — no new state, no IPC. Any other surface that must pull the palette out of Ask mode uses this prop, not a second mechanism.
- **ActionPanel is live.** `components/ActionPanel.tsx` renders the `Ctrl+K` contextual actions for the selected result (actions defined in `utils/fileActions.ts`, with `open` scoped to file/app rows, an `execute` row routing command rows to `onExecute`, and a `copy-result` row for calculator output). `App.tsx` owns the `actionPanelResult` state and passes `onOpenActionPanel` into `useKeyboard`; the panel closes on execute and Escape reaches it through the graded tier-1 dialog check. `SettingsDialog` (`components/SettingsDialog.tsx`, opened by `Ctrl+,`) owns the theme/mode/shortcuts/MCP overview. `SearchEmptyState` offers exactly one quick action. `quickActions` (`SearchEmptyState.tsx:23`) holds `find-in-folder` only (`:25`), and `App.tsx:230-237` handles only that id. `recent-files`, `open-terminal` and `git-status` are gone from the UI — their handlers did nothing but `logInfo('requires new IPC handler')`. Do not advertise four quick actions and do not re-add a tile whose App handler is a stub.
- **The window drag/resize handle lives at App level, outside the rounded container** (rendered only in expanded at `App.tsx:256-261`) because `CommandPalette`'s `overflow-hidden` would clip it. The pointer logic is `hooks/useResizeDrag.ts`, not an App effect: the inline version it replaces registered `mousemove`/`mouseup` behind a ref guard inside a `[]`-dep effect, so they never attached, `window:resizeHeight` was unreachable, and main's expanded-mode `setMaximumSize` ceiling constrained nothing. `useResizeDrag.test.tsx` pins all four behaviours, including that a move arriving before `getHeight` resolves is ignored. Geometry, cursor and stacking come from `.window-resize-handle` (`ask-mode-perplexity.css:1876-1889`); the handle must not carry an inline style again — it previously restated `position/bottom/left/right`, fought the `z-index` scale (60 vs the token layer's 50), and set `cursor` from a ternary with two identical branches. **Verified live** on the shipped app through the harness: one OS-level drag of 124 physical px moved the DOM height 603 → 702 CSS px (a 99 px delta, i.e. 1:1 in DIP), and `set_mode compact` afterwards still settled back to the compact height, so a user resize does not wedge the mode machine. Keyboard equivalent (no drag needed): `Alt+ArrowUp/Down` in expanded resizes ±40px through `resizeByKeyboard` (same floor + `window:resizeHeight` IPC), and the handle itself is a focusable `role="slider"` with arrow keys. Not verified: the min/max clamp — a second over-drag started at the old bottom edge, which the grown window had moved out from under, so the pointer landed on the body and nothing resized; at 702 CSS px nothing was near the ~1080 ceiling anyway. Keyboard resize is likewise live-unverified pending a restarted dev session.
- **`ErrorBoundary.tsx:13` is the only class component in the renderer** (`getDerivedStateFromError` `:19`, `componentDidCatch` `:23`, optional `fallback` prop `:5`). It wraps the whole tree (`main.tsx:11`) and owns the single sanctioned non-logger `console.error` (`:24`).
- **No code splitting exists here.** Zero `React.lazy` or dynamic `import()` in live renderer code — the only hit is dead `data/mockAskData.ts:124`. The <500ms budget is met by keeping the tree small; do not document lazy loading as current behaviour.
- **One preload, and the type surface is two competing declarations.** `src/preload/preload.ts:171` exports `electronAPI` → `:408` `contextBridge.exposeInMainWorld('electronAPI', …)` → `:416` `export type ElectronAPI = typeof electronAPI` → `types/electron.d.ts:3-7` declares `Window.electronAPI` from that type. Renderer code only ever reaches main through `window.electronAPI`; it never imports from `src/main`.
- **`types.d.ts` is a stale hand-maintained duplicate that currently WINS for the channels it declares — it is a fifth sync site.** It re-declares its own `ElectronAPI` interface (`:75-215`) and its own `declare global { interface Window { electronAPI: ElectronAPI } }` (`:217-221`), `src/preload/types.d.ts:1-3` re-exports from it, and `tsconfig.json:19` (`include: src/**/*`) plus `tsconfig.web.json` (`include: src/renderer/**/*`) both compile it, so `tsc` applies it to the renderer. Proof measured in this session: `src/renderer/types.d.ts:159` declares `chat.initialize(): Promise<{success, ready, error?, retryable?}>`, and when `retryable` was added to the main-process handler the renderer call site type-errored until `types.d.ts` itself was edited — `types/electron.d.ts` could not fix it. So a channel already declared there needs five edits, not four: preload, `ipcMain.handle`, renderer call site, and **both** `.d.ts` files. Do not extend it casually, and do not pretend types flow only from preload; deleting it is a deliberate change of its own that must clear every importer at once.
- **Channel namespaces available to the renderer** (`preload.ts:171-396`): `app:*` (version/platform/systemInfo/quit), `window:hide|setMode|getMode|toggleMode|setCustomDimensions|resizeHeight|getHeight`, `command:execute`, `url:open`, `file:open|revealInFolder|search|everything:status`, `apps:list`, `debug:log`, `chat:*` (11 invokes — `sendStreamMessage` not `sendMessage`, and no `resumeGraph`, both deleted — plus `cancelTurn` and the `turn-started` listener), `browser:*`, `mcp:*`, `dialog:openFile|openFolder`, `api-config:save|load|delete|test`. Deleted as senderless, so they are **not** available: `chat:stream-replace` and `chat:ui-payload-started|progress|reset`.
- **Push listeners**: `window:shown|will-hide|modeChanged` (`preload.ts:50,57,62`), `desktop:screenshot:capture` (`:74`), `chat:*` (5), `browser:*`. Every `on*` returns an unsubscribe function and the subscriber MUST store and call it — `hooks/useChatSession.ts:192-354` is the exemplar.
- **Every `electronAPI` promise is rejected-handled at the call site** — `.catch()` (`App.tsx:219,275`) or `try/catch` (`hooks/useWindowMode.ts:69-81,116-118`). A rejected IPC call must never reach the console.
- **Every async `setState` is mounted-guarded, and the guard is `isMountedRef`.** An effect that awaits `window.electronAPI.*` and then calls `setState` writes into a dead tree if the component unmounted first. The single shape — ref declared, set `true` on mount, flipped `false` in the mount effect's cleanup, checked before **every** setter including a `finally` that clears a loading flag — lives in `hooks/useFileSearch.ts` and is documented as a contract in `hooks/AGENTS.md`. `App.tsx`'s `useIsMounted()` plus module-scope `loadAppList`/`loadMcpCount` are that same pattern expressed for the root component, which is already at the 50-line ceiling and must extract rather than accumulate effect blocks. A timer or `requestAnimationFrame` armed without a ref and an unmount cleanup is the same defect class; the holders and the double-clear rule are in `hooks/AGENTS.md`. No `electronAPI` call is cancellable, so a guard means "do not start more work after teardown" — never "abort what is in flight", and never an `AbortController` in this tree.
- **`context/` and `contexts/` are BOTH live; the collision is the defect, not a candidate for deletion.** `context/ThemeProvider.tsx` is mounted at `main.tsx:4` and consumed at `App.tsx:14,38`; `contexts/ToastContext.tsx` is consumed at `components/AskModeExpanded.tsx:6` and `hooks/useToast.ts:1`. Document which is which in any new import; merge them only as a deliberate, all-importers-at-once change.
- **State management is React-only.** No store library, no redux, no zustand. `useState`/`useReducer` plus props; context is reserved for theme and toast. `useReducer` is used where IPC events drive a state machine — `browserReducer`/`desktopReducer` from `hooks/useBrowserState.ts:32` and `hooks/useDesktopState.ts:34`, consumed at `AskModeExpanded.tsx:82,85`.
- **Styling: pointer only.** Tokens belong to `styles/AGENTS.md`. The sanctioned forms at this level are `@theme`/`@theme inline` utilities and `var(--token)`; the drift check is `grep -rn "\-\[" src/renderer/components/ --include=*.tsx --include=*.ts` (98 code hits) and any hit is reviewed against that doc, not fixed ad hoc.
- **Dead code — proven zero importers repo-wide.** `components/ApiKeySetup.tsx`, `components/ChatHistoryDropdown.tsx` (its fake default history never reached a real session — `SearchBar` only logged selections — so the compact header no longer mounts it), `components/ContextUsageIndicator.tsx`, `hooks/useDebounce.ts`, `hooks/useFocusTrap.ts`, `utils/citationFormatter.ts`, `types/search.ts`, and all of `data/` (`data/mockAskData.ts`). Do not import, extend, or wire them up; do not document them as live. Deletion needs an explicit request.

## Work Guidance

- New renderer state goes in `App.tsx` only if it is cross-cutting orchestration; otherwise it belongs in a hook under `hooks/` and arrives as props.
- Data flows one way: `App` owns palette state, shell components are presentational. The single exception is `AskModeExpanded`, which calls `hooks/useChatSession` itself rather than receiving chat state as props — the session surface is too large to prop-drill. Do not create a third pattern.
- Add a component: named function export only (`export function X`), PascalCase, props interface exported from the same file next to the component (`CommandPalette.tsx:13`, `ModeTabs.tsx:9`). Type ownership: `SearchResult` is owned by `ResultsList.tsx:7`, `SearchMode` by `ModeTabs.tsx:7`; `types/commandPalette.ts:5` is a re-export, not a second definition.
- Class strings go through `cn()` (`lib/utils.ts:4`) as a multi-line array with one mockup-line comment per token group — copy the shape at `CommandPalette.tsx:183-200`.
- Import alias `@/` → `src/renderer` (`tsconfig.json:15-17`, `vitest.config.ts:22`). Relative paths are legacy; new code prefers `@/`.
- Never call `console.*`. Use `logInfo`/`logWarn`/`logError`/`logDebug`, gated by `VITE_LOG_LEVEL` (`utils/debugLogger.ts:16-27`). `utils/fileActions.ts:18,49` still uses `.catch(console.error)` — that is existing debt, not a pattern to copy.
- Any URL that reaches an `href`, a `window.open`, or `url:open` goes through `utils/externalUrl.ts` `safeExternalUrl` first. Model-authored and transcript-borne URLs are untrusted input in a renderer that holds the `command:execute` bridge.
- Keep functions under 50 lines (root rail). `App.tsx` is already at the ceiling: extract into a hook rather than adding another effect block.
- New IPC channel = four edits (preload method, `ipcMain.handle`, renderer call site, `types/electron.d.ts`) — **five** if `src/renderer/types.d.ts` already declares that channel, because it wins for the channels it names (see the bridge contract). Full recipe in `../main/ipc/AGENTS.md`.
