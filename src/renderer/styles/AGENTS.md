# src/renderer/styles — DOX child contract (token authority)

Parent: `src/renderer/AGENTS.md` (`../AGENTS.md`) and the root `AGENTS.md` rail (`../../../AGENTS.md`). This doc is the nearest contract for `styles/` and the token authority for the renderer.

## Purpose

- Sole source of every visual value in the renderer: colour, spacing, radius, shadow, motion, type scale, stacking. If a component needs a number or a colour that is not here, the fix lands here — never inline in JSX.
- Implements the three-layer token system and registers it with Tailwind v4 so shadcn utilities (`bg-background`, `text-muted-foreground`) resolve.
- Owns the two component-adjacent stylesheets that carry the ask-mode BEM class vocabulary.

## Local Contracts

- **Three layers, no skipping**: base `tokens/*.css` → semantic `semantic/theme.css` → component. Declared in-file at `tokens/colors.css:15-21` and `semantic/theme.css:12-15`; `tokens/colors.css:20` reads "NEVER SKIP THE SEMANTIC LAYER — this is what makes refactors safe." A component reads `--primary`/`bg-primary`, not `--color-mist-500`.
- **Registration split is load-bearing.** Plain `@theme` in `tokens/` exposes each token as a Tailwind utility. `semantic/theme.css:19-65` is `@theme inline` and maps `--color-*` → `var(--*)` (`--color-background: var(--background)` `:20` … status pairs `:52-57`, file-type tokens `:60-64`). Scoped to CSS it is the only `@theme inline` in `src/` (`grep -rn "@theme inline" src/ --include=*.css`); a second one means the layering is broken.
- **Dark mode**: light values in `@layer theme`'s `:root` (`semantic/theme.css:69-124`), dark overrides in the `.dark` block (`:127-173`), variant declared once as `@custom-variant dark (&:is(.dark *))` (`globals.css:14`) — the `theme.css:9-10` header comment points at it and is not a second declaration. **There is no `@variant dark` anywhere** — that spelling matches no real Tailwind v4 at-rule. `design-systems/SHADCN-DESIGN-SYSTEM.md:451` and the root rail state the `@custom-variant` form. Dark is applied at runtime by `../context/ThemeProvider.tsx:36-37`, which removes then adds `light`/`dark` on `document.documentElement`; no `prefers-color-scheme` query exists in `styles/`.
- **Token inventory** (all verified; extend, do not re-invent):
  - `tokens/colors.css` — mist ramp, gray ramp, the **full brand ramp 50–900**, functional red/green/yellow/blue 500s (fills only), `--color-chart-1..5`, always-dark code-block colours, `--color-gray-750/850`, and the raw `--color-purple-500`/`--color-orange-500` hues that exist only so `--agent-*` can be derived from them. Also holds four **deprecated aliases** (`--color-green-active/-muted/-subtle`, `--color-code-ts-dot`) that forward to semantic tokens so an un-migrated reference cannot drop; delete them once no consumer remains. Line numbers are not maintained — read the file.
  - `tokens/spacing.css` — a strict 4pt scale (`--spacing-0…16`, every rung a multiple of 4; the half-step rungs are deliberate grid aliases, see the header), container dimensions (`--container-command-palette` 800px, `--container-input-height` 40px, `--container-header-height` 72px — the latter MUST equal main's `MODE_CONFIGS.compact.height` because the compact card is exactly one header tall), the **rhythm vocabulary** (`--gap-inline`, `--gap-block` 12px, `--gap-section` 16px, `--padding-inline-control`, `--padding-block-row`, `--padding-block-section`, `--padding-card` 12px — tightened for the compact aesthetic), the **target floors** (`--target-min` 32px, `--target-row` 40px), icon sizes, ask-mode geometry and `--measure-readable`. The three mode-height tokens stay deleted (main owns height); the 9/10/11px text one-offs **moved to `typography.css`** — they were never spacing.
  - `tokens/radius.css` — the **minimum-radius standard**: a hard 8px ceiling (`--radius` = `--radius-lg`) and two tiers only. SURFACE tier = 8px (palette card, dialogs, popovers, dropdowns, cards, toasts, banners — the largest corner, pinned to the Win11 DWM frame radius this frameless transparent window is clipped by, `src/main/windows.ts:83`). CONTROL tier = 2–6px (`--radius-md` 6 for inputs/rows/menu items, `--radius-sm`/`--radius-chip` 4 for chips/badges/tags/keycaps, `--radius-xs`/`--radius-micro` 2 for swatches/indicator bars/text highlights). `--radius-xl/2xl/3xl/4xl` are **pinned to the ceiling**, not deleted — Tailwind v4 `@theme` merges with the default theme, so an undeclared name silently resolves to Tailwind's stock value (16px for `--radius-2xl`); declaring them at 8px makes "no corner exceeds 8px" a property of the token file, not a review convention. `--radius-full` is NOT part of the ladder — it is for shapes genuinely circular or pill-by-nature (avatars, status dots, switch tracks/thumbs, scrollbar thumbs, meter tracks/fills, spinner rings); a rectangular chip/badge/tag uses `--radius-chip`/`--radius-sm`. Bare `rounded` is banned because it silently resolves to the 8px SURFACE ceiling (`var(--radius)`) rather than the control tier — that is how 8px corners ended up on 20px keycaps. Tailwind v4 maps the `--radius-*` namespace onto the `rounded-*` utilities, so this one file moves every corner — including the pristine `ui/` primitives — with no component edit. The rungs are spelled out, not `calc()`-multiplied: multiplying produced 3.6px and 6.4px corners.
  - `tokens/shadow.css` — OKLCH tinted scale (`--shadow-sm…2xl`), one elevation per surface class (`--shadow-command-palette`, `--shadow-popover`, `--shadow-dialog`, `--shadow-tooltip`, `--shadow-toast`, `--shadow-shortcut-key`, `--shadow-inset`) and the ring tokens. `--ring-color` defers to `var(--ring)` so the focus indicator themes; pointing it at a brand primitive measured 2.35:1.
  - `tokens/motion.css` — durations (100/150/200/300/500), the **easing scale** (`--easing-smooth` `cubic-bezier(0.22,1,0.36,1)`, `--easing-enter`, `--easing-exit`, `--easing-spring`, `--easing-standard`, `--easing-linear`), loop tokens, entry/exit shorthands, stagger presets, and every `@keyframes` in the app. Entry shorthands use `backwards`, never `both` — see the rule above. `--easing-linear` exists for one thing (an elapsed-time meter) and `.toast-progress-fill` is its consumer; do not delete it. Durations 75/700/1000 and the `--transition-*` composites stay deleted: nothing consumed them and `--transition-*` could only be used by adopting `transition: all`. `node tmp/motion-tokens-check.mjs` fails on a shorthand with no keyframe, no reduced-motion reset, or no consumer.
  - `tokens/typography.css` — the font stacks (`--font-sans`/`--font-display`/`--font-body` are a **system sans**; `--font-mono` is JetBrains Mono and belongs on code, paths, key labels and command strings), the six-size scale where **each rung carries its own `--text-*--line-height` and `--text-*--letter-spacing`**, weights, `--tracking-*` and `--leading-*`. `--text-2xs`, `--text-xs-custom` and `--text-11px` are 12px aliases kept only so an old `var()` cannot drop; `--text-code-inline` (0.9em) is for inline code inside prose. Never add a size below 12px and never restate a leading next to a rung.
  - `tokens/z-index.css` — the eight layers the app stacks in: `--z-canvas 0`, `--z-raised 10`, `--z-sticky 20`, `--z-sunken 25`, `--z-overlay 30`, `--z-modal 40`, `--z-popover 50`, `--z-tooltip 60`, `--z-toast 70`. Consumed as `z-[var(--z-…)]` in JSX and `z-index: var(--z-…)` in CSS. The old `--z-base`/`--z-dropdown` names and the three `--z-command-palette*` aliases are deleted — they had one consumer between them and the aliases contradicted each other. Radix portals land in `document.body`, so anything that must beat a dialog has to be in that same root context; that is why `.toast-region` is portalled and why the palette container holds no layer.
- **OKLCH is required for every token value** (`tokens/colors.css:12`, "All colors in OKLCH format for perceptual consistency"). Scoped to code (`--include=*.css --include=*.tsx --include=*.ts`), `oklch(` has zero occurrences inside `src/renderer/components/` — colour literals must never migrate into JSX.
- **Import order is load-bearing** (`globals.css:1-12`): `tailwindcss` → `tw-animate-css` → `shadcn/tailwind.css` → the seven token files → `semantic/theme.css` → `ask-mode-perplexity.css`. Semantic must precede `ask-mode-perplexity.css`, which consumes `var(--border)` etc. A new `tokens/*.css` file needs an `@import` inserted **before** `:11`, or its utilities are never generated.
- **Consumption rule** (`design-systems/SHADCN-DESIGN-SYSTEM.md:289-297`): Tailwind utilities for typography, colour and radius; `var(--token)` inside arbitrary values for container dimensions, custom spacing and motion. Exemplars: `CommandPalette.tsx:183-198` (`w-[var(--container-command-palette)]`, `shadow-[var(--shadow-command-palette)]`, `rounded-[var(--radius-command-palette)]`) and `common/ShortcutKeys.tsx:19-25`.
- **Forbidden**: any raw literal — `w-[800px]`, `text-[13px]`, `rounded-[10px]`, `shadow-[0_1px_3px…]`, `text-[oklch(…)]` — and `text-[var(--text-xs)]` where the utility exists (`SHADCN-DESIGN-SYSTEM.md:303`: "the CSS var won't resolve at build time"). New tokens go in `tokens/`, never inline in a component.
- **Legibility is a token contract, not a review opinion**: a `--file-*` token or an accent token must clear 4.5:1 **as text in both themes**, which is why the `.dark` block is mandatory rather than optional. Light `--primary`, `--ring`, `--chart-1`, `--sidebar-primary`, `--sidebar-ring` are `oklch(0.54 0.115 230.923)`, `--muted-foreground` `oklch(0.53 0 0)`, `--destructive` `oklch(0.5 0.245 27.325)`; light `--file-*` are darkened (ts `0.545 0.119 254.1`, js/py `0.48 0.189 84.43`, rust `0.48 0.158 162.48`, go `0.48 0.118 184.704`) and each has a `.dark` override lifting only lightness (ts `0.75`, js/py `0.8`, rust `0.72`, go `0.72`). Nothing in `styles/` may restate the old "file type colors stay the same in dark mode" note — that comment described the bug, and the `.dark` block is what replaced it. **Line numbers are not maintained here** — read `semantic/theme.css` for the current values, and `node tmp/contrast-full.mjs --strict` to prove they still clear their floors.
- **The surface ramp is the elevation language.** Light `--background` 0.975 < `--sidebar` 0.965 < `--muted`/`--secondary`/`--accent` 0.955 < `--card`/`--popover` 1.0 (in light, up = whiter, and a popover is separated from a card by shadow + border). Dark `--background` 0.145 < `--sidebar` 0.175 < `--card` 0.205 < `--muted` 0.245 < `--popover` 0.275 (up = lighter). Before this, light background, card and popover were all `oklch(1 0 0)` and dark card, popover and sidebar were all `oklch(0.205 0 0)` — the app had no way to express a raised surface at all. `--border` (decorative divider, floor 1.4) and `--input` (the boundary of an interactive control, floor 3.0 per WCAG 1.4.11) are **deliberately different values**; merging them back into one is the regression this note exists to prevent.
- **A hue primitive is never a fallback for text.** `text-[var(--color-blue-500)]` / `text-[var(--color-green-500)]` used to be cited here as the sanctioned step below a semantic utility; that was wrong and it is now gated. A primitive has no `.dark` half, so as text it is legible in exactly one theme — measured on a light card: `--color-yellow-500` 1.72:1, `--color-green-500` 2.40:1, `--color-red-500` 3.79:1, `--color-blue-500` 3.65:1. `node tmp/token-refs.mjs` fails on any of them in a `color:` position or as a `text-[…]` utility. The real fallback ladder is: semantic utility (`text-success`) → semantic variable in an arbitrary value (`bg-[var(--success-soft)]`) → **promote a new semantic pair with a `.dark` half** into `semantic/theme.css` when something genuinely has no name yet. That is how `--success`/`--warning`/`--info`, the `-soft` tints and `--agent-browser`/`--agent-document` got there.
- **Reduced motion is centralised, and an animation that consumes an `--animate-*` shorthand is covered by it automatically**: `globals.css:16-64` (a) sets every `--animate-*` token to `none` `:25-38` — `none`, not `0ms`, because `animation: 0ms` is invalid at computed-value time and only works by CSS error recovery, whereas `none` states the intent, (b) zeroes the whole `--duration-*` scale `:40-44` and every `--stagger-*` delay `:46-51`, and (c) applies `*, *::before, *::after { animation-duration/animation-delay/transition-duration/transition-delay: 0ms !important }` `:54-63`. The universal rule exists because Tailwind `duration-*` utilities and any literal duration bypass the token path entirely (the two that did — `animation: progressPulse 2s …` in `globals.css` and `animation: agentPulse 2s …` in `ask-mode-perplexity.css` — are now the `--animate-progress-pulse` / `--animate-agent-pulse` shorthands, so their keyframes live only in `tokens/motion.css`). Adding an animation therefore means: the keyframe plus its `--animate-*` shorthand in `tokens/motion.css`, and the matching `--animate-…: none` line in `globals.css:25-38` — **two** places. A third is needed only for a class that animates through a literal loop duration rather than a token (`globals.css:647-655`); the per-file mirror that used to sit at the end of `ask-mode-perplexity.css` was deleted once every animation in that file went through a shorthand. Measured in the running app under emulated `prefers-reduced-motion: reduce`: `.palette-revealing` computes `animation-name: none, opacity: 1, transform: none`, so reduced motion reveals the palette rather than hiding it.
- **JS motion reads the same tokens instead of adding a second media query**: `../utils/motion.ts` exposes `motionDurationMs` / `motionEasing` (both read `getComputedStyle(document.documentElement)`, so the `:root` overrides above are the signal) and `prefersReducedMotion` for APIs that take no duration, e.g. `scrollIntoView({ behavior })`. `@formkit/auto-animate` disables itself on `prefers-reduced-motion` and needs neither.
- **A component class must never share a name with a library `@utility` — the utilities layer beats the components layer regardless of specificity.** `globals.css:3` imports `shadcn/tailwind.css`, which defines `@utility shimmer` (+ `--shimmer-angle/-color/-duration/-spread/-image/-none/-once/-reverse/-text-fill` variants) and `@utility no-scrollbar` / `@utility scroll-fade*`; `tw-animate-css` at `:2` owns the `animate-in`/`fade-in-0`/`zoom-in-95`/`slide-in-from-*` vocabulary. Anything written here under one of those names is overridden, silently. Proven on `.shimmer`: the `animation: shimmer 1.5s infinite`, the gradient `background` and `background-size` this file used to declare **never applied** — the running app computes `animation-name: tw-shimmer` at `2s` on those nodes, not `shimmer` at `1.5s` — and only `background-color` survived, because the library does not set it. The rule now says exactly that (`:458`). Before adding a component class, `grep -c "@utility <name>" node_modules/shadcn/dist/tailwind.css node_modules/tw-animate-css/dist/tw-animate.css`.
- **Consequence for reduced motion, and why the mirror lies.** `animation: none` written for `.shimmer` in the `@media (prefers-reduced-motion: reduce)` block at `:647-655` would also lose the layer battle, so it was removed rather than kept as decoration. What actually stops library and literal animations is the blanket `*, *::before, *::after { animation-duration: 0ms !important }` at `:54-63` — `!important` reverses CSS cascade-layer order, which is the only reason it reaches the utilities layer. Verified under emulated reduce on a real `.skeleton-row shimmer` node: `animation-name: none, animation-duration: 0s, getAnimations().length === 0`, with `background-color` retained so the skeleton stays visible.
- **Measured, then rejected: a "composited" replacement for the library shimmer.** Rewriting `.shimmer` as a transform sweep on `::after` (renamed `.skeleton-sweep` to escape the collision) was measured against the library utility, interleaved twice, window visible, 21 nodes each: `tw-shimmer` 30.1ms / 27.7ms of main-thread `RecalcStyleDuration` per 2s, the transform version 39.6ms / 41.6ms — i.e. **not cheaper, and consistently a little worse**, at the same ~121 style recalcs (one per frame). Chromium ticks every CSS animation on the main thread whether or not the animated property composites, so `transform` does not buy what the theory predicted. The rewrite was reverted; `paint` was not measured and is the only place a win could still exist. Do not re-litigate this without a paint measurement.
- **The agent-pill hue gap is closed, and the gate now keeps it closed.** `--color-purple-500`/`--color-orange-500` were referenced by `.agent-indicator--browser/--document` and never defined, so CSS dropped the declaration and the pills rendered untinted with inherited text. Do not "fix" this by painting a single lightness: purple clears 4.5:1 only in light and orange only in dark. They are now the semantic pairs `--agent-browser` / `--agent-document` in `semantic/theme.css`, each with a `.dark` half that lifts only lightness — the same shape as `--file-*`. `node tmp/token-refs.mjs` fails if any non-token file references a hue primitive again, and also fails if a live stylesheet paints `--color-{green,yellow,red,blue}-500` as text or uses `rgb()`/`hsl()` anywhere.
- **Semantic pair naming**: `name` / `name-foreground` (`semantic/theme.css:20-51`) — primary, card, popover, secondary, muted, accent, destructive, sidebar (+ `sidebar-primary`, `sidebar-accent`, `sidebar-border`, `sidebar-ring`) — plus the status pairs `--success`/`--success-foreground`, `--warning`/`--warning-foreground`, `--info`/`--info-foreground`, declared in both `:root` (`:95-100`) and `.dark` (`:144-149`) and registered in the single `@theme inline` as `--color-success` etc. (`:52-57`). They exist because the primitives `--color-yellow-500` (1.30:1 on a light card) and `--color-green-500` (2.6:1) are illegible as text and toasts were hardcoding raw hex; a toast or status surface uses `var(--success|warning|info)`, never a primitive green/yellow for text. Any new surface token needs both halves.
- **Component-adjacent vocabulary lives in these two files only**: `ask-mode-perplexity.css:2869-2955` defines `.ask-mode-expanded`, `.chat-loading-state`, `.loading-spinner`, `.chat-not-ready` and `.chat-not-ready-title|-body|-list|-actions` (consumed by `../components/AskModeExpanded.tsx`), and `globals.css:539-645` defines the toast vocabulary `.toast-region`, `.toast-container`, `.toast`, `.toast-icon`, `.toast-message`, `.toast-dismiss-btn`, `.toast-progress-bar`, `.toast-progress-fill` with `@keyframes toastDrain` `:640` (emitted by `../contexts/ToastContext.tsx`). `.toast` enters on `--animate-toast-enter` and exits on `.toast[data-state="exit"]` `:571`, which the provider sets — the provider's removal delay reads `--duration-150`, the duration that shorthand composes, so CSS and JS cannot disagree about how long a dismissed toast stays. Before these rules existed the classes were referenced from JSX and styled by nothing, which is why the ask-mode loading state painted as raw left-aligned text and toasts had no layout.

## Work Guidance

- Add a token: pick its file by kind, append inside the existing `@theme` block, comment the provenance in the house style (`/* Mockup line 78 */`, `spacing.css:36`), then consume it. Do not create a fourth layer, a `tokens/*.css` without an `@import`, or a component-scoped stylesheet.
- Add a dark-mode value: override the **semantic** variable in the `.dark` block (`semantic/theme.css:127-173`). Reserve `dark:` utilities for upstream shadcn primitives in `components/ui/`; do not scatter them through feature components. A light-only change to an accent or `--file-*` token is incomplete until the `.dark` half exists and passes the contrast gate.
- Add an ask-mode class: it goes in `ask-mode-perplexity.css` (chat/transcript/command-bar/loading vocabulary) or `globals.css` (generative-UI primitives and toasts) — see the ask-mode contract at `../components/ask-mode/AGENTS.md`. A class referenced from JSX but defined in neither file renders unstyled; that is a bug, not a TODO.
- Add an animation: keyframe + one `--animate-*` shorthand in `tokens/motion.css`, then consume the **whole shorthand** — `animation: var(--animate-scale-in)` in CSS, or the generated `animate-scale-in` utility in JSX. Never re-composite `animation: scaleIn var(--duration-150) var(--easing-smooth) both` by hand: that is the shape that drifted, and `node tmp/motion-tokens-check.mjs` is what catches it. Then add the `--animate-…: none` line to the reduced-motion block. Looping indicators (`spin`, `pulse`, `cursorBlink`, `typingDots`) are the only animations whose duration may sit outside the `--duration-*` scale, because the scale describes transitions, not cycles.
- Add a view-swap animation: the branch must carry a distinct React `key`, or React reuses the existing DOM node, the class never re-applies, and the animation silently never runs — the failure looks identical to "no animation was authored". `CommandPaletteBody.tsx` (`key="ask"|"empty"|"results"`) and `CommandPaletteHeader.tsx` (`key="ask"|"files"`) are the exemplars; `CommandPalette.tsx` is the exception because its animation restarts through `../hooks/useWindowReveal.ts` rather than through a mount.
- Keep the two stylesheets as CSS only. No `@apply` outside `@layer` blocks, no inlined component stylesheets from JS, no CSS-in-JS.
- Asset tracks are separate and both live outside this folder: `src/renderer/index.html:10-11` links favicons out of the renderer root (`../../build/icons/icon-256.png`, `icon.ico`) while `npm run generate-icons` regenerates only `build/icons/`; `public/` is a hand-maintained set consumed at runtime by ask-mode (`ChatWelcomeState.tsx:72-73`). A logo used by a component belongs in `public/`; a window/app icon belongs in `build/icons/`.

The older `node tmp/contrast.mjs` checked 11 pairs, marked the border pair "informational", and mis-computed luminance (it reported `foreground on card` as 17.32:1 where the correct figure is 19.77:1) — it exits 0 on states that fail, so it is not the gate. Values are read from the token files, never hardcoded.
- **Token-resolution gate (scratch tool)**: `node tmp/token-refs.mjs` asserts every `var(--x)` used in `src/` resolves to a defined token, and enforces layer discipline (no hue primitive as text, no `rgb()`/`hsl()`, no `transition: all` outside pristine `components/ui/`). This exists because an unresolved custom property makes the whole declaration vanish silently at runtime — that is exactly how the undefined `--color-purple-500` shipped an untinted pill. DOX-declared dead files are excluded: a gate that fails on code that never renders gets ignored wholesale.
- **Live-style probe (scratch tool)**: `node tmp/live-style.mjs` attaches to the running palette over CDP and reports *computed* values — body font family, the resolved surface ramp, a button's `transition-property`, whether `.view-enter` still holds a permanent `transform`, whether `.toast-region` is a child of `BODY`, and every rendered node below 12px or 32px. CSS greps prove intent; only the running app proves pixels. It dispatches a synthetic key to switch palette tab, which `scripts/harness` deliberately never does — it is a diagnostic, not the harness.
- **Motion gate (scratch tool)**: `node tmp/motion-tokens-check.mjs` strips comments, then asserts that every `--animate-*` shorthand names a keyframe that exists, that every `var()` in an `animation`/`transition` declaration is defined, that every `--animate-*`/`--duration-*`/`--stagger-*` token has a reduced-motion reset, and that no `--animate-*` token is defined-but-unused (JSX is scanned for the generated `animate-*` utilities). It exits non-zero on all four — a dangling token is invisible at runtime, which is why this check exists. Currently exits 0; it also flagged the `--color-purple-500`/`--color-orange-500` gap recorded above.
- There are no CSS unit tests — nothing in `vitest.config.ts` renders a stylesheet. The motion surface is covered by the scratch gate above plus `src/main/windowManager.test.ts`, which drives the real main-process tween (its deceleration assertion was mutation-checked: swapping the eased curve for a linear one fails it at 0.534 against a 0.65 threshold).
