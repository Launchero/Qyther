## Re-render the SVGs

```bash
# write the puppeteer config into gitignored scratch first (contents below), then render
# the config is NOT committed: authoring it is part of the render step
PUPPETEER_SKIP_DOWNLOAD=1 npx -y -p @mermaid-js/mermaid-cli -p puppeteer \
  mmdc -i docs/diagrams/ask-routing.mmd -o docs/diagrams/ask-routing.svg -c tmp/mmd-cfg.json
```

The `-p puppeteer` half is not optional: `npx -y @mermaid-js/mermaid-cli` alone installs the CLI without its peer, and every verb then dies with `ERR_MODULE_NOT_FOUND: Cannot find package 'puppeteer'`. mermaid-cli drives headless Chromium via puppeteer. With `PUPPETEER_SKIP_DOWNLOAD=1` set, point it at an installed Chromium through a config file: `... -c tmp/mmd-cfg.json` where that file is `{"executablePath":"<path>/chrome.exe","headless":"true","args":["--no-sandbox","--disable-gpu","--disable-dev-shm-usage"]}`. The Playwright-installed Chromium under `%LOCALAPPDATA%/ms-playwright/chromium-*/chrome-win64/chrome.exe` works; the standalone `chrome-headless-shell` did not (crash 0xC000013B). Both `ask-routing.svg` and `desktop-hitl.svg` were re-rendered from their rewritten sources on 2026-10-16. `system-context.svg` was re-rendered on 2026-10-17 after its source turned out to carry six stale labels that an earlier pass had assumed needed no change: `MCPAdapter (client.ts)` (the client is `MCPService` over `@earendil-works/pi-mcp`), `HTTPS (@langchain/openai)` (the model is reached through `@earendil-works/pi-ai`), `HTTPS fetch (tools.ts)` (it is `web/fetch/page.ts`), `browser-memory/trajectories.db` (that store was deleted), `60 handlers` (62), and a `html.duckduckgo.com / api.tavily.com fallback` box describing the deleted two-engine scrape rather than the seven-rung registry chain. **Every `.svg` here is a real render of its `.mmd`, not hand-authored — and an `.mmd` whose mtime is newer than its `.svg` is a stale render, so check `ls -la --time-style=+%F docs/diagrams/*` after editing a source.**

## What these diagrams deliberately do NOT show

- Not the internals of each tool family — `web`, `ui`, `document`, `browser` and `mcp` are drawn as single boxes; the per-tool contracts live in the owning `AGENTS.md` under `src/main/services/`. (There are no subgraphs to expand: the graph was deleted at the Pi cutover.)
- Not the document path's known defect — `uniqueFilePath` (`src/main/services/document/document-executor.ts`) is supposed to append a counter when a file already exists, but an unconditional `break` at the top of its loop makes it hand back the plain path, so same-named documents overwrite. Too much for these canvases; see `src/main/services/document/AGENTS.md`.
- Not the IPC four-site sync surface, validation drift, or the push-channel list; that is `docs/architecture.md`.
- Not the `browser:executeTask` direct-IPC path, which reaches the browser session without going through an Ask turn at all.
- Not any worker threads, a single-instance lock, or blur-to-hide — none of those exist in this codebase. (The settings window **does**: `src/main/settings-window.ts` builds a second `BrowserWindow`, and `system-context.mmd` shows only the process topology, not that window's internals.)
