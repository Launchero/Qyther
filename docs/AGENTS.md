# docs/ — Documentation boundary (DOX leaf)

Binding work contract for `docs/`. The root `AGENTS.md` "Documentation Authority" section classifies root-level markdown; that table is not repeated here. This doc governs the markdown files and material folders in `docs/` plus the durable rules for classifying any repo doc as live vs diary.

## Purpose

- Make `docs/` honest: every file is labelled by freshness so no reader has to infer whether its claims are current.
- Give an agent working in this repo a trustworthy pre-edit read: here, live reference and point-in-time diary are never confused.
- Encode the five classification rules in Local Contracts; they outlive any current file list.

## Local Contracts

1. **Freshness label mandatory.** Every doc added to `docs/` declares at the top, in one line, exactly one of: live / roadmap / history / mockup. A reader must never have to infer freshness.
2. **No `path:line` citations of source code.** Line numbers rot on the next edit; cite `path` plus symbol name instead. Existing violators to fix if touched: `UI-FIXES-SUMMARY.md:51`, `VISUAL-TESTING-REPORT.md:11`.
3. **No Cursor-tree references.** `.cursor/rules/*`, `.cursor/skills/*`, and `@design-tokens-enforcement` are dangling everywhere in this repo; never cite them as if they existed.
4. **Changelog convention** (the closest thing to a house template): metadata blockquote at the top, then `### [YYYY-MM-DD] slug: description` entries with **What / Files / Impact / Details** (`overall-architecture.md:136-142`). There is no front matter anywhere and no other template — do not invent one.
5. **Numeric facts are re-derived from source before being written.** Tool counts, file counts, versions must be counted from code, never copied from another doc. The docs above carrying wrong tool counts (`docs/desktop-agent.md` = 26, `docs/desktop-agent-gap-analysis.md` = 28) failed this. Current truth: **32 desktop tools**, all TypeBox `AgentTool`s in `src/main/services/pi/toolbox.ts`, with the list frozen by `src/main/services/pi/toolbox.test.ts`. There is no `DANGER_POLICY` and no 29/2/1 danger split to recount — both were deleted at the Pi cutover and not replaced; a doc citing them is citing deleted code, not a wrong number.

## Work Guidance

- New reference material belongs in the root `AGENTS.md`, `overall-architecture.md`, or the owning subtree's `AGENTS.md`; `docs/architecture.md` is the established live deep reference. Use the rest of `docs/` for studies, reports, mockups and generated material, and label any new prose doc per rule 1 on day one.
- Apply the rule 1 label as a blockquote directly under the `#` title, e.g. `> **Status**: roadmap — counts below are stale; see docs/AGENTS.md`.
- When editing `docs/desktop-agent-gap-analysis.md`, keep the roadmap label visible and correct the 28→32 tool count where you touch those sections; do not treat its gap tables as current inventory.
- Quarantined files (`docs/desktop-agent.md`, `docs/WEB-TOOLS-GUIDE.md`) are not authority; repair only as part of explicit doc-cleanup work, and if you cannot fix them, label per rule 1 rather than deleting.
- If your code change alters anything `docs/` counts or names (tool count, UIA backend, IPC surface), either update the affected doc in the same pass or state in your report that the doc is now stale.
- The HTML mockup needs no maintenance; if it is ever wired into the app, it stops being a `docs/` file and moves to the renderer tree.
- `docs/architecture.md` is live only while its counts match its own "How this doc is verified" greps; re-derive before citing, and correct in place when a tool count, IPC count, node count, storage engine or accessibility backend changes.
- Material folders (`docs/diagrams/`, `docs/assets/screenshots/`, `docs/assets/brand/`) are governed here, not as separate boundaries — they carry no independent rules. Regenerate their outputs rather than hand-editing: diagram `.svg`s from their `.mmd` sources (command in `docs/diagrams/README.md`), screenshots via `scripts/capture-ui.mjs`, brand PNGs via the render command in `docs/assets/brand/README.md`.
- Classifying a new file: dated + describes one change + "Files Modified" section = history; describes work not yet done = roadmap; matches current code = live only if you re-derived its facts per rule 5.

## Verification

There is no doc linter in this repo. `npm run typecheck`, `npm run lint`, `npm run test` do not touch `docs/` at all — they are not doc verification, and a green run says nothing about these files. The repeatable checks are the read-only greps and recounts below, run from the repo root before and after any work in `docs/`:

```bash
grep -rn "\.cursor/" docs *.md                      # rule 3. Expect hits only in docs/WEB-TOOLS-GUIDE.md, docs/desktop-agent.md, this contract, and root files; any new file = dangling Cursor ref. Do not grep bare "cursor" — the gap-analysis legitimately means the mouse pointer
grep -rn "@design-tokens-enforcement" docs *.md     # rule 3. Expect hits only in AGENTS.md and this contract (both name the ban); any other file = violation
grep -cE "^\s*name: '[a-z_]+'" src/main/services/pi/toolbox.ts   # rule 5: must equal any documented tool count (32)
npx vitest run src/main/services/pi/toolbox.test.ts               # the frozen-name list is the real gate
grep -rn "DANGER_POLICY\|inferStatusFromTool\|desktop-subgraph" src/ docs/ *.md   # deleted at the Pi cutover; any hit is a stale citation
```

Then, per doc: confirm the rule 1 freshness label exists, every cited `path` resolves, every cited symbol exists, and no doc line cites a source `:line` (rule 2 — `path:line` into `docs/*.md` files is allowed, into `src/` is not).

- The counting greps above stay valid with the new subfolders: `grep -r` over `docs` now also walks `docs/diagrams/` and `docs/assets/`, but neither adds a `.cursor/` or `@design-tokens-enforcement` hit, so the "expect hits only in …" note is unchanged; the tool-count recount reads `src/main/services/pi/toolbox.ts` by explicit path and never touches `docs/`. The deleted-symbol grep is the one that must return **no hits in `src/`** — hits in `docs/` and `*.md` are only acceptable where a doc names the deletion explicitly.
- Diagram freshness: `docs/diagrams/*.mmd` are the source of truth and are re-renderable — run the mermaid-cli command recorded in `docs/diagrams/README.md` (do not duplicate the full invocation here) and treat any `.svg` that no longer matches its `.mmd` as stale. `desktop-hitl.mmd` was redrawn around the Pi agent (one `Agent` loop, the `AgentEvent` bridge, the `details.verifies` opt-in and the turn-abort path) and its `.svg` re-rendered from that source; both the filename and any remaining HITL framing are historical.
