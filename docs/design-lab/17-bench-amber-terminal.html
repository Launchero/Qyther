17 · Bench Amber — the CRT financial-terminal readout

Provenance — no terminal vendor publishes a colour spec: Bloomberg's font and palette are proprietary and unspecified, and the #FF9E1B terminal yellow that circulates has no source and is dropped here. The citable lineage is the hardware — P3 amber phosphor peaks near 595–602 nm and virtual amber is RGB 255,191,0 = #FFBF00 — plus two teardown repos: wadetandy/vim-bloomberg (amber #E0C010, green #A8FF60, red #FF6C60, cyan #0B85DF, black ground) and jx22/berg. Values quoted above are VERBATIM from those two repos; the day-mode amber-to-ink darkening (--info #6cc4f0/#0a5ba0, --success #2f6b12, --destructive #a02015, --muted-foreground #5a5a46, the 1.16/3.09 --border/--input split) is DERIVED so each clears 4.5:1 / the 3:1 control floor. The day half is not decoration — MIL-STD-1472H §5.18.2.2.1 specifies dark characters on a light background for day use, §5.2.2.7 asks 6:1 min / 10:1 preferred; a saturated-on-near-black palette is indefensible as the default in a bright room, because reflected ambient adds to black and white alike and the dark ground collapses first. Sunlight-readability thresholds (contrast >5:1 needs 1,000–1,500 nits; above ~500 nits reflected ambient readability is unsatisfactory even at 1,200–1,500 nits) put a 300–400-nit laptop panel well outside that envelope.

Type plan — values in JetBrains Mono (OFL, already this app's mono), with B612 Mono (OFL, aviation-tuned) as the alternative; condensed field labels in Chivo / Saira (OFL). Never Major Mono Display on data — its 0 / 8 / O collision is exactly the failure mode of a latency or cost column. Machine without them falls back to ui-monospace / Segoe UI. Scale 12/13/14/16/24/40. The one non-negotiable is font-variant-numeric: tabular-nums lining-nums on every numeral — this mock introduces the repo's first usage (today `src/renderer/` has zero occurrences of tabular, font-feature-settings or font-variant-numeric).

Geometry — row heights from IBM's published data-table spec (24/32/40/48/64 px, 16 px column padding, 20 px header — the only published dense-table numbers available); 80×25 character-cell rhythm suggested by a repeating-linear-gradient baseline; column rules via border-inline-start; radius 0px everywhere; the only "shadow" is phosphor bloom, text-shadow: 0 0 6px at ~45% alpha, applied to the readout line only and none in day mode. What makes the dense table authoritative is alignment, not colour: numerals right, labels left, a fixed --tab-w gutter for sign/units so a delta never jitters, a row rule instead of zebra (zebra competes with alarm colour), and never rounding the last significant digit — precision is the aesthetic.

  • Move 1 · typography.cssAdd the repo's first --numfmt: tabular-nums lining-nums token and apply it to the --font-mono stack; carry B612 Mono as an alt face and Chivo/Saira on labels. Re-skin only the existing mono path.
  • Move 2 · colors.css + theme.cssNew amber ramps + readout/data/field/pos/neg roles in tokens/colors.css; every new role needs a .dark half in semantic/theme.css to pass node tmp/contrast-full.mjs --strict — bench = amber-on-black, day = ink-on-paper with amber as chip fill.
  • Move 3 · radius/spacing/shadow + markupradius.css to 0; spacing.css gains the IBM row rungs and the --tab-w gutter; shadow.css the bloom. components/ask-mode/GenerativeUI/DataTable.tsx and Transparency/TaskMetrics.tsx need text-align, the fixed gutter, and the .cell--field chip markup.

Cost — LOW. A re-skin of the existing --font-mono path plus new tokens/colors.css ramps; but every new role needs a .dark half in semantic/theme.css to pass node tmp/contrast-full.mjs --strict, plus the repo's first font-variant-numeric token.

Biggest risk — amber on pure black at 13px is the worst halation case (bloom smears the digits), and the mode choice must be made explicitly by the user, not by prefers-color-scheme: the app is dark-first and this direction says dark is the wrong default in daylight.
