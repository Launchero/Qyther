10 · Carbon Layers — an enterprise surface model, at 14px

Provenance — IBM Carbon Design System, Apache-2.0, read from the compiled sheet of @carbon/styles@1.117.0: 628 --cds-* custom properties, 134 of them paint roles. The greys above are that file verbatim — background #ffffff/#161616, the layer planes (layer-01/02/03 = #f4f4f4 → #e0e0e0 → #c6c6c6 in the white theme, #262626 → #393939 → #525252 in g100), field-01, border-strong-01 #8d8d8d, overlay rgba(0,0,0,.6) and icon-interactive #0f62fe; g100 lifts the interactive blue to #78a9ff, so that is the dark --primary. Carbon's support-01/02/03 hexes were NOT verified this session: the red/green/amber triad here is an APPROXIMATION of them, chosen to clear 4.5:1 on the layer each one sits on, not a quoted token.

Type plan — 'IBM Plex Sans' and 'IBM Plex Mono' for paths, both SIL OFL 1.1 and therefore vendorable; named here as a local-first stack, nothing is fetched. 14px is native rather than tolerated — --cds-body-01-font-size: .875rem, which is exactly this app's primary UI size, with label-01 at .75rem as the hard floor. The transferable idea is Carbon's ADDITIVE type law: Xn = Xn-1 + (INT((n-2)/4) + 1) * 2 → 12, 14, 16, 18, 20, 24, 28, 32, 36, 42, 48… A multiplicative 1.25 ratio skips the rungs a dense UI actually needs; the six sizes tokens/typography.css already ships (12/14/16/18/20/24) are literally the first six rungs of this scale, unchanged.

Geometry — corners go to zero: --r, --r-md, --r-sm, --r-xs all resolve to 0px, and the progress bar, the toggle, the spinner and nothing else stay round. Elevation is a step in the ramp plus a per-layer border, never a drop shadow, so --elev/--elev-sm collapse to a 1px ring in layer-03. --input is field-01: a FILL with a border-strong underline, so the search field and the command bar are drawn filled, not outlined — and because field-01 and layer-01 are the same grey in the white theme, the field reads by its underline alone. Density is a real axis: --cds-layout-density-padding-inline-condensed .5rem vs normal 1rem maps one-to-one onto this app's existing [data-window-mode="compact"] token switch, which is why the last rule re-points --pad rather than inventing a control; these mocks render the normal rung. Selection stays on --primary (our brief's contract) instead of Carbon's layer-02 + inset bar. Exactly one soft shadow survives — --palette-float, applied only to the palette sitting on the desktop plate, so the always-on-top window still detaches; it is not a Carbon token and is labelled as such. The plate itself is Carbon's scrim (overlay), which is why the light column's mat is dark.

The adoption trap — Carbon's layers only work because every subtree redeclares its --cds-* values under a layer wrapper (the SCSS @layer mixin). Copying the flat variable list silently breaks the layer maths: a popover would paint with the page's border colour. The .gu { --muted: var(--layer-02) } line above is that redeclaration in miniature — without it the table header inside a --popover card is lighter than its own container, which is the exact bug the mixin exists to prevent. That is the difference between a migration and a paste.

Cost: token-only for colour, radius and type — but the layer-scoped redeclaration is a structural rule the token layer has to encode, not just a value swap. Biggest risk: Carbon reads as an operations dashboard, and 628 roles against our 12-slot semantic layer means a mapping shim that has to be maintained by hand.

  • Move 1semantic/theme.css re-expresses the five-step ramp as --background / --layer-01 / --layer-02 / --layer-03 and adds a per-layer border token (--border-strong), so every surface role is derived from the ramp instead of hand-picked — the pattern already visible at the top of this file.
  • Move 2tokens/radius.css to zero, and every pristine ui/ primitive follows; tokens/shadow.css goes from drop shadows to 1px rings, keeping one hand-written shadow for the always-on-top palette.
  • Move 3tokens/typography.css takes Plex (OFL) plus the additive scale; tokens/spacing.css gains the condensed/normal density pair and drives it from the existing [data-window-mode="compact"] switch instead of adding a second density mechanism.
