26 · Frutiger Aero — technology photographed in a garden, four layers deep

Provenance — the definition is Wikipedia's: a mid-2000s-to-early-2010s aesthetic named in 2017, after Adrian Frutiger and Windows Aero, built from skeuomorphic elements, glossy textures, lens flares, bright blues and greens, Aqua gradients and Frutiger / Helvetica Neue type on Vista, Windows 7 and early-iOS surfaces; the Aesthetics Wiki adds the bubble UI and the optimistic "technology in harmony with nature" frame. The recipe is not folklore — Visnalize/MakeAero (MIT) is a shipped generator that produces "authentic Frutiger Aero styles" from an OKLCH base using gradients plus box-shadows, which is exactly the shape a token file wants. Anchors are the published hexes, converted here: #0a5c9e → oklch(46.72% .1279 250.15), #6fc3ff → oklch(78.77% .1187 241.48), #0d7ea8 → oklch(55.7% .1097 231.28), #7ac943 → oklch(75.8% .1844 134.91), #ffd45e → oklch(88.53% .1427 89.07), ink #062740 → oklch(26.4% .0598 245.86). Everything else is DERIVED by moving lightness only — the aqua body holds C .115 / H 245 across all three stops (L 66 → 52 → 40 for chrome, 28 → 22 → 17 under text, 96 → 90 → 84 for the pale plate) — and the night half is the same stack with lightness moved down (26 → 19 → 13 field, 58 → 46 → 34 chrome, 76 → 64 → 52 under ink). Licence: MIT (MakeAero), n/a for the technique.

The Electron caveat, which is the whole decision — backdrop-filter composites against the page's own backing store. It never samples the desktop, and Qyther's window is transparent: true with nothing painted behind the DOM, so a glass palette in the shipped app would blur nothing (this is the same wall Fluent/Mica hit in mock 09 — Chromium cannot read behind the window). Gloss is therefore only legal here if the sky exists inside the page. It does: --field + --clouds + --flare are in-page layers, and --blur sits on chrome over them, where it genuinely saturates and softens that field. A real Mica/Acrylic look still needs win.setBackgroundMaterial() in main; this mock deliberately does not pretend CSS can do it.

Type plan — "Frutiger" in the name is a naming convention, not a licence: Frutiger and Helvetica Neue are proprietary and unshippable. The honest substitutes are Rubik (SIL OFL), Open Sans (SIL OFL) or Inter (SIL OFL); this file cannot embed a font, so the stack is Rubik, Open Sans, Segoe UI Variable Text, Segoe UI, system-ui and on a machine with none of them installed you are reading Segoe UI, which is the honest render. Nothing is fetched: the sandboxed renderer has no guaranteed network and a CSP, so any face must be self-hosted through the Vite asset pipeline (public/ or an @font-face with a bundled .woff2, not a CDN link). Scale: UI rows 13/17, labels 12, headline 24/32 with the period's slight positive tracking (--ls-display .015em) and a subtle text shadow on the display line only. Rubik's own metrics are unverified here — no copy of it was fetched this session.

Geometry — the 4pt grid is untouched (800×72 header, 40px row, 32px target); the corners rise, because 12–20px radii are period-correct for once: --r 16 / --r-md 12 / --r-sm 10 / --r-xl 20 / --r-pill. The depth recipe is the four layers, in this order and never fewer: (1) --*-body aqua gradient, lightness-only; (2) --spec specular cap over the top half (`.55` bubble white — MakeAero's value) and --spec-ink (`.14`) where text sits on it; (3) --gloss = inset 0 1px 0 oklch(100% 0 0/.75) rim + inset 0 -1px 1px oklch(0% 0 0/.25) ground + 0 6px 16px -6px oklch(0% 0 0/.4) cast; (4) --blur = blur(12px) saturate(160%) on the water-line footer. Any one of the four alone reads as a flat gradient. Contrast numbers in this file were computed in this session from the OKLCH numbers (L→Y via the cube-root path, alpha composited in gamma-encoded space) — not run through tmp/contrast-full.mjs. Worst cases: white-on-aqua selected row 4.75:1 (with the cap), its `` 4.71:1, placeholder over the 93%-alpha card glass on the deepest water stop 5.46:1, footer muted text over glass on the water stop 4.66:1, night foreground over the moon flare 8.15:1, night muted-foreground over the same 4.90:1. --sun (1.87:1) and --grass (1.55:1) cannot carry 13px labels, so they are fills and rules only; the status text roles are the same hue and chroma with lightness pulled down (--success 5.44:1, --info 6.22:1, --warning 7.08:1, --destructive 5.22:1 on the plate). --border stays decorative (1.95:1) and --input stays a real control boundary (4.00:1).

  • Move 1 — colour rolesAdd the aqua ramps as primitives in src/renderer/styles/tokens/colors.css (lightness-only steps, printed above) and the semantic pairs in src/renderer/styles/semantic/theme.css: --primary/--primary-foreground swap to the deep-aqua body with white ink, plus new --sky-hi/--sky-mid/--water/--grass/--sun and the four layer tokens. Both halves of every new token or the dark half silently inherits light values.
  • Move 2 — radius, shadow, motiontokens/radius.css: the --radius base moves 8 → 16 and the scale to 12/20 — one file, and the pristine components/ui/ primitives and every rounded-* utility in the app follow with no component edit. tokens/shadow.css: --gloss/--gloss-lg/--gloss-inset become the elevation language; the specular cap cannot be a shadow, so it has to be a background layer, which is why Move 3 is markup. tokens/motion.css: aeroDrift + its --animate-* shorthand and the globals.css reduced-motion line.
  • Move 3 — the scene is markupsrc/renderer/components/CommandPalette.tsx needs a real first child (a .sky layer, or the card's own ::before) because App.tsx's old fixed inset-0 bg-transparent div was deleted — there is currently nothing behind the DOM for the glass to sit on. Then CommandPaletteHeader.tsx/CommandPaletteFooter.tsx take the aqua body + cap, ModeTabs.tsx the glossy pill, ResultItem.tsx the 55% cap on the selected row. Keep --radius honest: ResultsList's rows must stay on the opaque plate, or the field is under the text.

Cost — tokens for colour, radius and shadow (three files, and radius.css drags the pristine ui/ primitives with it), plus a real in-page background layer: that is markup in src/renderer/components/CommandPalette.tsx, not a variable, and the main-process height tween (windowManager.animateWindowHeight, one setBounds per reported frame) pays a full repaint of the gradient field, the cloud plates, the flare and a 12px backdrop-blur every frame of a mode change. The cap layer is free (one extra background stop); the blur is not — budget it on chrome only, never on a scrolling list.

Biggest risk — gloss is a contrast tax. The field behind a 13px row is uncontrolled by definition: it is a scene, it is animated, and its brightest pixel is a lens flare. This is the same failure mode as the mesh/glass direction (mock 07), only prettier, and the numbers above are the ones that had to be engineered back — a `.55` specular cap over a `L 66%` body measured 1.95:1 against white text, which is why text-bearing aqua is a different ramp (L 28→17) with a `.14` cap. The honest recommendation is chrome-only gloss with an opaque result plate: header, tabs, footer, buttons and the selected row get all four layers; the results list, the transcript and every table get --card and no field behind them. A translucent row would hand its contrast to a cloud.
