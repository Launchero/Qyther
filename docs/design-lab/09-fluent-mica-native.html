09 · Native Material — Fluent 2 and what Mica actually costs

Provenance — Microsoft Fluent 2 / WinUI 3 material language (Mica, Acrylic, the layer stack, the Reveal focus visual, the Windows type ramp). Colour truth is the WinUI / Windows Terminal Campbell scheme, MIT-licensed and quoted verbatim: background #0C0C0C, foreground #CCCCCC, black #0C0C0C, red #C50F1F, green #13A10E, yellow #C19C00, blue #0037DA, cyan #3A96DD, purple #881798, white #CCCCCC; brights #767676 #E74856 #16C60C #F9F1A5 #3B78FF #61D6D6 #B4009E #F2F2F2. The dark half is taken from that set. Segoe UI Variable is licensed by Microsoft and is not redistributable — it is referenced by family name only, which costs nothing in Electron because Chromium resolves installed local fonts. Not fetched this session, so labelled as approximations wherever used: the exact LayerFillColorDefault / SolidBackgroundFillColorBase alpha values (hence the whole light plate), the FocusVisualPrimaryThickness / FocusVisualSecondaryThickness pixel recipe, and the 4px grid step table.

Material model — the content of this option, not decoration. Mica is an OPAQUE wallpaper-tinted base for long-lived windows; content sits on a layer, a low-opacity solid, above it (.layer in this file, with the plate behind it a static gradient). Acrylic is the translucent blur + exclusion-blend + tint + noise material, and Microsoft's own guidance reserves it for transient surfaces with an explicit warning not to put desktop acrylic on large background surfaces (.acrylic wraps the tooltip and the MCP modal only). Both materials fall back to a solid colour when the window is INACTIVE, when transparency effects are off, on battery saver, or on low-end hardware — and an Alt+Space palette is inactive for most of its life. So the flat form must be the legible one. The fallback is the design, not the exception. Surface 2 is rendered in it deliberately: same tokens, tint and highlight swapped out, nothing else changes.

How to get it in Electron — win.setBackgroundMaterial('mica' | 'acrylic' | 'tabbed' | 'none' | 'auto'), @platform win32 in the shipped typings, and the same value as the constructor option backgroundMaterial (which src/main/windows.ts already sets to 'none'). CSS backdrop-filter cannot sample the desktop behind the window (electron/electron#30412; the Mica feature requests #38532; vibrancy conflicts #19765), so a mock that fakes Mica with backdrop-filter is demonstrating something the shipped app cannot do. There is no backdrop-filter anywhere in this file: the desktop tint is a static gradient plate and the acrylic surfaces render their solid fallback. Pointer-following Reveal borders also need JS hit-testing and are out of scope for a static mock — only the two-ring focus form of Reveal is shown.

Type plan — Segoe UI Variable, by family name only: a variable font with a wght axis and automatic opsz in HTML, present on Windows 11 and silently falling back to Segoe UI on Windows 10; the metric-compatible open-source stand-in is Selawik, second in the stack. Windows' own ramp, declared as rungs: Caption 12/16, Body 14/20, 18/24, 20/28, 28/36, 40/52, 68/92. Microsoft's stated floor is "14px Semibold, 12px Regular — text smaller than these sizes and weights are illegible in some languages"; they also prefer Semibold over Bold and exclude italic. This app's 12px label floor and 14px primary UI size already sit exactly on that guidance (tokens/typography.css states 12px as the accessibility floor and keeps --text-2xs / --text-xs-custom / --text-11px as 12px aliases). What does have to move: the control still paints 11px text in three places (.chip, .met span, and the metrics caveat in each theme) — those come up onto Caption 12/16; font-weight: 700 is painted in three rules (globals.css .streaming-cursor, .best-badge, .chart-value-number) and becomes Semibold; and three font-style: italic sites exist (.model-name plus two rules in ask-mode-perplexity.css) and are deleted, because the ramp has no italic.

Geometry — 40px minimum touch targets on standalone controls (--target-touch; the README's 32px --target-min is kept for in-header icon buttons so the fixed geometry still diffs), control radius 4px, card/palette radius 8px with the nested content radius stepping down by the 4px Mica rim, a 1px white-at-~10% top-edge highlight over tinted surfaces (--edge-highlight) instead of a tinted drop shadow, the WinUI 3px info/error bar on the alert card's leading edge, and the Reveal two-ring focus: Windows draws it as an outer 2px border plus an inner 1px border (FrameworkElement.FocusVisualPrimaryThickness / FocusVisualSecondaryThickness), expressed here as outline: 2px solid + outline-offset: 1px + an inner inset ring, and kept visible on the third results row permanently. Spacing runs on a 4px grid — the exact step table and the exact ring pixel values are the approximations named above.

Motion — Windows' own duration bands are short, so only 100 / 150 / 250ms are declared. No invented curve: the easing is the app's existing cubic-bezier(0.22, 1, 0.36, 1) and that curve is ours, not Microsoft's.

  • Move 1 — typography src/renderer/styles/tokens/typography.css → replace --font-sans with the Segoe UI Variable stack (Display rungs, Text for body, Selawik as the stand-in), restate the six-size scale as the Windows ramp 12/16 · 14/20 · 18/24 · 20/28 · 28/36 · 40/52, cap weights at Regular/Semibold, delete italic usage. No file ships.
  • Move 2 — radius src/renderer/styles/tokens/radius.css → controls to 4px and the card/palette to 8px; the 6px --radius-md rung collapses onto 4px, since Fluent has one control radius. Tailwind maps the --radius-* namespace onto every rounded-* utility, so this moves the pristine components/ui/ primitives too, with no component edit.
  • Move 3 — elevation src/renderer/styles/tokens/shadow.css → drop the OKLCH tinted drop shadows as the primary elevation signal in favour of the 1px white top-edge highlight plus a 1px outer stroke; keep one small shadow for the transient acrylic surfaces only. --ring-color becomes the two-ring pair (outer 2px foreground, inner 1px surface).

The one main-process change — this option is not CSS-only. src/main/windows.ts currently constructs the palette with transparent: true, hasShadow: false and backgroundMaterial: 'none'; the direction needs win.setBackgroundMaterial('mica') (or the constructor option set to 'mica') in createMainWindow, which is a real code change, carries a Windows 11 22H2 floor, has to be branched through isWindows() and a version check with 'none' as the fallback, and must be re-tested against the transparent: true + roundedCorners: true pair the palette geometry depends on. The renderer cannot see which material it is being given, so the CSS must be correct on its own.

Cost: colour, type and radius are token-only — three files, no component edits, and the app's 12/14px floor already matches the guidance. The material itself is one main-process window flag plus a tested fallback path (inactive window, transparency off, battery saver, sub-22H2), and that path is where the real work sits.

Biggest risk: the material disappears on settings the app does not control — an inactive window, battery saver, or transparency effects off — so the design is only correct in its flat form, and a palette that is invisible-when-inactive is a palette that is invisible most of the time. The tint is also the only elevation signal left once the shadow goes, which means a theme that reads as flat is one stroke value away from reading as broken.
