03 · Ink Hairline — the new-OS craft look

Provenance — this is an aesthetic read off live marketing CSS (Linear, Attio, Framer and Raycast public surfaces, inspected in a browser 2026-10), not a published token package. No design system was vendored, no spec was released, nothing here is MIT-licensed material. Every value in the two token blocks above is derived: the hexes were lifted by sampling those pages, then re-checked against WCAG and, where a sampled value failed, replaced with the nearest value that passes (the accent-as-text #8b7bff exists because the marketing default, an indigo near #6366f1, measures ~3.4:1 on #0b0c0f and is therefore illegal as text — the fill keeps #5b5bd6 with white type at 5.37:1, and the lifted violet is used wherever the accent is a glyph, a caret or a link).

THE FINGERPRINT — hairlines are inset box-shadows, never borders. Separation comes from a 1px hairline at 7–9% white (dark) / 8% black (light) plus a roughly 2% luminance step between plate and raised surface; grey borders are absent and there is no blurred shadow anywhere in the file — --shadow-command-palette, --shadow-popover, --shadow-dialog and --shadow-key are each re-declared as a 1px hairline ring (a 0 0 0 1px spread for a floating surface, an inset 0 0 0 1px for a control), so the four shadow slots keep their names and lose their blur. This is an implementation requirement, not a stylistic flourish: this app's user runs at device-pixel-ratio 1.25, where a 1px border painted in a low-alpha colour resolves to a sub-pixel band that Chromium rasterises to nothing — the divider vanishes and the card reads as a flat slab. Every hairline in this file is therefore either an inset 0 0 0 1px ring (--edge-inset, --edge-inset-strong), an inset 0 -1px 0 divider (--edge-divider), or a 0 0 0 1px spread for the edge of a floating surface (--edge-spread). Box-shadow bands are snapped to whole device pixels by the compositor; sub-pixel borders are not. One honest cost of the grammar: --input here is the same 16% hairline, which measures about 1.6:1 against the plate, so this direction gives up the 3:1 non-text contrast floor for control boundaries that semantic/theme.css holds deliberately (--border decorative, floor 1.4; --input interactive, floor 3.0 per WCAG 1.4.11). The mock keeps the two roles as separate tokens so the tradeoff stays visible instead of being merged away.

One translucency layer, and only one. --popover is the sole translucent surface in the system — #0b0c0fcc over backdrop-filter: blur(20px) saturate(160%), with the opaque --popover-solid declared first at every use so a compositor that cannot blur (or a Windows machine with transparency effects off) still paints a legible tooltip. Cards, rows, dialogs and the command palette are all fully opaque; anything else translucent would break the always-on-top palette's legibility over arbitrary desktop wallpaper.

Type plan — Inter and Inter Display (SIL Open Font License 1.1) for UI and display, JetBrains Mono (SIL OFL) for every file path, key cap, tool name and metric figure — the Inter-plus-mono pairing. Attio's own move is an Inter UI against a serif heading; that is honestly available with Newsreader (SIL OFL), so this mock uses Newsreader for exactly one thing: the assistant's generative-UI answer heading (.genui-head h4, i.e. the DataTable title). There is no separate "answer heading" node in the transcript, so the card title is where a serif accent can legally land. Fallback note, and it is a real one: no webfont is loaded anywhere in this folder (self-contained mocks, no CDN), so this page renders in "Segoe UI Variable Text" / Georgia / Cascadia Mono on Windows and shows the direction's metrics, not its letterforms — adopting it means self-hosting the three OFL families into src/renderer/ and adding them to the CSP, which is a separate decision from adopting the palette. Scale: 11 / 12 / 13 / 15 / 22 / 34 px, leading 1.25 for labels and 1.45 for UI prose. The uppercase tracked label — 600 weight, letter-spacing:.09em — is the look, and the look wants 11px; --text-2xs: 11px is declared and then deliberately never consumed, because this app's own floor is 12px (src/renderer/styles/tokens/typography.css: "never add a size below 12px"). Every label in this mock is therefore 12px at .09em. That is the tradeoff, stated plainly: the direction is slightly softer and the tracked labels sit a hair wider than a real Linear or Attio screen, and the alternative — a 11px label — is an accessibility regression this repo has a token file guarding against.

Geometry — 4px base grid, radius 6px controls / 10px cards, palette still 800px (--container-command-palette) under a 72px header. Rows are the collision: this direction reads at 28–32px, and the app's contract is --target-row: 40px (tokens/spacing.css, enforced by the palette's own row markup). The mock is pinned to 32px — the tightest value that still clears WCAG 2.5.8 Target Size (Minimum)'s 24px — because 28px would be a knowingly-illegal screenshot. Anything under 40px is a real regression risk for a launcher driven with a mouse on a 1.25-scaled display, so this is the one dimension where the direction cannot be adopted without an accessibility argument, and the argument belongs to src/renderer/components/ask-mode/AGENTS.md and the audit, not to a mock.

Motion — 120ms enter / 90ms exit on cubic-bezier(0.22, 1, 0.36, 1), the curve this app already owns as --easing-smooth in tokens/motion.css, so adopting it costs nothing. The signature is the streaming caret: a 1px accent-coloured bar that is solid while tokens are arriving and only blinks when the stream goes idle — shown beside the transcript's existing ▊ glyph in surface 3 as the two caret states (.caret-bar solid, .caret-bar--idle blinking); a caret that blinks mid-token is the tell of a fake stream. Skeleton sweep and panel entry are the only other movement, and the whole file collapses under prefers-reduced-motion: reduce.

  • Move 1 · hairline as an inset ring
    Retire the grey border language in src/renderer/styles/tokens/shadow.css by adding --edge-inset / --edge-inset-strong / --edge-divider / --edge-spread and re-declaring --shadow-command-palette, --shadow-popover, --shadow-dialog, --shadow-tooltip, --shadow-toast and --shadow-shortcut-key as a 1px ring — spread outside for a floating surface, inset for a control — so every shadow slot keeps its name and loses its blur; then flip --border in src/renderer/styles/semantic/theme.css to the alpha hairline. Because --border is consumed by utilities, this is token-only for the dividers — but each border: 1px solid in a pristine primitive must become shadow-[var(--edge-inset)], and the dpr-1.25 sub-pixel-erasure is the reason the change is mandatory rather than cosmetic.
  • Move 2 · delete the surface lightness ramp
    In src/renderer/styles/semantic/theme.css collapse --card/--popover/--muted/--secondary/--accent from five ramp rungs to two plates plus hover (#0b0c0f → #111318 → #171a21 in dark; #fbfbfc → #ffffff → #eef0f4 in light), and drop the corresponding mist/gray ramp rungs from src/renderer/styles/tokens/colors.css. Separation is then carried by the hairline, not by lightness — which also means --popover loses its ramp position and gains the single translucency layer instead. In the same pass, src/renderer/styles/tokens/radius.css moves the base from 8px to 6px controls / 10px cards, which the --radius-* namespace pushes through the pristine ui/ primitives with no component edit.
  • Move 3 · label typography and density
    src/renderer/styles/tokens/typography.css: --tracking-label 0.06em → .09em, labels pinned at the 12px floor (never the direction's 11px), --font-display added for the 22/34px rungs, --font-serif (Newsreader, OFL) added for the one answer heading, and --font-mono extended to cover key caps and metric figures. src/renderer/styles/tokens/spacing.css: --target-row 40px → 32px and the rhythm vocabulary tightening to match — the rung that needs the accessibility argument in Move 1's own sentence.

Cost: roughly 90% token-only — the palette, the rings, the radius scale, the ramp collapse and the tracking all land in tokens/*.css and semantic/theme.css, and the --radius-*/--border namespaces carry the pristine components/ui/ primitives for free. The remaining 10% is markup: the uppercase tracked section labels must be applied in src/renderer/components/ResultsList.tsx and in the pristine ui/ tabs primitive (components/ui/tabs.tsx, where a text-transform/letter-spacing change is an upstream fork that makes shadcn diff expensive forever), and --edge-inset replaces a border utility wherever one is written as a class rather than a variable. The self-hosting of three OFL families is extra, and separable.

Biggest risk: a hairline-only system has no elevation signal left for a window that floats always-on-top over arbitrary user wallpaper — today --shadow-command-palette is the one thing that says "this is above your desktop", and with the four shadow tokens carrying a 1px ring instead of a blur, the palette survives only on the --desktop-plate contrast and the 0 0 0 1px spread edge, both of which are outside this app's control the moment the user's wallpaper is a mid-grey. The second, and the one that will bite first in a screenshot review: at dpr 1.25 a naive 1px alpha border disappears, so any implementation that translates this direction back into border utilities — which is exactly what every shadcn primitive writes — ships a UI with no dividers at all and looks broken rather than minimal.
