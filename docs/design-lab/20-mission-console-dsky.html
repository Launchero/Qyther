20 · Mission Console — the Apollo Guidance Computer's DSKY as a command grammar

Why this layout grammar — the DSKY is not a retro skin, it is the best model on the shelf for what Qyther's agent surface actually is: a command interface in which every state is legible at a glance. Four devices carry that. A value bay is a fixed label line above a large numeral inside a bordered cell, with the unit suffix set at a smaller optical size and never inline prose. VERB / NOUN is a two-field command entry — an honest model of "tool + argument", and a better one than a free-text box that hides what the operator actually asked for. PRO / KEY REL / ERR is a lamp row that reads as an annunciator panel, not as a stack of toasts. And the law underneath all three: nominal values are always shown, including zeroes — an empty cell is a fault, not a layout nicety. That last rule is why this mock paints its off lamps rather than omitting them.

Provenance — each digit on the DSKY was displayed by a green electroluminescent seven-segment display, specified as 530 nm (Wikipedia, Apollo Guidance Computer; the artefact is in the Smithsonian Air & Space collection). NASA-STD-3001 Vol 2 requires displays be judged on "brightness, luminance contrast, and color gamut, taking into account the ambient illumination, glare, reflections" — which is why this direction ships a day-lit half as a first-class theme, not a bonus. DSEG is SIL OFL 1.1: the author's page states the licence changed to OFL 1.1 from v0.40, so seven-segment is legally shippable. B612 Mono is OFL too and was cockpit-tested by its author for aerospace panels. Palette is DERIVED from the 530 nm figure alone — ground #020604, digit green #3BF0A2 (530 nm reads green-cyan, not pure green), label green #8FD9C0, lamp-off #1A2420, caution amber #E4A72E, verdict red #D8453A. UNVERIFIED: the DSKY's actual lamp colours, every SpaceX/Starlink terminal value, and any ESA console spec — nothing public exists for any of them, so none is used as an authority here; the amber/red pair is a convention, not a measurement.

Type plan — three rungs, and the split is the whole discipline. DSEG7 Classic (OFL 1.1) for numerals only, in value bays, readout cells and the table's ms column. B612 Mono (OFL) for every label, kicker and unit suffix. The shipped system sans (--ff) for prose: answer text, paths, tooltips, settings copy. Seven-segment is illegible as prose and is never used as such — a direction that sets an answer in DSEG has stopped being a console. Nothing loads over the network, so without the woff2 files installed everything degrades to JetBrains Mono / Cascadia Mono at the same size and weight: numerals stay monospaced and the bay grid is untouched, only the segment look is lost.

Geometry — the fixed frame (800 px palette, 72 px header, 40 px row, 32 px control target) with radius collapsed to 0, so separation is a 1 px rule plus a lightness step and depth never comes from a corner. Frame corners are cut with clip-path at --cut 14 px. --border stays decorative (#1a2420 dark, 1.6:1) and --input stays the control boundary (#3d5549 light, 3.73:1). Shadows are absent except a 1 px ring; elevation is the cell fill --cell against the plate. Two overlays sit above the whole page: a 3 px repeating-linear-gradient scan veil at 4% alpha (removed under prefers-reduced-motion) and a permanently visible "off segments" ghost at 8% on the seven-segment cells at 20px and above only.

Contrast, measured — dark, on --card: digit green 13.26:1, label green 12.02:1, muted label 6.01:1, caution amber 9.23:1, verdict red 4.52:1. Light, on --card: ink 13.9:1, muted 6.5:1, verdict 6.0:1, warning 6.69:1, success 4.93:1, info 5.10:1. Status copy in this system sits on a 12% tint of itself, so light --success and --info were darkened until they clear 4.5 on the composited plate too (4.93:1 and 5.10:1 measured there, not on bare card). Two fills are kept off the text path and said so here: #E4A72E caution amber is 1.77:1 on a light card, so in the floodlit half amber survives only as a lamp fill (darkened to #a8730c where it must carry meaning) and the readout colour becomes ink, not green. #D8453A is 4.52:1 on a dark card — over AA by 0.02, with no headroom — so 12 px error copy uses --verdict-ink at 6.18:1 while the red stays the lamp and the rule.

  • Move 1Semantic values: rewrite the :root / .dark halves in src/renderer/styles/semantic/theme.css with this palette and add the direction pair (--digit / --cell) plus the four lamp values there, each with both halves; tokens/colors.css gains the 530 nm ramp as OKLCH primitives (its mandate) and tokens/radius.css drops to 0.
  • Move 2Type: tokens/typography.css gains --font-dseg / --font-cockpit, a display rung above the six-size scale (--text-28 / -34 / -44, each with its own line-height), and keeps --text-xs 12px as the label floor — nothing may go under it. Add the real @font-face rule and place the self-hosted woff2 in public/, which Vite packages into out/renderer.
  • Move 3Markup that has no analogue today: ask-mode/Transparency/TaskMetrics.tsx becomes four .bay value bays (label line, numeral, unit suffix as a sibling, not inline prose); ask-mode/BrowserProgressPanel.tsx's status row becomes .lamp annunciators with the off state painted; the tool trace gets the VERB / NOUN row; ask-mode/ThinkingSteps.tsx's ✓/• glyphs swap for lamps; and contexts/ToastContext.tsx gains a one-slot annunciator surface so a toast writes a lamp instead of stacking.

Cost: MEDIUM-HIGH. Not the palette — the type. A genuine readout needs a real @font-face, and the CSP in src/renderer/index.html whitelists only fonts.googleapis.com / fonts.gstatic.com; a shipped Electron app cannot assume a network, so the woff2 files must be self-hosted in public/, which Vite packages into out/renderer — unlike main-process disk resources such as services/browser/skills/, which the root rail records are not packaged by default. Then a display rung above the current --text-* scale, three component markups, and the lamp/toast reconciliation. The zero-@font-face fallback is honest (B612 falls back to the mono stack) and costs the segment look, which costs the direction.

Biggest risk: seven-segment is illegible as prose, so it survives only as numerals — and a launcher whose chrome outshouts its results has inverted the hierarchy. This direction works only while the giant digits stay inside the metrics and activity bays and the result rows keep their 14 px titles. The moment a 44px readout competes with the file the user is trying to pick, the panel becomes the point and the palette stops being one. Secondary risk: the annunciator panel has exactly one slot per condition, so a burst of toasts becomes a fight over four lamps — which is a real product decision, not a CSS one.
