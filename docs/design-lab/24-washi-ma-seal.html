24 · Washi, Ma, Seal — one sheet of unbleached paper, one vermillion seal, and 40 px of nothing

Provenance — the palette is not invented. The seven names and their sRGB mappings are the 日本色名 list as published in Wikipedia's Traditional colors of Japan, which sources the table to 日本色彩学会 1985 and to the Hibi / Fukuda / Nagasaki colour-name papers: SUMI 墨 #27221F (ink), SHIRONERI 白練 #FFDDCA (unbleached paper/silk), SHU-IRO 朱色 #FF3500 (vermillion), ENJI 臙脂 #9D2933, BENIHI 紅 #F35336, KON 紺 #192236, RURI 瑠璃 #1F4788. Those seven hexes are quoted verbatim and converted to OKLCH here (the conversion is DERIVED; the hues are not). NIPPON COLORS cites the same tradition but injects its swatch hexes by script, so only its stylesheet field was readable in this session and the book values for those names are UNVERIFIED — nothing below leans on it. The card, popover, pressed-paper and bone-grey surfaces are DERIVED from SHIRONERI and SUMI by lightness only. Doctrine line, one, from Kenya Hara (White and Designing Design): emptiness is not solitude but opportunity, and it is an invitation the viewer completes — hence the 40 px band and the single object. Field is SHIRONERI, text is SUMI, and there is exactly one saturated element per column — the SHU seal; RURI/KON is the secondary ink for links, selection and the focus ring. Status green and ochre have no counterpart in the seven quoted names, so --success/--warning stay the shipped hues from tokens/colors.css, retuned for the warm field — labelled DERIVED, not traditional. Licence: colour names are uncopyrightable facts; Hara's books are cited, not quoted beyond that one line; fonts below are OFL.

Type plan — --ff-display is Zen Old Mincho then Shippori Mincho, both verified SIL OFL 1.1, with Noto Serif JP (OFL) behind them for CJK coverage. The hard rule: mincho only at the three display rungs — 24 px plate title, 20 px page title, 17 px first line of an answer — and nowhere else. A mincho hairline at 13 px is thinner than one device pixel and the stroke ends (the uroko triangles) smear into each other, and these faces' Latin is drawn as a companion to a 1000-em square rather than as a text face. So every row, path, badge, table cell and dialog line stays the existing system sans at 13 px (--t13) and every label stays mono/sans at 12. On a machine without the faces installed this renders in Yu Mincho / Hiragino Mincho ProN / Georgia — a serif still, at the same three sizes, so the structure survives the fallback; the single 印 in the seal falls back to a system CJK face, and if it tofu'd the seal still reads as a vermillion diamond. State the constraint plainly: in a Latin-only UI the vertical writing-mode: vertical-rl rail — the most recognisable Japanese print device — is unavailable, because the strings are English and the palette is a 74 DIP strip; the identity therefore has to be carried entirely by the seal, the field and the void. The one piece of infrastructure that already exists for a future CJK query is useKeyboard's event.isComposing bail (it returns before every key branch), so an 漢字 query would never be torn apart by the palette's keymap.

Geometry — strict 4pt grid; radius 0 on every corner, with --radius-xs 2 px kept in the scale and used for nothing; no shadow on the card at all (--elev, --elev-sm, --key are literally none) — surfaces are separated by a 1 px border plus whitespace, never by depth; --border stays a lighter decorative hairline than --input, which carries the 3:1 control-boundary floor. One deliberately oversized gap: a 40 px unbroken band above the input (--void), which is the ma — it carries no rule, no label and no divider. Exactly one vertical hairline exists in the layout, border-inline-start on the transcript, and the header's old .vr divider is demoted to transparent so nothing else competes with it. Labels are tracked all-small-caps Latin (font-variant-caps: all-small-caps; letter-spacing: .18em); the only interactive affordance is a 1 px RURI underline, so the ghost buttons and the export chips lost their boxes.

  • Move 1Colour: new OKLCH pairs in src/renderer/styles/tokens/colors.css plus both halves in src/renderer/styles/semantic/theme.css — SHIRONERI/SUMI swap roles as background↔foreground between :root and .dark (a sumi field with bone ink), RURI takes --primary/--ring/--info, ENJI takes --destructive, and --shu/--sumi/--shironeri/--enji/--benihi/--kon/--ruri join as named source tokens that never move between themes.
  • Move 2Shape and depth: src/renderer/styles/tokens/radius.css drops --radius-sm…4xl to 0 (keep --radius-xs 2 px at its current value — nothing consumes it), and tokens/shadow.css sets --shadow-command-palette, --shadow-popover, --shadow-dialog, --shadow-tooltip, --shadow-toast and --shadow-shortcut-key to none. This is not a component edit: Tailwind maps the --radius-* namespace onto rounded-*, so the pristine src/renderer/components/ui/ primitives move with it, and dark: utilities inside those primitives will need a look.
  • Move 3Type and rhythm: one --font-display value in src/renderer/styles/tokens/typography.css (leave --font-sans/--font-body alone — rows are not mincho) plus the three display rungs, and --void: 40px in tokens/spacing.css. Markup that has to exist: a <span class="seal"> in CommandPaletteHeader (or ChatMessageBubble's assistant label) and one empty <div class="ma"> above the command bar in ask-mode/UnifiedCommandBar; .ans::first-line and the tracked all-small-caps labels are CSS-only.

Cost: MEDIUM-LOW. Colour is a token rewrite with both theme halves (measured below), shape is two token files, type is one value plus three rungs. The three things that push it off "tokens only" are (a) radius 0 and zeroed shadows reaching the pristine ui/ primitives through the --radius-*/--shadow-* namespaces, so shadcn diff gets noisy and the primitives must not be hand-patched, (b) two new markup nodes (seal, ma), and (c) packaging: a mincho must be self-hosted through the Vite asset pipeline, never a Google Fonts <link> — a link dies offline, this renderer is sandboxed with no guaranteed CDN, and CJK webfonts run to multiple megabytes split by unicode-range, so subset to Latin plus punctuation (a few tens of KB) and let the system CJK face serve 印. Adding a font-asset copy step is an explicit request, because electron.vite.config.ts currently copies only sql-wasm.wasm and Automation.node into out/main — anything else read from disk at runtime silently disappears in a production build.

Biggest risk, bluntly: SHU #FF3500 measures 3.31:1 on the bleached card and 2.85:1 on the SHIRONERI field, so it cannot clear 4.5:1 as text — it is a fill, or the seal, and nothing else; the seal's own white glyph is 3.4:1, which is legal only because a seal is an object rather than copy. BENIHI #F35336 fails the same way at 3.13:1. Second, and worse: with no CJK, no photography, no vertical rail and no depth language, "emptiness" inside a 74 DIP launcher strip reads to Windows users as a broken layout — a palette that looks unloaded, missing its background, or clipped. This direction therefore collapses into "shadcn, beige, one red dot" unless the void, the seal and the mincho are all committed at once; any two of the three and it is just a beige theme with a decorative square.
