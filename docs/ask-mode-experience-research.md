## 0. The structural cause

v1's cause was correct and is now largely paid off: *no ask-mode control was coupled to a truth in the main process*. The IME guard, the fake history dropdown, the wall-clock confidence and token meters, the dead Pause buttons and the silent Copy are gone.

Two causes remain, and they are different in kind.

**0.1 — The renderer's display vocabulary is a hand-copied mirror of the producer's registry, and the producer changed runtime underneath it.** The Pi cutover deleted the graph, and `ThinkingSteps.tsx` kept its `LOADING_MESSAGES`, `PHASE_LABELS`, `PHASE_ORDER`, badge switch and retry path keyed to graph node names that no longer exist. The bridge does not fix this — `ask-events.ts`'s `STEP_NAME_BY_TOOL` translates **five** tool names onto five legacy strings and passes every other name through, so 39 of the 44 first-party tools display their internal snake_case identifier. `aggregateSteps` dedupes by step string, so three `search_web` calls render as one line. The sort is by `PHASE_ORDER`, in which no Pi tool appears, so ordering survives only because the sort is stable. And the retry line writes itself onto a step named `validate`, which no longer exists, so iteration counts are dropped on the floor. This is precisely the coupling the root rail already solved twice — `SUBSYSTEM_ENV_VARS` for logger names, `buildFamilyIndex` for tool labels — with a test that fails when a call site lacks a registry row. Nothing links the tool registry to the step vocabulary, so this cannot be noticed; it can only be stumbled into. **The rule that generalises: a display string is derived from the producer's registry or it is not displayed.**

**0.2 — Ask mode is one surface asked to be three products, and it is currently the weakest member of all three.** It is a launcher (Alt+Space, type-to-filter, must be faster than the thing it replaces), a grounded assistant over the user's own machine (Everything + OCR + document readers), and a control surface for a 44-tool desktop agent. v1 analysed it almost entirely as a chat window, which is the one category it is not: nobody reads a 2000-token answer in a 602px always-on-top slab. The category's actual leaders — Raycast on Windows, PowerToys Run/Command Palette/Advanced Paste, Copilot on Windows — all solved this by **tiering**: a one-off answer inline, an escalation key into a real window, and the agent in its own workspace. Qyther has no escalation path, so every answer is trapped.

## 3. The category question, settled by the reference set

Every product that has shipped this combination solved it the same way, and the pattern is consistent enough to be a rule:

| Tier | Surface | Holds | Precedent |
|---|---|---|---|
| 1 | The overlay, ~600px, one keystroke away | A question, a short answer, a result list, an action grid | Raycast Quick AI ("Same Tab — More power"), Advanced Paste's action grid, PowerToys compact box |
| 2 | **Escalation key** | The same conversation, with history and attachments, in a real resizable window with a taskbar presence | `⌘J`/`Ctrl+J` Quick AI → AI Chat ("AI Chat is a separate window") |
| 3 | Result pane | Anything substantial — document, table, chart, code, diagram — beside the thread, editable and exportable | Claude artifacts ("separate window beside the chat", version on edit, export to Word/PDF/PPT/HTML) |
| 4 | Agent workspace | A long run, watched not read, pausable and take-overable, off by default | Copilot Actions' Agent Workspace; Devin's recordings and take-over; Cursor cloud agents |

Qyther has tiers 1 and 4's tools and none of 2, 3 or 4's surfaces. That single gap bounds everything else: no amount of markdown work makes a 602px always-on-top slab a good place to read a research answer, and no amount of chat polish makes a chat transcript a good place to supervise a desktop agent.

## 4. Evidence — what the running app did

Observed in this session against `npm run dev` on this machine (dpr 1.25, dark theme, work area 3440×1440). `harness:preflight` passed with no refusal; DOM 800×602, `hidden: false`.

**4.1 — Ask mode did not start, and the card blamed the wrong thing.** Clicking the Ask tab (`click_role --role tab --name "Ask"` → `clicked: true`) rendered the not-ready card: **"Ask mode isn't connected — The model client could not be created. ### 5.5 Transcript mechanics

### 5.6 Context, cost, latency
`chat:sendStreamMessage` replays `history.messages … .slice(-10)` and `ask-turn.ts`'s `HISTORY_TURNS` is 10, so turn eleven silently forgets turns one to ten and nothing says so. `thinkingLevel: "off"` is hard-coded in both `ask-turn.ts` and `agent.ts`, and the model id comes only from `MODEL` — read at the point of use since §10b, and with no model or reasoning-effort control anywhere in the UI. Gate:** focus another app, invoke it, ask about it, see the scope chip.
31. **Dictation.** `⌃M`-equivalent, and the launcher's input field is where voice earns its keep. **Complexity M.**
32. **Index state and the no-result state, named.** The Files half must say what the indexer could not see: an online-only OneDrive placeholder is searchable **by name only** and Everything indexes its name/path/size while its contents are not on the device — so a content claim about a placeholder is a silent half-hit. Distinguish *name hit* from *content hit*, label "not downloaded", offer hydration, and give "nothing found" a cause and two exits (widen scope, search the web, index this folder) rather than a dead end. Windows Search's status strings are the model. **Complexity L. Gate:** a placeholder file returns a labelled name-hit, never a content answer.
33. **The privacy boundary at first use, in the capture path.** Consent before capture, an allow/deny list resolved *before* a file is read (enforcement at retrieval, never post-filtering the answer), a stated retention and storage ceiling, and an honest negative sentence about what the protections do not do. Redact out-of-repo paths from the accessible name of a result row and offer a "blur paths" mode for screen sharing — §4.4 is the observed defect. **Complexity M. Gate:** a screenshot of the live palette whose rows contain no absolute path outside the repo.

### P5 — The host and the measurement (M–XL; the ceiling and the instruments)

34. **Decide the geometry, explicitly.** An 800px width-locked, always-on-top, frameless overlay whose height main owns is not a reading surface and not a supervision surface. Options: a result pane that widens into a second column above ~900px (the documented preview-pane threshold), a separate conversation window (item 28), anchor the palette 15–20% down and cap it at ~60% of the viewport so the subject stays visible, or dock-and-push like the Copilot sidebar. Each collides with a real invariant — main is the sole owner of mode geometry, the mirrored height tokens were deleted for that reason, `MODE_HEIGHTS` is a measured contract — so this is a decision, not a patch. **Complexity XL. Gate:** `harness:selftest` still green plus a re-derived geometry report.
35. **Instrument, then optimise, then claim.** Emit `turn_start`, `first_token`, `first_visible_text`, chunk deltas, `turn_end`, `stop_press` on the existing `{threadId, seq}` envelope; report TTFT, ITL and time-to-first-**visible**-text as p50/p95/p99, never means, and keep the three apart — a token is not a pixel, and markdown parse plus scroll sit in series. Adopt INP p75 ≤200ms for the input bar as the one client metric with a published "good" cut, and a LoAF observer on the transcript. Only then touch the <500ms cold-start claim, which the rail correctly calls never measured. **Complexity M. Gate:** three numbers, printed from the running app, with the command that produced them.
36. **Accessibility, as a contract not a pass.** Transcript is `role="log"`, polite, `aria-relevant="additions"`, never `aria-atomic`; silence it while streaming and announce **once** at completion (per-token announcement is a shipped bug class); ≤2 live regions, established before content arrives, never carrying rich interactive content; focus stays in the combobox with `aria-activedescendant`; dialog focus-in/focus-restore; every new control keyboard-reachable; `prefers-reduced-motion` honoured for every streaming reveal; and a high-contrast pass, because Windows ships four contrast themes at ~7:1 and a token system that only has light/dark will not survive them. **Complexity L. Gate:** a whole turn driven by keyboard plus a screen-reader recording, and the first real component tests under `ask-mode/`.
37. **Measure reliance, not usage.** Regenerate rate, stop rate, copy-vs-paste rate, citation-open rate, time-to-first-visible-token, error-banner rate, abstention-vs-answered-anyway. No vendor publishes targets for these, so set a baseline and regress it; the value is the trend and the canary, not the absolute. **Complexity M. Gate:** a per-session table printed from the local database.
38. **Say it is an AI system.** EU AI Act Art. 50 has applied to providers since 2026-08-02 for systems that interact directly with people. A persistent, unambiguous label costs one string. **Complexity S. Gate:** visible in the transcript chrome.

## 7. EXCLUDE

- **Any number the system did not measure** — confidence percentages, tokens from string length, cost from a constant, "Reviewed N iterations" from a step that cannot exist, and any progress percentage for a run with no denominator. An estimate is allowed only where the word "estimated" is also on screen.
- **A determinate progress bar for an agent.** "Percent-complete assumes a known denominator, but an agent discovers its work as it goes." The step ledger's denominator is the plan; if there is no plan artifact, there is no percentage.
- **Paraphrased chain-of-thought presented as reasoning.** Show actions, evidence and assumptions.
- **Citation theatre.** A `[n]` whose target is a filename, a source list at the foot of an answer nobody opens, or markers emitted for claims the retrieval did not support. A dead marker is worse than none, and the AAAI result says a random one still raises trust — which is the argument against, not for.
- **A second skeleton/progress path for a payload that arrives atomically.** Delete `GenerativeUISkeleton`/`GenerativeUIProgress` rather than invent a sender for them.
- **Re-introducing the confirm modal** without first deciding the reversibility tier and where the paused-turn payload lives.
- **Per-app `dark:` sprinkles, a new stylesheet, IPC inside `components/ask-mode/`, raw pixel/OKLCH literals, a second owner of window height, patched `components/ui/` primitives, an `AbortController` in the renderer tree.** If an item above appears to need one, the item is specified wrong.
- **Product scope that belongs to someone else:** voice *conversation* mode (dictation is in; a spoken agent is not), image generation, shared session links, live presence, collaborative comments, mobile breakpoints, an embedded webview inside the palette, and a plugin marketplace.
- **Proactive interruption inside a launcher.** It is summoned; it should not volunteer.

### 12.1 File search, preview, and the file→answer bridge

1. **Name matching and content matching are different products** — never let one impersonate the other. **[C]** voidtools FAQ.
2. **Never put content search or a document parse in the keystroke path.** Everything's `content:text` is documented as "slow as it is not indexed"; make it an explicit second tier. **[C]** [Searching in Everything](https://www.voidtools.com/support/everything/searching/).
3. **Accept the operator grammar rather than re-inventing it** — `ext:`, `name:`, `path:`, `size:>1mb`, `date-modified:today`, `dupe:size`, `child-count:0`, `regex:`, `count:`, `sort:`, space=AND, `|`=OR, `!`=NOT, `""`=exact — and pass `-r/-i/-n/-s` through to `es.exe` instead of re-ranking its output. **[C]** [Search functions](https://www.voidtools.com/support/everything/search_functions/), [ES CLI](https://github.com/voidtools/ES).
4. **Bound the result set and say it is bound** (`-n`, `count:10`).
5. **Preview toggles on one key and must not steal the query field** (Peek: Space; Raycast: `Ctrl+Y`); **preview follows arrow-key navigation**; Enter opens, and opening is a separate verb from previewing. **[C]** [Peek](https://learn.microsoft.com/en-us/windows/powertoys/peek), [Raycast shortcuts](https://manual.raycast.com/keyboard-shortcuts).
6. **Row anatomy = identifier + locator + differentiator** (name / path / kind+size+modified) with the matched substring highlighted — this app already highlights (`ResultItem.tsx` `highlightMatches`) and `SearchResult.metadata` already carries `size`, `dateModified`, `kind`, `fileType`. The metadata exists and is partly unused. **[V repo] [C]** [NN/g SERP anatomy](https://www.nngroup.com/articles/anatomy-search-results-page/).
7. **Rank with stable buckets and a deterministic tie-break**, never by path depth — Firefox's urlbar model, and the fix Raycast had to ship ("Deep directories no longer outrank shallower or more recent files"). **[C]** [Firefox ranking](https://firefox-source-docs.mozilla.org/browser/urlbar/ranking.html).
8. **Exclusions are a ranking feature**: skip `.venv`/`.cargo`/`.git` objects, honour `.metadata_never_index`, allow volumes off. **[C]**
9. **A cloud placeholder is a name hit with no content** — label it in-row ("online-only — not downloaded") and offer hydration. ⚠️ Community-level sourcing, not a Microsoft doc. **[C]** [voidtools thread](https://www.voidtools.com/forum/viewtopic.php?t=11883).
10. **Copy name / copy path / copy as markdown link / open / reveal / open-with are distinct verbs** (Raycast ships three separate copy actions). **[C]**
11. **A zero-result state must explain and offer a start.** **[C]** [NN/g no-results](https://www.nngroup.com/articles/search-no-results-serp/).

### 12.3 Capability discovery — a "capability browser" is the wrong answer

The temptation with 44 tools is a page that lists them. The research says don't.

1. **Configure where you discover** — set an alias or hotkey by selecting the command in the search field, not in a settings window (Raycast). **[C]**
2. **Settings are searched, not scrolled** (`Ctrl+F` over extensions, commands *and* settings). **[C]**
3. **A sigil grammar beats icon tiles** — one reserved character per intent plus a single footer line naming them. **[C]**
4. **Zero-query shows recents + user-pinned + relevance and nothing else** — two rows, not five marketing cards. **[C]** PowerToys Home.
5. **A collapsed launcher must be keyboard-expandable** ("press Down Arrow or Tab to expand and browse the top-level commands"). **[C]**
6. **Tooltips carry nothing load-bearing** — they must open on keyboard focus and no task may require finding one. **[C]** NN/g.
7. **The cheat sheet must be typable**, not just menu-reachable (Figma: menu, *or type "Keyboard shortcuts"*, or `⌃⇧?`). **[C]**
8. **Prime at point of need, never wall the launch, degrade visibly on denial.** **[C]** Android runtime-permission guidance is the most mature published contract.
9. **"Works on the selection" is the disclosure** — power attaches to an object (Notion `⌘/`, Linear `Cmd+K`), never a mode to enter. **[C]**
10. **A disabled-by-default capability says so where it is enabled**, naming the settings path rather than returning nothing. **[C]**
11. Assume taught power features go unused; and note honestly that **no measured evidence exists** for suggestion-click-through or discovery→retention in launcher-class tools. **[C]** flagged by the researcher.

For this app: the welcome tiles and footer hint are the entire discovery surface today, so the fix is *typable capability*, not a tour or a browser.

### 12.4 Provider, model and cost handling

**Setup-screen contract**: base URL with `/v1` suffix behaviour stated; key masked and stored separately; model id **discovered via `/v1/models` or typed**, unknown metadata rendered as unknown; per-purpose assignment (chat / fast / embedding); context window per model; a test distinguishing **401 (bad key) / 404 (wrong base path) / empty list (no catalog)** from generic failure; live switch without restart; last test result with a timestamp. **[C]** AnythingLLM, Continue, Zed, Cherry Studio, LobeChat, OpenRouter.

Rules: retry only 429/5xx with `Retry-After`, jitter and a cap; never offer retry where waiting cannot help; fallback is a **named configured relationship** (LiteLLM fallback groups, `context_window_fallbacks`), not an ad-hoc second model; show cost at selection as a **relative multiplier** (Copilot's "premium request multiplier"), never a guessed dollar figure; on a mid-stream disconnect **keep the partial, mark it incomplete, offer continue** — Claude Code's own wording is "Connection lost mid-response. The response above may be incomplete.", and gateway guidance is blunt: "Never make displayed output disappear silently"; on context pressure, warn before degradation and offer explicit compaction (Cline's ~50% handoff / 70–80% warning figures come from **its own blog, not a benchmark**). **[C]**

### 12.5 Reading the answer

The measure correction is already in item 10: **49ch is below the floor, not above the ceiling** — Baymard's eyetracking range is 50–75ch with ~66 optimal, so the column must widen. WCAG 1.4.8 adds ≤80ch, ≥1.5× line spacing, ≥2.5× paragraph spacing, and no justification (it creates rivers). **[C]**

**57% of viewing time is above the fold and 74% within two screenfuls** — the strongest argument in this document for the result-pane/escalation tier in §3. **[C]** [NN/g](https://www.nngroup.com/articles/scrolling-and-attention/). Skeletons beat spinners on *perceived* speed in a controlled experiment, but **never fake rows beside a live token stream**. **[C]** [ACM](https://dl.acm.org/doi/10.1145/3232078.3232086). Text must stay selectable end-to-end including code fences — a real shipped competitor defect ("selection is either text or code but not both") and the precondition for select→quote, copy and print. **[C]** Prefer a print stylesheet plus copy-as-markdown over bespoke PDF. **[C]** App-level find-in-answer beats native `Ctrl+F` in a frameless overlay. Progressive disclosure ≤2 levels, with a sticky outline that shows where you are, not only where to jump. **[C]**

### 12.6 Evaluating a 44-tool desktop agent — the cheapest credible harness

The first pass had no success metric for the agent. The published bar is humbling: **OSWorld 369 tasks — human 72.36%, best agent 12.24%**; **WindowsAgentArena 154 tasks — Navi 19.5% vs human 74.5%**; **AndroidWorld 116 tasks / 20 apps — best 30.6%**; **WebArena 812 tasks — GPT-4 agent 14.41% vs human 78.24%**; **VisualWebArena 910 tasks — best 16.4% vs human 88.7%**. **[C]** Read from the papers by the delegated researcher; re-derive before publishing any of them.

Ordered proposal sized to this repo:

1. **Transcript before oracle.** Log every run as `{tool, args, result digest, family label, seq, wall time}` plus screenshot references. `pi/ask-events.ts` already sees every `AgentEvent` and `DatabaseManager.saveTrajectory` plus the three `desktop_*` tables already model it with the right indexes — **the only missing piece is the call**.
2. **~30 tasks, one file each**: prompt, target app + required initial state, oracle spec, budget (max steps, max seconds). Roughly 12 Windows UI / 4 browser / 5 document / 4 web / 3 command-or-file / 2 negative-and-injection. Add tasks only once an oracle exists — a suite without oracles is a demo.
3. **The oracle is OS or app state, never the model's claim.** Windows UI → UIA properties and filesystem facts, reachable today through `scripts/harness`'s `state` and `ax_snapshot`; browser → a local fixture server with `exact_match`/`must_include` plus a programmatic DOM/URL predicate; document → **re-parse the written file and assert structure** (the document family already re-parses, so the oracle exists); command/file → a throwaway temp dir plus a filesystem diff. Include **unachievable tasks whose correct answer is "N/A"**.
4. **Three determinism tiers.** CI-on-PR: existing stub-toolbox tests plus golden-trajectory replay against canned tool results (asserts plan and argument shape; never touches Win32). Nightly: one snapshot-restored Windows VM, k≥3. Judge: LLM-as-judge only for prose and only behind a passed programmatic check — screenshot-judging alone yields high false positives. **[C]** [An Illusion of Progress?](https://arxiv.org/html/2504.01382v4)
5. **Metrics**: pass@1 and **pass^3** (τ-bench), step ratio against one human reference trajectory per task (OSWorld-Human: the best agent used 1.4–2.7× more steps than needed while succeeding), median wall time, irreversible-action count (any `execute_command` or file write outside the sandbox), refusal rate on the negative tasks, and injection attack-success rate as a first-class number — InjecAgent measured GPT-4 at 24% base rising to 47% under enhanced attack prompts, and GUI screen-text injection exceeds 80% ASR on some commercial agents. **[C]** Report exact counts with a Wilson interval; do not compute p-values on N=30.
6. **Do not attempt**: 369-task suites, pixel diff as the primary oracle, live-web tasks, CI on a developer's desktop, or any leaderboard claim this harness did not produce.

### 12.7 Good, newly confirmed — do not regress

`document-loader.ts`'s disclosure of empty / oversize / scanned / encrypted / corrupted extraction outcomes is the honest pattern the rest of the surface should copy. `ResultItem.tsx` already highlights matched substrings and `SearchResult.metadata` already carries size, modified date, kind and fileType. `errorClassifier.ts` + `ChatErrorBanner` already offer retry/edit/new-chat gated on main's `retryable`. And the trajectory schema is correct but unused — the expensive part of §12.6 is already paid for.
