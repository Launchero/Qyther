# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

`1.0.0` is the version declared in `package.json`. It is the only release entry in this file: the repository has no git tags, no changelog history before it, and no published binaries, so the date below is the commit date of `HEAD` at the time this file was written, not a download date.

## [Unreleased]

### Added

- **Web research can now read the pages it ranks, and the search behind it is a chain instead of one scrape.** Ask mode's research path (`externalSearchNode` in `src/main/services/langgraph/research-agent.ts`) called a single tool that scraped DuckDuckGo with two fragile regexes, fell back to Tavily, and handed the model **snippets only** - so it ranked pages it had never read, and citations were the model's guess. Search and fetch now live in a new Electron-free, LangChain-free subtree, `src/main/services/web/`, whose design is reverse-engineered from the oh-my-pi coding agent: a provider chain walked in registry order with first-usable-response-wins, failures returned as model-facing notes rather than thrown, and one normalised result shape rendered as prose instead of a JSON string the caller had to re-parse. Query directives (`site:`, `-site:`, `after:`/`before:`, `filetype:`, quoted phrases) are parsed once, re-emitted in whatever dialect each engine understands, and re-applied afterwards as a lenient post-filter that *relaxes* a constraint matching nothing rather than obeying it - a model that asked for `site:` and got nothing still gets an answer. Fetching a URL tries the `<url>.md` sibling (the llms.txt convention), then markdown content negotiation, then a reader chain: a local HTML-to-markdown extractor, and only if its output fails a quality gate the remote `r.jina.ai` reader on a 10s budget. `externalSearchNode` reads the top 3 hits at 6000 characters each, through the same formatter that stamps each page's provenance, so the synthesizer prompt carries page bodies rather than blurbs - and can see whether a page was read cleanly or fell back to raw HTML.
- **Two more keyless search providers, and a measured answer to "which of these actually work".** A second round of live probing against the whole candidate space (SearXNG instances, Marginalia, Mwmbl, Right Dao, Stract, Wiby, Teclis, Alexandria, Firecrawl keyless, `s.jina.ai`, plus the keyless vertical APIs) added **SearXNG** - implemented as a **rotating pool of public instances** rather than one host, because no single one can be relied on: 2 of 20 instances served JSON from the test machine and then both went 429, and a sweep of **0 of 71** graded instances served JSON at all. The pool is ordered by observed success first, then by the `searx.space` grade, and runs under a 6s whole-pool budget with a 4s per-instance cap - the budget was cut from 12s to 6s *after measuring the failure*, because a pool that cannot reach one JSON-enabled instance was costing 11.1s of a 120s Ask turn to report the same failure twice as fast. And **Marginalia**, an independent small-web index, whose relevance is the point: a different corpus from the commercial engines rather than a second view of the same one. The chain is now five keyless rungs out of seven (`exa` -> `parallel` -> `searxng` -> `marginalia` -> `duckduckgo`), so search works with no configuration whatsoever.
- **The finding that matters more than the two providers: every keyless engine rate-limits by IP.** DuckDuckGo bans and unbans on its own; SearXNG went 2-of-20 then 0-of-71; Marginalia answers 200 with a 1 KB empty page after about five requests. A working rung is not a reliable rung, and the chain is a best-effort ladder rather than redundancy - which is why the failure path is bounded rather than removed. Verified live end to end by running the chain from rung 3: SearXNG exhausted 8 instances in 6.0s, Marginalia returned empty, **DuckDuckGo answered with 4 relevant results**, and both failures reached the model as `Note:` lines naming the instance errors.
- **Recorded what was evaluated and deliberately not shipped, with the reason.** Seven vertical search APIs answer keyless and would be genuinely useful - GitHub repositories, Wikipedia, Stack Exchange, Hacker News, OpenAlex, Crossref, archive.org - but in a sequential first-usable-wins chain they are **unreachable**, because `exa` answers everything first. Wiring them would be code no query can reach; they are worth wiring only if the chain grows query-aware routing. Eleven other keyless engines were measured dead (Startpage's result-less shell, Mojeek's captcha, Mwmbl, Right Dao, Stract, Wiby, Teclis, Alexandria, Firecrawl keyless, `s.jina.ai` search now requiring a key), and `web/AGENTS.md` carries the whole table so it is not researched twice.
- **An SSRF guard for model-chosen URLs.** The design this was ported from has no such rule anywhere (verified by reading its fetch path end to end); this app needed one. `checkFetchUrl` (`src/main/services/web/url-guard.ts`) runs before every socket opens *and again after redirects* - following a redirect being exactly how an allowed literal becomes a request for `169.254.169.254`. `http`/`https` only, no embedded credentials, 2048 characters max, loopback / RFC1918 / CGNAT / link-local / `metadata.google.internal` rejected, because a desktop on a real LAN has a router admin page and a NAS UI one fetch away and both answer unauthenticated GETs. Verified live: `localhost` and `169.254.169.254` are refused in **0 ms**, before any socket opens. Deliberately stricter than `api-config-guard.ts`, which must allow `http://localhost:11434/v1` because pointing the palette at a local model server is the feature. Like that guard it inspects the URL literal rather than the address a name resolves to, so DNS rebinding is not covered; `SECURITY.md` says so rather than implying otherwise.
- **74 -> 82 tests for the web substrate, and they caught seven real defects while it was written.** An absent `filetype:` directive filtering every plain query down to empty (`[].some()` is `false`); a constraint that emptied the set being obeyed instead of relaxed; quoted phrases split on their own spaces; a 404 spending three user-agent rotations; `tryUrlMarkdown`'s `catch` swallowing an abort, which turned every timeout and every cancellation into a hang on an already-fired signal; Exa's highlights truncated at the first blank line because the `m` flag made a `$` end-anchor match at every line end; and the Jina front matter stripped by only its marker line when the real body carries `Title:`/`URL Source:` above it. Five provider parsers are pinned by `search/providers.test.ts` against fixtures **captured from live responses**, because a hand-written fixture keeps passing after the provider changes theirs - with the one exception stated at the top of its own block: SearXNG's fixture is its published API shape, not a capture, because no instance served JSON to the machine that recorded the others.
- **Palette summon motion.** The frameless window had no open animation of its own, so the card now fades and scales in over 150ms on first paint and on every Alt+Space summon (`src/renderer/hooks/useWindowReveal.ts`, `.palette-revealing`). Dismissal is still instant by decision: a launcher that delays `window.hide()` feels laggy and races its own toggle.
- **Eased window-height tween.** `src/main/windowManager.ts` replaces the old 30px-per-16ms `setInterval` stepper with a time-based `easeOutCubic` over 180ms that touches height only, so the palette grows downward from its fixed top edge instead of landing linearly. It snaps when Windows' "Show animations in Windows" accessibility setting is off, read through `SPI_GETCLIENTAREAANIMATION` (`utils/platform.ts`) because a CSS media query cannot reach `setBounds`.
- **View-swap and toast motion.** The Files↔Ask router, the header swap, the three Ask-mode readiness cards and the generative-UI payload replacing its skeleton all enter on tokenised animations instead of popping. Toasts, which previously appeared and disappeared with no transition at all, now enter and exit, with the provider's removal delay read from the same `--duration-150` the exit animates for.
- **First main-process shell test.** `src/main/windowManager.test.ts` drives the real singleton against a stub `BrowserWindow` and asserts the tween's deceleration, its cancellation on a second mode change and the reduced-motion snap (81 tests, up from 77).
- **Motion gate.** `node tmp/motion-tokens-check.mjs` asserts every `--animate-*` shorthand names a keyframe that exists, every `var()` in an animation or transition resolves, every motion token has a reduced-motion reset, and no animation token is dead — the silent-invalidation class that made `.welcome-fade-out` ship a no-op.
- **Two more gates, and one of them exists because the first one's sibling was lying.** `node tmp/token-refs.mjs` asserts every `var(--x)` in `src/` resolves to a defined token and enforces layer discipline (no hue primitive painted as text, no `rgb()`/`hsl()`, no `transition: all` outside pristine `components/ui/`) — an unresolved custom property makes the whole declaration vanish with no error, which is precisely how `--color-purple-500` shipped two untinted agent pills. `node tmp/contrast-full.mjs --strict` recomputes WCAG ratios for the 28 pairs the UI actually paints in both themes, deriving luminance from the OKLCH numbers via the cube-root path and compositing alpha over the plate it sits on. It was written after `tmp/contrast.mjs` reported **0 failures** while the border pair measured 1.26:1 — that gate checked 11 pairs, marked the failing one "informational" so it could never fail, and mis-computed `foreground on card` as 17.32:1 where the correct figure is 19.77:1. The new gate found **20 real failures** the old one could not see. `node tmp/live-style.mjs` reads *computed* styles off the running window over CDP (body font, resolved surface ramp, a button's `transition-property`, whether `.view-enter` still holds a permanent transform, whether `.toast-region` is parented to `BODY`, every node under 12px or 32px), because a CSS grep proves intent and only the running app proves pixels.
- **The full visual/interaction audit is recorded in `docs/design-system-audit.md`** — every colour, spacing, motion, layer and type change with the measured defect that motivated it, the verification table, and what was deliberately left alone.

### Changed

- **The launcher is now compact, sleek and low-radius, end to end.** The whole visual language pivoted on its two source-of-truth token files, so no component or pristine `ui/` primitive needed editing: `tokens/radius.css` dropped from a 12px base to a minimal 8px base with tighter rungs (`xs 2 / sm 4 / md 6 / lg 8 / xl 10 / 2xl 12 / 3xl 14 / 4xl 16`, `--radius-input 6`, `--radius-chip 4`, `--radius-shortcut-key 4`, card/palette/large = 8px), and because Tailwind v4 maps the `--radius-*` namespace onto the `rounded-*` utilities every corner in the app moved with it. `tokens/spacing.css` tightened density for compactness: control height and list-row floor 44px → 40px, `--gap-block`/`--padding-card` 16px → 12px, `--gap-section` 24px → 16px, and the header 100px → 72px. The compact palette window is exactly one header tall, so `MODE_CONFIGS.compact.height` in `src/main/windowManager.ts` moved 100 → 72 in lockstep (its legal-tween floor `TWEEN_MIN_BOUNDS.height` too, or a raised minimum would bump the compact window before the tween reads its start), and `windowManager.test.ts`'s compact literals track 72 with the ratio thresholds unchanged — **297 tests green**. Verified live over CDP against the running palette: computed `--radius-command-palette`/`--radius-card` = 8px, `--radius-input` 6px, `--radius-chip`/`--radius-shortcut-key` 4px, header 72px, input 40px, and the largest border-radius rendered anywhere in the DOM is now 8px. `contrast-full.mjs --strict`, `token-refs.mjs` and `motion-tokens-check.mjs` all still exit clean; the compact OS-window realized height is to be re-measured on the next full launch (the prior 103/603 figures were taken at the old 100px ask).
- **The token layer was rebuilt as one system, and the app was moved onto it.** Motion, spacing, colour, type and stacking each got a single source of truth in `src/renderer/styles/tokens/` before any component changed, so the result is a design language rather than fifty local edits. Easing went from one curve used for everything to a scale with a stated job per curve; the spacing scale went from 6px/10px/18px/16.6px drift to a strict 4pt grid (the half-step rungs are kept as deliberate grid aliases, because Tailwind resolves `p-1.5` straight to `var(--spacing-1-5)` — verified in the built CSS — so re-snapping the rung moves 267 usages with no class-string churn); the `--z-*` scale went from nine declared layers with **one** consumer and raw `z-50` everywhere to eight real layers that are actually consumed; and every floating surface now draws its elevation from one shadow token per surface class.
- **Body text is no longer monospace, and the type scale became a style instead of a number.** `--font-display` and `--font-body` were byte-identical `'JetBrains Mono'` strings — duplicated verbatim in `semantic/theme.css` — loaded only from a Google Fonts CDN with nothing bundled, so offline the whole app silently fell back to Arial. UI text is now a system-first sans (`system-ui`/Segoe UI Variable) with zero network cost, and `--font-mono` keeps JetBrains Mono for exactly what a monospace face is for: code, file paths, key labels, command strings. Each size rung now carries its own `--text-*--line-height` and `--text-*--letter-spacing`, so `text-lg` applies a style and components stop restating leading by hand; 12px became an enforced floor (9/10/11px one-offs survive only as 12px aliases so no old `var()` can drop), and the markdown heading scale stopped rendering `##` and `###` identically.
- **20 measured contrast failures fixed, including one that failed in both themes.** Light `--background`, `--card` and `--popover` were all `oklch(1 0 0)` and dark card, popover and sidebar all `oklch(0.205 0 0)` — the app had no way to express a raised surface, so elevation is now a monotonic lightness ramp per theme carried together with a matching shadow. Dark `--destructive-foreground` on its fill was 2.73:1 (below AA *large*); light `--chart-4` 1.81:1, `--chart-5` 2.24:1, `--file-typescript` 3.65:1 as text, `--info` 4.17:1 on a muted plate. 56 lines painted raw hue primitives as text — illegible in one theme by construction, since a primitive has no `.dark` half (yellow measured 1.72:1) — and now use the semantic `--success/--warning/--info/--destructive` pairs plus new `-soft` tints. `--border` and `--input` were the same value and are now deliberately different: a decorative divider may stay quiet, the boundary of an interactive control is held to 3:1 by WCAG 1.4.11. Shadows moved from `rgb()` to tinted OKLCH, and `--ring-color` stopped pointing at a brand primitive (2.35:1) so the focus indicator themes correctly.
- **`animation-fill-mode: both` was trapping the toast layer, and dismissal semantics were wrong for menus.** Entry shorthands parked their final `transform` on the element for its whole life, which creates a permanent stacking context *and* containing block — so `.view-enter` on the palette body made the `position: fixed`, `z-index: var(--z-toast)` toast region re-anchor inside a `z-10` layer where it could never paint above a dialog, and the bug vanished under `prefers-reduced-motion`, which is how it survived. Entries now use `backwards` (verified live: `.view-enter` computes `transform: none`), and the toast region is portalled to `document.body` beside the Radix portals. Escape's first tier tested only `[role="dialog"]`, so a Radix menu — which carries `role="menu"` — was invisible to it and Escape hid the entire OS window with the chat-history menu still open; the predicate is now a four-selector list, and the hand-rolled click-outside effect in `SearchBar` that double-owned that dismissal is gone.
- **Components stopped inventing their own interaction model.** Every icon-only control is floored at `--target-min` (32px) via the button variants instead of call-site `h-7 w-7` overrides that fought the recipe — a live sweep finds no rendered target under 32px and no rendered text under 12px. Menu items had `focus:` styles and no hover, so the mouse got no feedback at all; that, the dialog's missing shadow, and the absent scrim are assigned through `[data-slot]` rules in `globals.css`, because `components/ui/` stays pristine-by-policy and a `@layer components` rule loses to Tailwind's utilities layer regardless of specificity. Dozens of raw `<button>`s across ask-mode and the generative-UI tables now go through `ui/Button`, so hover/active/focus-visible/disabled behave identically everywhere; file-search loading renders skeleton rows instead of a spinner and its scroll behaviour reads `prefersReducedMotion()`. The `App.tsx` `fixed inset-0 bg-transparent z-0` div — no colour, no handler, nothing beneath it, and the only reason the palette container needed a layer — is deleted, and the loading overlay became a real state with a scrim, a token entrance, `role="status"` and the `.catch()` this file requires on every IPC promise.
- **The screenshot harness could not run against a palette left in Ask mode.** `scripts/capture-ui.mjs` opened with `type('')`, which throws `search input not mounted` there, and `searchMode` is React state with no IPC to force it; its dialog dismissal also selected `button[aria-label="Close"]` while the upstream close button takes its accessible name from an `sr-only` span, so the shortcuts dialog stayed open and occluded every later frame. Both are fixed — the mode is now entered by expanding the pill and clicking `[role="tab"]` (matching by text ping-pongs, because the collapsed pill's label is the *current* mode) — and all six PNGs in `docs/assets/screenshots/` are regenerated against the new system.
- **Two DOX bullets prescribed the thing the new gate forbids.** `styles/AGENTS.md` and `ask-mode/AGENTS.md` both cited `text-[var(--color-green-500)]` as the sanctioned fallback below a semantic utility; as text that value is 2.40:1 on a light card and unthemeable. They now state the real ladder (semantic utility → semantic variable in an arbitrary value → promote a new pair with a `.dark` half), and the restated token values, orphan-BEM list and "only `.dark` rule" claims that this pass invalidated were corrected in place.
- **`src/main/services/langgraph/tools.ts` is deleted, not rewritten.** It held `webSearchTool`, a zod `tool()` wrapper invoked imperatively by `externalSearchNode` - which parsed its returned JSON string back into sources. Nothing in the AskGraph binds tools to a model (`chatModel.bindTools` is reached only for MCP tools, and the ReAct agent in `langchain/agent.ts` is not a caller for this turn), so a `tool()` object here would have had no caller: a wrapper for the sake of a wrapper. The node now calls `searchWeb` and `fetchWebPage` directly and keeps the typed sources it needs. If a tool-executing loop ever binds tools again, the wrappers belong back in this file.
- **The research freshness hack is now a parameter.** `externalSearchNode` appended the literal string `" 2025 2026"` to a second query for research intent; it now runs a second pass with `recency: "year"`, from a closed `day | week | month | year` vocabulary that each provider maps onto its own knob (`df=d/w/m/y`, `with_date`, `freshness=pd/pw/pm/py`, `time_range`).
- **Two `AskState` fields were dead and are deleted.** `researchResults` had zero writers and zero readers anywhere in `src/`; `searchQueries` was written by `externalSearchNode` and read by nobody - the queries are already in the synthesis prompt and in the log, so the field carried nothing a reader could see. `state.test.ts`'s per-turn-array case now pins `sources`, which is the field the research path actually fills. A field with a writer and no reader is decoration, and decoration in a shared state object is a cost every later reader pays.
- **The renderer's web badge finally has step names to key on.** `ThinkingSteps.tsx` labelled three web steps (`webSearch`, `externalSearchFanOut`, `fallbackSearch`) that main has never emitted - it emits `externalSearch` - so the badge could not fire. Those entries are replaced by `externalSearch` and `webFetch`, which the node now emits, and the third dead label went with them.
- **Motion tokens are consumed, not admired.** Every entry animation in `ask-mode-perplexity.css` was re-composing its own keyframe, duration and easing by hand while `tokens/motion.css` shipped 18 of 28 motion tokens to nobody; they now consume the `--animate-*` shorthands, and the unreferenced ones (`--transition-*`, `--easing-bounce`/`-snap`, `--animate-bounce`, durations 75/700/1000) are deleted.
- **Reduced motion is honoured in JS, not only CSS.** `src/renderer/utils/motion.ts` reads the design-system tokens from `:root`, so `scrollIntoView`, the toast exit delay and the auto-animate tween all stop when the OS asks them to; the reset block now sets shorthands to `none` rather than `0ms`, which only worked through CSS error recovery.
- **`auto-animate` is torn down.** Its controller was discarded at `ChatMessagesList.tsx`, leaking a MutationObserver per StrictMode remount; it is now destroyed on cleanup, and its duration and easing come from tokens rather than JS literals. Note the design system documented `ctrl.stop()`, which does not exist in auto-animate 0.10 — the correct call is `destroy()`.
- **The desktop agent is now the Pi agent, and the whole desktop subgraph is gone.** `src/main/services/pi/` replaces the hand-rolled ReAct loop, the 7-node plan→execute→verify→recover subgraph, its NL-postcondition verifier, its recovery ladder and its trajectory memory. What ships instead is one Pi `Agent` loop over the same 32 tools, now TypeBox `AgentTool`s rather than zod `tool()` factories, with a typed `AgentEvent` → bridge translation that is exhaustive by construction — so a new event kind is a type error instead of a silent drop, which is exactly the failure mode the old `metadata.langgraph_node` plus two hand-maintained token whitelists had. Two long-gone indirections died with it: `inferStatusFromTool` (a tool-name string map, replaced by every tool reporting its own `details.status`) and `DANGER_POLICY` (32 rows consulted by name, replaced by a single `details.verifies` opt-in that only `close_window` sets). The `desktopAgent` AskGraph node keeps its name and its `Desktop` label because the node registry binds the name to the builder and the renderer shows the label — it is a node in name only, making one call to `runPiDesktopTask`. Pi has no `maxSteps`, so the 25-step cap is gone and `RUN_TIMEOUT_MS` is now a 10-minute **whole-run** budget rather than the 60s it inherited from a per-call timeout.
- **`PiDesktopAgent` is a lazily-constructed process-wide singleton, and is now actually released.** It owns two native resources — a tesseract worker and the UIA facade — behind a single abort slot, which is why neither call site (`research-agent.ts`, `document-delegation.ts`) needs to thread an `AbortSignal`: `Agent.prompt()` throws if one instance is already processing, so two concurrent desktop runs are impossible by construction. `closePiDesktopAgent()` existed but **nothing called it**, so both native resources outlived the last task; it is now wired into `app.on('will-quit')`, behind a dynamic `import` because a static one would put Pi's model provider on the cold-start path. `DesktopAdapter` gained an optional `cleanup?()` for it, optional precisely so a stub adapter in `toolbox.test.ts` need only the 18 tool methods.

### Fixed

- **Quitting never actually tore anything down.** `will-quit` fired three `.catch`-ed promises and returned, so Electron finished the quit while the MCP stdio children, the Playwright/Chromium session and the Pi agent's tesseract worker and UIA facade were all still being released — and the `Cleanup complete` line printed synchronously, before any of them settled. It now calls `event.preventDefault()`, runs `buildShutdownSteps()` through a new `src/main/lifecycle.ts`, and only then `app.exit(0)`. That module owns the four properties the quit depends on: steps run in array order and sequentially, each is bounded by a 2s deadline so one wedged disposer cannot strand the rest, `run()` never rejects, and `run()` is memoised — which is what makes the unconditional veto safe, because a second `will-quit` joins the run in flight instead of double-disposing handles that are already torn down. The order is a contract: the koffi message-pump interval first (it is what holds the event loop open), the database last (its `close()` flushes). Eight tests import the production `createShutdown` and pin each property.
- **A failed MCP initialisation orphaned every server it had spawned.** `MCPAdapter`'s constructor connects each configured server, and both call sites assigned the adapter to the instance field *before* awaiting `listTools()`. A throw there left a half-built adapter parked with its stdio children attached, and the next `initialize()` — gated only on a flag that stays false — overwrote the field without closing it. `initializeWithRetry` makes three attempts, so a misconfigured server orphaned up to three. Both sites now construct into a local, publish on success, and `close()` the local on failure. The browser fallback was the worse of the two: `cleanup()` is gated on `usingFallback && fallbackClient`, and the throw happened before `usingFallback` was set, so the orphan was unreachable from both ends.
- **`command:execute` ran an unbounded OS child.** It was the only `exec` in the tree carrying neither bound, and Node's default for both is a trap: `timeout: 0` means *no timeout*, so a command that never exited held its shell and the IPC call open with nothing to kill it, and the 1 MB default buffer turned a chatty command into a truncation error. It now passes `timeout: 30000` and `maxBuffer: 10 MB`, matching `esRunner.ts` and the Pi `execute_command` tool.
- **`DatabaseManager.close()` and `BrowserMemoryStore.close()` had zero production callers**, so the sql.js handles were abandoned at exit. Both are steps in the shutdown list now, and the database is deliberately last so its flush captures anything written during teardown. `LangChainAgent.cleanupBrowserAgent()` had the same shape of bug in miniature: it nulled its session id without clearing `browserSessionTimeout`, leaving a live five-minute timer that would later fire against an already-null session. It is also the browser subtree's release path, so there is deliberately no second `browser` step.
- **Five renderer timers fired after unmount.** `CodeBlock`'s copy-confirm reset, the `useCommandExecution` executing-marker clear, `useWindowMode`'s collapse flash, `useFocusManager`'s focus frame and the `useFileSearch` retry backoff all discarded their handles; the collapse flash also stacked on rapid mode changes. Each now holds its id in a ref, clears on re-arm as well as on unmount. Separately, seven effects awaited an `electronAPI` call and then called `setState` with nothing mounted-check — `App`'s app list and MCP count, `useMCP`'s status and tools, `MCPToolModal`'s server list — and they now share the one guard idiom the tree already had, `isMountedRef`. No `electronAPI` call is cancellable, so the guard means "do not start more work after teardown", which is also how the retry loop now stops. The browser status poller gained an in-flight flag, since a tick that outruns its own interval was firing overlapping requests.
- **A desktop run could hang forever, and its own regression test could not catch it.** On 2026-10-15 a live 3-step task (`launch_app` → `wait` → `close_window`) never settled: the renderer gave up at the graph's 120s `GRAPH_TIMEOUT_MS` and cleared `loading`, but main sat at 0% CPU on a promise that never resolved. LangGraph does not cancel a node that is already running. Three pieces close it — a per-run `AbortController` in `PiDesktopAgent.run`, a `withAbort` race around `agent.prompt()` so the node settles as an abort rather than waiting on work that never answers, and `abortPiDesktopRun()` from the chat pump's `finally` on **every** exit path, not only a user stop. The toolbox's `wait`/`launch_app` poll loops take the same signal, so a long sleep unblocks too.
- **That regression test was a mirror of its own subject.** `cancel.test.ts` *re-declared* `withAbort` and `sleep` rather than importing them, so it kept passing after the real `withAbort` was deleted — a gate for the hang, testing a copy of itself. `withAbort`, `withTimeout` and `AbortError` now live in an Electron-free `src/main/services/pi/abort.ts` (reachable without `agent.ts`'s native imports) and the test imports both subjects. Mutation-checked: replacing the race with a bare `return work` now reddens the suite, and it hangs for 5s on the never-settling promise — the original defect. The suite also caught that `RUN_TIMEOUT_MS` had been mis-scoped: it inherited `DesktopAgent`'s 60s *single model call* timeout and was applied to a whole run, aborting legitimate multi-step work.
- **The desktop agent's reasoning step described machinery that no longer exists.** The `in_progress` step the renderer shows verbatim read `Initializing hierarchical desktop subgraph (memory -> planner -> executor -> verifier -> store)` — the exact chain the Pi cutover deleted. It now describes the agent that actually runs. The `[DesktopAgent]` log prefix, which named a deleted class, is `[PiDesktop]`.

- **`window:getMode` and `window:toggleMode` answered an exception with `'compact'`.** A fabricated mode is not a neutral default: the renderer lays the palette out for whatever main says, so a swallowed error made an ordinary read indistinguishable from a genuinely compact window — the `handlers.ts:72,82` pair now re-throw, which is the idiom `window:setMode` already used, and the one consumer already catches. `dialog:openFile`/`openFolder` had the same shape one layer out: a thrown dialog returned `{ cancelled: true }`, so a caller could not tell "the user chose nothing" from "the dialog broke"; they now return `{ error }` and keep `{ cancelled: true }` for a real dismissal. Surfacing that field needed the stale `src/renderer/types.d.ts` declaration edited as well, which is the repo's five-site rule biting exactly once more, and both picker call sites log the failure now instead of ignoring it. Covered by `src/main/ipc/handlers-failures.test.ts`, the second test to drive the production registrar (it mocks `electron`, registers `registerIPCHandlers()`, and calls the captured handlers); mutation-checked both ways — restoring `return 'compact'` and restoring the dialog's `{ cancelled: true }` each redden one test. The mode handlers are synchronous, so the tests assert `expect(() => …).toThrow()` rather than a rejected promise; `ipcMain.handle` is what turns the throw into a rejection for the renderer.
- **The selftest could not lose.** `step()` scored `detail?.pass !== false`, so any step whose verdict evaluated to `undefined` was recorded and printed as PASS. `JSON.stringify` drops `undefined` keys, so the transcript looked fine: `hide via real Escape` computed `r.hidden === true || r.note?.startsWith('already')` on a result with no `note`, which is `false || undefined` → `undefined` → PASS **with `hidden: false` in the same line**. It is `=== true` now. No step needed a loosened bound afterwards — the suite ran 16/16 twice — so the only thing the old default was hiding was undeclared verdicts. The same class produced two more corrections: `paletteHasFocus` compared **process ids**, and detached DevTools (`windows.ts` opens it in dev) shares the app's pid, so the harness believed the palette had the keyboard while three real Escape presses were landing in DevTools — it compares window handles now and reports the foreground handle/pid/title on refusal; and the `state` read's `dialog` field measured `text.includes('Keyboard Shortcuts')` while the app's own Escape ladder tests `document.querySelector('[role="dialog"]')` — the read now measures the app's predicate, with the shortcuts help split into its own `helpOpen` field.

The window's own `show` handler is now the single emitter (`windows.ts:120-123`), which covers boot, the Alt+Space toggle, the tray and `activate` identically, and `showMainWindow()` no longer sends it a second time — the duplicate used to restart the reveal on every summon. `ready-to-show` also calls `mainWindow.focus()`. Measured symptom of the gap: after a cold start `document.activeElement` was a `BUTTON`, typing `x` left the input empty, and Escape hid nothing until something clicked the field.
- **A new graph node could run perfectly and stream nothing, with no error anywhere.** `chat-handlers.ts` kept its own node→label map and **two** hand-copied sets of the nodes allowed to emit tokens — one inside the send pump, one inside the resume pump — and nothing in the type system, the build, or the tests related any of them to the `.addNode()` chain in `research-agent.ts`. The documented recipe was to edit four places, and the root rail recorded the failure mode as silent. All three lists are gone: one `ASK_GRAPH_NODES` table in the new Electron-free `src/main/services/langgraph/node-registry.ts` derives both `NODE_AGENT_MAP` and `RESPONSE_NODE_SET`, both pumps import the same set, and `research-agent-registry.test.ts` reads the builder's own source and fails if a node has no row or a row has no node — proven by adding a `.addNode("ghostNode", …)`, which turns two assertions red. Placing the table outside `research-agent.ts` is what makes the test cheap: importing the graph module pulls `electron`'s `app.getPath` through the browser/desktop/document agents, so the production table is now testable with no mocks at all, the same reason `command-guard.ts` and `file-guard.ts` exist.
- **A streamed answer committed once per token and re-parsed itself whole every time.** `chat:stream-chunk` wrote `setMessages` directly, so the renderer committed at whatever rate the model emitted — far above the 60 Hz the page can paint — and each commit rebuilt the entire element array from the accumulated string. Chunks now accumulate in a ref and flush on one `requestAnimationFrame` (`useChatSession.ts:206-237`), with the terminal chunk draining the buffer in its own tick so a completion that arrives mid-frame cannot truncate the answer, and the listener's cleanup cancelling the frame instead of committing into a dead tree. `ChatMessageBubble` renders the settled prefix through a memoized parser and only the tail through the live one (`src/renderer/utils/markdownBlocks.ts`), with the cut refused inside a code fence and inside a loose list because a wrong cut is a wrong render, not a missed optimisation. Transcript tracking is `instant` while a message streams (`ChatMessagesList.tsx:78-90`) — a ~300 ms smooth scroll restarted per chunk made the view swim toward a bottom that had already moved — and `ChatMessageBubble`'s mount-time `scrollIntoView` is deleted, not gated: it yanked the viewport once per bubble while a history loaded. Proven by four new cases (five chunks in one `act()` render nothing until a frame; the terminal chunk preserves buffered text with no `fullContent`; character-exact rejoin; monotonic settling) and mutation-checked by flushing eagerly, which reddens the buffered case. **Not verified live:** the app has no `api-config.json` in this profile, so no model is reachable and a real streamed answer was never rendered — the coalescing and the split are proven by unit tests only.
- **Expanding the palette jumped ~200 px before it animated, and the animation's first frame carried a third of the distance.** Two independent causes, both found by reading the page-frame trace rather than the pass/fail line of the step that produced it. (1) `setMode('expanded')` called `applyModeConstraints` before reading the tween's start height, and `setMinimumSize(800, ≈301)` on a window locked at 103 px makes Windows resize it immediately — the trace opened `103 → 450`. `beginTweenBounds` now loosens min/max without moving the window, and the mode's real bounds go on in the completion callback. (2) The curve was `easeOutCubic`, whose velocity is maximal at `t = 0`, so the first presented frame moved the window ~135 px (27% of the distance, measured 33.8% with a late first report). It is smoothstep now: 0.4% in the first frame, peaking mid-transition. `windowManager.test.ts` gained a Win32 rule in its stub — a raised minimum resizes at once — which is the only way a unit test can see the call-order bug (reverting it reads `expected 300 to be 100`), and the shape assertions run on a scripted clock because a real `setTimeout` lets the first frame land anywhere from 17 to 40 ms and turns a fraction bound into a measurement of the scheduler (it did, once, in a full `npm run test` run). Re-measured live on a fresh build: 11 ramp frames, 11 distinct heights, 0 consecutive duplicates, 167 ms, repeated three times.
- **`reveal opacity trace` could not fail.** It returned `pass: true` on both branches and marked itself `scored: false`, so a summon with no fade at all stayed green. It now requires the card to start transparent (`minOpacity ≤ 0.2`, measured 0) and the fade to finish inside the envelope its own token declares (`dimForMs ≤ 260` against `--duration-150`, measured 34), and a two-frame-short trace is a failure. It does NOT require a minimum number of dim frames: a hidden window runs no rAF, so the first samples land ~100 ms into the animation and frame count measures compositor start-up (5 frames over 67 ms on one run, 2 over 34 ms on the next, same build). That same fact is left on the record as an open finding — the user may be seeing the tail of the entrance — rather than hidden behind a green step.
- **The `file:*` guards lived where a renderer can step around them.** `file:search`'s metacharacter blocklist was preload-only (`src/preload/preload.ts:243`), and `ipcRenderer.invoke` is reachable from the renderer directly, so a direct invoke — or any driver holding a DevTools `Runtime.evaluate` on the debug port — handed the raw string to the `es.exe` invocation. `file:revealInFolder` had no check at either layer and passed whatever it received to `shell.showItemInFolder`. Both rules now exist in main through `src/main/ipc/file-guard.ts`: `isSafeSearchQuery` (eight metacharacters, empty, NUL, >500 chars → the handler warns and returns `[]`), `isUsablePath` (empty, >1000, embedded NUL, interior `\\` that could re-point a UNC string → `file:open` fails and `file:revealInFolder` is skipped with a warning). `file-guard.test.ts` asserts main's list is still byte-identical to preload's — the sandboxed preload cannot import `src/main`, so the duplication is structural and the test is what keeps it honest — and mutation-checks the wiring by deleting each guard call. This narrows a bypass; it is not containment, because an accepted path can still be anywhere on any drive and that is the feature.
- **`window:resizeHeight` resized the window to whatever it was told.** The channel existed so the expanded palette's drag handle had something to push against, but the handler wrote `setBounds({ height: Math.round(height) })` with no check at all — no finiteness test, no ceiling, no work-area clamp — which made it the one IPC path that could size the always-on-top window past the usable strip (the plan's "arbitrary bounds that bypass `getPaletteLayout`"). It now refuses a non-finite request, rejects a resize outside `expanded` (where the size lock would just snap it back), clamps through `windowManager.clampExpandedHeight`, and returns the height actually applied so the drag cannot drift from reality. The floor/ceiling moved into `expandedHeightBounds()`, which `applyModeConstraints` also uses, so the OS limits and the validation cannot disagree. While there, the width-lock listener's one-way `resizeListenerAttached` boolean became `resizeListenerWindow`: a session that recreated the palette window (`main.ts` does on `activate`) gave the new window **no** listener at all, so its width could be dragged sideways and nothing restored it. Four new assertions in `windowManager.test.ts`, mutation-checked (clearing the latch only for the first window, or deleting the clamp, each turns one red).
- **`main`'s own contract doc still described the retired tween.** `src/main/AGENTS.md` asserted the height tween was "a self-rearming `setTimeout` chain, not `setInterval`" after the page-frame pacing had already replaced that; it now records that main owns the curve and the page owns the clock, with the measured 11 → 6 → 1 duplicate-history and the 120 ms stall-snap fallback, and its `windowManager.ts` line counts, logger refs and gate counts were re-derived from the files rather than carried forward.
- **The history list was polled, not pushed.** Chat session identity lives in main's in-memory `Map` and had no push channel, so `AskModeExpanded` invented `loadHistory` + `useEffect(loadHistory, [loadHistory])` to keep the recent-chats row fresh; the dependency was a fresh closure every render, so every render fired another `chat:listSessions` IPC whose result re-rendered it — an unbounded loop for as long as Ask mode was open, which the earlier referential-stability fix only stopped the symptom of. Main now publishes `chat:sessions-changed` with `ChatSessionSummary[]` (`src/shared/ipc/sessions.ts`, so the row shape is declared once instead of three times) from every agent mutation that can change the visible list and once from `chat:initialize`, and `useChatSession` exposes the arriving `sessions` directly: an Ask-mode mount now costs **zero** `chat:listSessions` calls, and `loadHistory` is deleted rather than left half-wired. `sessions-publish.test.ts` drives the real `langChainAgent` and caught a defect in the first draft while it was being written — publishing through a floating `listSessions()` promise meant two rapid mutations could publish out of order and a caller could not observe the push, so the snapshot is now built synchronously by `visibleSessions()`, which `listSessions()` also uses, leaving one definition of "non-empty, newest first". Both halves are mutation-checked: deleting the agent's publish call reddens two tests, deleting the renderer's subscription reddens the zero-fetch test.
- **`windowMode` had three owners and all of them could be wrong.** `src/renderer/hooks/useWindowMode.ts` wrote the mode optimistically before `window:setMode` even round-tripped, main's echo was then thrown away by `mode !== windowMode` because the renderer had already guessed the answer, and a third writer — a `visibilitychange` handler that re-fetched the mode on every summon — overwrote whatever was still in flight. The value now arrives only from main (mount snapshot + `window:modeChanged`), and a renderer that wants a different mode *requests* one. The auto-expand/collapse policy is unchanged in behaviour, and one subtlety had to be built to keep it: an expansion must not auto-collapse, but main echoing back the renderer's own request is not the user taking over, so `requestedRef` distinguishes the two — without it the palette expanded on two keystrokes and never collapsed again (caught by driving the real app, not by the first draft of the tests). `isManuallyExpanded`, `setWindowMode`, `toggleMode` and `setIsManuallyExpanded` were returned to `App.tsx` and read by nobody — deleted. Six tests in `useWindowMode.test.tsx`, mutation-checked in both directions; verified live: 103 px → type 5 chars → 603 px → clear → 103 px, with `Alt+Shift+M` still surviving an empty query.

- **The reveal waited for a round trip before it began.** `useWindowReveal` armed the entrance fade from `electron-window-shown`, but main calls `show()` and only then sends that IPC (`src/main/windows.ts:145-149`), so the always-on-top window was on screen for a beat with the card still at `opacity: 0` — measured as 4 sampled frames below 0.1 (34-67 ms) of a palette you could click but not see. It now arms on `document.visibilitychange`, which flips in the same frame the window appears, with the IPC event kept as a fallback guarded by `REVEAL_FALLBACK_MS` (250 ms, longer than the 150 ms animation) because re-adding the class mid-fade resets opacity to 0 and makes the invisible window *longer*. Honest limit: the trace reads 4 frames under 0.5 before **and** after — that span is the entrance ramp itself, not the round trip. Pinned by `src/renderer/hooks/useWindowReveal.test.tsx`, which fakes the clock and counts class additions through a `MutationObserver`; mutation-checked both ways (dropping the visibility listener fails two tests, dropping the guard fails the no-restart test).
- **Three harness steps reported a working app as broken.** `ArrowDown moves selection` compared the selection text against the state snapshot `pressKey` returns, which is taken before React commits the new index inside `startTransition` — two identical pre-paint frames, "failed" in 42 ms, and the doc blamed `[aria-selected]` attribute drift when `ResultItem.tsx:311-316` renders it fine. It now presses and polls the named `state` read, and passes on the real transition (`.mmd` → `.svg`). `OS click focuses input` demanded bit-exact equality between `GetCursorPosition` and a computed point; the CSS→physical→`SendInput` pipeline is a few px off by construction (+4/+3 measured, 0/0 on the next run), so it asserts focus plus ≤6 px drift, which still cannot hide the DPI-unaware/aware mix it exists to catch (hundreds of px). `hide via real Escape` pressed once, but Escape is graded, so a query left over from a previous run ate the press and the step declared the ladder broken; it clears to a known state first and allows three presses. **`npm run harness:selftest` is 16/16 green, twice in a row, on a fresh build** — the first time this repo's live UI gate has passed end to end — and the rAF-paced height tween measures 12 ramp frames / 11 distinct heights / 1 duplicate / 183 ms against a 7-16 / ≤2 / ≤260 ms budget that was never relaxed.

- **24 logger subsystems were permanently switched off.** Anything whose name was missing from `SUBSYSTEM_ENV_VARS` (`src/main/utils/logger.ts`) inherited `globalLevel`, which is `error` in production, so every `info`/`debug` line those modules emit vanished and no environment switch could bring them back — all seven `Document*` names, six of nine `Browser*` names, the whole UIA/input/screenshot layer, `MCPRouter`, `ApiConfig` and `Search`. All are registered now (`LOG_DOCUMENT` is new), and `logger.test.ts` reads every `createLogger('<Name>')` out of `src/` and fails on either an unregistered name or an entry whose call site is gone, so the registry cannot silently re-drift. Mutation-checked: dropping two entries turns it red.
- **Main fetched any URL the renderer named.** `api-config:test` took `{apiKey, baseUrl, model}` off IPC and POSTed to `<baseUrl>/chat/completions` with `Authorization: Bearer <key>`, returning the first 100 characters of the response; `api-config:save` persisted that `baseUrl` for every later chat request. A steered renderer (Ask mode renders model-authored text; a DevTools holder has the same reach) could therefore probe internal services or deliver the user's key to a host it chose. `checkBaseUrl` (`src/main/ipc/api-config-guard.ts`) now runs in main before either handler acts — http(s) only, absolute, no embedded credentials, no link-local or cloud-metadata host, while loopback stays allowed because a local OpenAI-compatible server is the reason the field exists. `api-config-guard.test.ts` drives the production registrar and asserts no file is written and no fetch happens for a rejected URL.
- **The transcript kept two copies of every streaming fact.** `useChatSession` mirrored `thinkingSteps`, `confidence` and `activeAgent` in its own `useState` — none of them read by `AskModeExpanded`, which renders the copies attached to each message — and wrote the message *from inside* the `setThinkingSteps` updater, which is an impure updater React may invoke twice. The mirrors are deleted; `withThinkingStep` and `withAgentLabel` are exported pure folds and the only writers of `message.thinkingSteps` / `message.agent`, pinned by `chatTranscriptFolds.test.ts` (no input mutation, a new array on change, the identical array when nothing is streaming, an `update` folding into the in-progress step). Rewriting a fold to push in place turns the tests red.

- `.welcome-fade-out`, `fadeOutUp`, `--animate-fade-out-up` and `--duration-250` were fully authored and applied to nothing. Deleted rather than wired: animating that exit would have required a deferred unmount of the exact element `@formkit/auto-animate` observes, which the design system forbids.
- **The palette card and the OS window disagreed about the palette's height.** `CommandPalette`'s container carried its own `transition-[height] duration-150` and, per mode, a fixed 100px or a 600px `min-height` while the main process was resizing the actual window. Sampled frame-by-frame, the card was up to 298px **taller** than the window mid-expand (footer and input clipped below the frame) and up to 444px **shorter** mid-collapse — leaving a transparent, still-always-on-top slab over the desktop that swallowed clicks on nothing. The container is now `h-full` in every mode and the window is the sole animator of height; the difference is 0px in every frame of both transitions.
- **`.shimmer` was never the app's animation.** `shadcn/tailwind.css` (imported at `globals.css:3`) defines `@utility shimmer`, and a Tailwind utility sits in the `utilities` layer, which outranks the `components` layer regardless of specificity. The `animation: shimmer 1.5s infinite`, gradient `background` and `background-size` written in `globals.css` were therefore always overridden — the running app computes `animation-name: tw-shimmer` at `2s` on those nodes. The local `@keyframes shimmer` and the ineffective `.shimmer { animation: none }` reduced-motion mirror are deleted, and the rule keeps only `background-color`, the one property the library does not set and the skeleton's only fill. A transform-based rewrite was built, then measured against the library version (interleaved twice, 21 nodes, window visible): 30.1/27.7ms vs 39.6/41.6ms of main-thread style recalculation per 2s — **not cheaper**, because Chromium ticks every CSS animation on the main thread whether or not the animated property composites. It was reverted; the collision fix stands on its own.
- `cursorBlink` was defined twice (`tokens/motion.css` and `globals.css`) with the later duplicate silently overriding the token, and a third variant existed at 0.8s inside the dead `.process-indicator` block. Both are gone; `@keyframes slideDown` had no consumer and was deleted too.
- Two agent-pill colours — `--color-purple-500` and `--color-orange-500` — are referenced by `ask-mode-perplexity.css` but defined nowhere, so the browser and document agent pills render with inherited text and no tint. Found by the motion gate and **not yet fixed**: neither hue clears 4.5:1 as text in both light and dark at a single lightness, so the correct fix is a semantic pair with a `.dark` half, which is a colour change rather than a motion one.

## [1.0.0] - 2026-10-13

### Added

- **Command palette shell.** A frameless, transparent, always-on-top Windows window opened by the global hotkey Alt+Space, with fuzzy result ranking, quick-execute slots for rows 1-9, an Emacs-plus-Vim keyboard map, a shortcuts overlay, and a system tray. Alt+Space on Windows needs both a koffi low-level keyboard hook and an in-window `SC_KEYMENU` intercept, because the operating system reserves the combination.
- **Three window modes.** `compact`, `expanded` and `custom` geometry (`src/main/windowManager.ts`), persisted through `preferences.json` and broadcast to the renderer over IPC. The window hides to the tray rather than closing.
- **File search.** Instant Windows filename search through the Everything CLI (`es.exe`), auto-download of that CLI if it is missing, debounced queries from the renderer, and a recent-files list.
- **Ask mode with compiled LangGraph graphs.** An `AskGraph` of 5 nodes plus two delegated subgraphs — browser (8 nodes) and document (9) — for 22 nodes in total, with a shared `AskState`, intent classification before any model call, per-turn checkpoint threads, and reasoning-step streaming to the renderer. (A third subgraph, desktop (7 nodes), shipped in this release and was removed in Unreleased when the Pi agent replaced it.)
- **Windows GUI automation agent.** 32 LLM-callable tools over three native backend families (koffi FFI into `user32.dll`/`shell32.dll`, `libwin32`, and `node-winautomation` UIA COM), with screenshot capture, `tesseract.js` OCR, pixel-diff verification, and a plan-execute-verify-recover subgraph. (The subgraph was replaced by the Pi agent in Unreleased; the tool count is unchanged.)
- **Human-in-the-loop gating — removed in Unreleased.** This release shipped a per-tool danger policy — 29 `safe`, 2 `reviewable`, 1 `dangerous` — that interrupted for confirmation before any non-safe action, with deny fed back to the model as a no-retry instruction. The gate was never reachable in production (it read the paused payload from a LangGraph field LangGraph does not populate) and has since been removed by decision. **No approval gate exists in the current build; every tool runs without asking.**
- **Browser automation agent.** Chromium driven through the Playwright MCP stdio server, with on-disk `SKILL.md` prompt material, LLM task planning, postcondition verification and a five-strategy recovery ladder.
- **Document generation.** Real `.docx`, `.pptx` and `.xlsx` output via `docx`, `pptxgenjs` and `xlsx`, written only into `~/Documents`, verified by re-parsing the written bytes, with reads bounded by a shared loader (`mammoth`, `pdf-parse`, `unzipper`, `xlsx`) and per-format size caps.
- **MCP client.** Servers are added by editing `mcp-config.json` — no code change per server — with intent- and keyword-prefix tool routing, per-server enable/disable in preferences, and a non-fatal retry at startup.
- **Trajectory and failure memory.** `sql.js` persistence with four append-only migrations (`src/main/services/database/`), reused by both the desktop and document learning loops.
- **Structured generative UI.** Table, form, comparison, list and chart payloads rendered from validated Zod structured-output payloads, with skeleton and progress states while a payload streams, plus a per-answer token/cost/duration disclosure.
- **Design system.** A three-layer OKLCH token architecture (`src/renderer/styles/tokens/` -> `semantic/theme.css` -> component) over shadcn primitives and Tailwind v4, with `.dark` class theming and centralised reduced-motion handling.
- **Windows packaging.** An NSIS x64 installer target via `electron-builder` (`npm run build:win`), plus an unpacked directory build (`npm run build:win:dir`).
- **Security posture.** Sandboxed renderer with context isolation and no Node integration, denied `setWindowOpenHandler`, a `will-navigate` allowlist, protocol checks on `url:open`, and dev-only remote debugging gated on `NODE_ENV`. See `SECURITY.md` for the limits of this.

### Notes

- LLM access is `@langchain/openai` against any OpenAI-compatible endpoint. Configuration is three required environment variables — `API_KEY`, `BASE_URL`, `MODEL` — with optional `FAST_MODEL` and `TAVILY_API_KEY`; see `.env.example`.
- Web search is a DuckDuckGo HTML scrape with a Tavily fallback; there is no vendor search API dependency.
- The automated test suite in this release is a skeleton: `npm run test` collects two files, `src/main/ipc/handlers.test.ts` and `src/main/services/langgraph/research-agent.test.ts`, and neither imports production code. The graphs, the 32 desktop tools, the streaming contract and the renderer are untested. See `CONTRIBUTING.md`.
- Documentation in this repository is contract-driven: nested `AGENTS.md` files are binding for contributors, and several root-level reports are explicitly marked historical.
