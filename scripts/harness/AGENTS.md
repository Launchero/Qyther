# scripts/harness — DOX child contract

Parent rail: `../../AGENTS.md`. Research record and rationale live in `docs/windows-ui-harness.md`; this doc owns the rules for editing the harness itself.

## Purpose

Let an agent or a human capture and operate the running app the way a Windows user does — real cursor, real keystrokes, real composited pixels — and assert against DOM ground truth. Exposed twice from one core: a CLI for operators, an MCP stdio server for agents.

Root `AGENTS.md` ## Live Verification makes this the repo's default way to test: a change to anything the user sees, presses or any IPC channel is not done until it has been driven here against `npm run dev` and the observed result reported.

## Ownership

| File | Owns |
|---|---|
| `native.mjs` | Every Win32 call: `SendInput` mouse/keyboard, the normalised virtual-desktop move, cursor, `EnumWindows` with class + pid + per-window DPI, monitors, GDI desktop grab, process DPI awareness, `GetLastError` diagnostics. Re-declared koffi bindings; must never import Electron. |
| `cdp.mjs` | Endpoint discovery and pid attribution, target selection by window title, the closed registry of DOM reads (`READS`), page capture, the lifecycle event recorder, the accessibility tree, `latestTrace`. |
| `driver.mjs` | The verbs, and the single place the input-vs-observation boundary is decided. Owns the coordinate pipeline, the focus rule, the privacy predicate (`foreignPaths`) and artifact pruning. |
| `cli.mjs` | argv → verb → JSON, the per-verb success predicates that drive the exit code, flag parsing, and `selftest` + the DOM-input guard. |
| `mcp-server.mjs` | The whitelisted tool table. The only file in the repo that may import an MCP **server**. |

## Local Contracts

- **All input is OS-level.** State changes go through `native.mjs` `SendInput`. Never synthesize input in the page: no `HTMLInputElement` native setter, no `el.click()`, no `dispatchEvent`, no `new Event`/`new PointerEvent`, no `window.electronAPI` call, and no CDP `Input.dispatch*` or `Emulation.setDeviceMetricsOverride`. CDP is for reading and for the palette's own pixels only. `selftest` fails if this is violated, and the guard list covers the CDP input and emulation verbs too — they make the page believe it was driven by a user when nothing crossed the OS input queue.
- **Move the cursor with a move *event*, not `SetCursorPos`.** `SetCursorPos` repositions the arrow but inserts nothing into the input stream, so no `WM_MOUSEMOVE` reaches the app and a drag's intermediate positions are never seen. All movement goes through `moveTo`, which sends `MOUSEEVENTF_MOVE | ABSOLUTE | VIRTUALDESK` with `dx`/`dy` normalised to 0-65535 **from the virtual-desktop origin** — without `VIRTUALDESK` the normalisation is against the primary monitor and the origin is ignored, so a window on a second screen is clicked in the wrong place while every DOM read still looks healthy. Measured on this box: every target across the full desktop lands within 1 px.
- **No verb may close, quit, launch or navigate the app.** `src/main/windows.ts` vetoes `close` unconditionally and its only escape is the `before-quit` flag, so a stray close no longer takes the app down — but the harness still never attempts it, and starting the app is the operator's job.
- **No caller-supplied code, anywhere near the MCP surface.** Reads are named entries in `cdp.mjs` `READS`. Do not add an `evaluate`/`expression`/`script`/`ipc_invoke` argument: the app's `command:execute` bridge makes any `Runtime.evaluate` into OS command execution.
- **The exit code is a verdict, and every verb supplies its own.** `VERBS` in `cli.mjs` pairs each verb with an `ok` predicate, because only `preflight` and `wait` return an `ok` key. The previous rule (`out.ok === false || out.problems?.length`) meant `hide` on an app that ignored Escape, `reveal` on a dead hotkey, `clear_input` on text that stayed, `set_mode` on a window that never settled and `click_element` on the wrong element all printed a healthy result and **exited 0**. The selftest's own rule — only `pass === true` counts, never a permissive default — has to reach the exit code too, or the gate can say no while the command line says yes.
- **A selftest step must state its verdict, and only `pass: true` counts.** Never `pass: r.ok !== false`: that is the permissive default this suite already documents once, and it was still present on the event step, safe only by the coincidence that `waitFor` happens to set a boolean. A step that cannot say "no" is a log line.
- **Flags are the documented CLI form; JSON still works.** `--flag value` carries no quotes to lose, and Windows PowerShell 5.1 strips the double quotes out of a single-quoted argument before the native process sees it, so the previously documented `cli.mjs type '{"text":"qyther"}'` died with a raw Node `SyntaxError` on the default Windows shell. A flag value becomes a number only when it round-trips exactly through `Number`, so `--text 007` stays the string `"007"` and is typed as typed.
- **A thrown verb prints JSON and exits non-zero.** Never an unhandled rejection: a raw stack trace on stderr with non-JSON stdout is the worst possible shape for the agent that invoked the command. Argument-parse failures exit 2; verb failures exit 1; unknown verbs exit 2.
- **Identify the palette by class + owning pid, never by title alone.** The `BrowserWindow` starts with `title: ''` and gains `Qyther` only after the renderer loads; a title filter misses it during launch. `preflight` resolves the CDP port's `OwningProcess` and requires the window to belong to that pid.
- **Every child process is bounded.** `portOwnerPid` shells out to PowerShell for `Get-NetTCPConnection` and passes `timeout`, `maxBuffer` and `windowsHide`, per the root rail's rule for every `exec`/`execFile` in the repo. An unbounded PowerShell holds `preflight` open forever with no error and no exit.
- **A closed CDP socket rejects everything pending, immediately.** `ws.onclose` fails in-flight calls naming the close code. The previous behaviour surfaced a dead session as `Runtime.evaluate timed out after 20000ms` on every call, which reads like a slow app rather than a lost connection — and a renderer reload is the common cause.
- **Pin DPI awareness before reading coordinates.** `makePerMonitorAware()` must run first; unaware and aware processes see different numbers for the same window. Derive `scale = GetWindowRect.width / innerWidth` **per call** and assert it against `devicePixelRatio`; never hardcode a scale and never cache it, because the tween alone changes the window by 500 px between two verbs.
- **Keys that a keyboard reports with the extended byte set must carry it.** `pressKey`/`pressCombo` set `KEYEVENTF_EXTENDEDKEY` for the arrows and the navigation block. Sent as a virtual key with `wScan = 0`, Windows synthesises a scancode from the VK, and without the flag an arrow arrives as the non-extended key sharing its scancode — something no hand can produce. Verified end to end: ArrowDown still moves the app's selection.
- **Every injecting verb refuses when the palette is not the foreground window.** Keystrokes reach the foreground window, and this one is `skipTaskbar`, so a verb that types or presses a key without confirming focus is recording another application's keystrokes as a Qyther result — the scenario where the suite typed its probe query into a foreign session dialog and reported that Qyther ignored typing. `hide()` already refused; `typeText`, `pressKey` and `clearInput` did not. Each returns `{refused:'unfocused', focus}` carrying the `foreground` handle/pid/title instead of injecting.
- **Arguments are validated in `driver.mjs`, not only in the MCP handlers.** The CLI reaches these verbs directly, so the layer both surfaces cross is where a check belongs. `String(undefined)` is `"undefined"`, so an omitted `text` used to type that literal into the palette; `requireNumber` rejects a non-finite coordinate before it can become a dead `SendInput`; `button` must be literally `left` or `right` (anything else silently left-clicked); `clearInput` distinguishes an empty field from a **missing** `#search-input`, which it used to score as a successful clear.
- **A cached session is dropped when its socket dies.** `need()` watches `conn.isOpen()` and rebuilds once. The CLI is safe (one verb per process) but the MCP server is long-lived: after an app restart every verb failed with "CDP socket closed" until the server process itself was restarted.
- **GDI handles are checked before use, and the pixel budget is bounded.** An unchecked null `CreateCompatibleDC`/`CreateCompatibleBitmap` made the `finally` block call `SelectObject(memDc, undefined)` and mask the real failure; and `Buffer.alloc(width*height*4)` with no cap meant an absurd rect was a multi-gigabyte allocation. `GetDIBits` must return the full scan-line count.
- **`typeText` sends one UTF-16 code unit per down/up pair**, which is already correct for astral characters: iterating `charCodeAt` yields the surrogate pair as two units, four `INPUT`s total, which is the documented mechanism. Do not "fix" it by switching text to `VK_*`, which is layout-dependent.
- **A key-down/key-up pair keeps its gap.** `SendInput` inserts events serially but with no time between them, and a zero-duration press is not something a hand produces.
- **Name what `SendInput` could not deliver.** A short insert count reports `GetLastError` and names the UIPI case. Windows is not reliably loud about a silent drop, so this does not claim to diagnose every one — it stops the harness reporting a bare "inserted 0 of 1" and blaming the app for input Windows refused to deliver.
- **A partial `GetDIBits` is a failure, not a frame.** A short scan-line copy leaves the buffer tail uninitialised and encodes as a partially transparent PNG rather than an error.
- **`preflight` is allowed to be a hard refusal, and must stay able to say no.** It refuses on multi-instance, on pid/endpoint mismatch, on scale drift, and on a full artifact drive. A preflight that always passes is a broken preflight.
- **Keyboard verbs take focus first, by clicking.** OS keystrokes reach the foreground window and this window is `skipTaskbar`, and the focus check compares **window handles**, not process ids: `npm run dev` opens DevTools detached, DevTools belongs to the same pid, and a pid equality test happily reported `focused: "already"` while three real Escape presses went into the DevTools window. Handles are koffi pointers: `String()` them before putting one in a returned object, and compare them as text. `ensureFocused` returns the foreground handle, pid and title on refusal so that state is readable from the transcript. When a step fails with `focused: false`, read `foreground.title` before suspecting the app; do not dismiss another process's dialog to get a green run.
- **The accessibility tree works; use it.** `Accessibility.enable` → `getFullAXTree` → `Accessibility.disable` returns the palette's real tree — measured **101 nodes**, including `textbox "Search for files, tools, actions..."`, `listbox "Search results"`, `option` rows with computed accessible names and `button "Keyboard shortcuts"`. Both this doc and `docs/windows-ui-harness.md` recorded that `getFullAXTree` returns 0 nodes here and that DOM queries were the only reliable tree; that was measured **without `Accessibility.enable`**, which is what switches the tree on for a CDP read, and it was wrong. `ax_snapshot` is built on the real tree, and `click_role` targets a control by role plus accessible name — the `getByRole` model, which survives a restyle that renames a class, where a CSS selector is a guess at something the caller cannot see. `queryAXTree` is not usable for name/role filtering in this Chromium: it demands a nodeId/backendNodeId/objectId, so filter client-side.
- **A name that needs a parameter is not a read.** `READS` entries take no arguments; the frame series and the AX tree are data, not caller code.
- **Per-frame geometry is sampled in the page, from the page, and every frame is attributable.** `installRecorder` arms a rAF loop on the window lifecycle events and pushes `{trace, at, h, w, op}` for 500 ms, capped at 900 entries, dropping the oldest rather than stopping so the newest animation survives. Measuring `innerHeight` rather than counting `setBounds` calls is deliberate: it survives a rewrite of `src/main/windowManager.ts` and reports what the user actually gets. The sampler is repo-authored and takes no caller argument.
- **One trace is one animation episode, not one event.** `setMode` emits `mode-changed` when the tween starts and `mode-settled` when it ends, more than one 500 ms window apart, so arming a new trace per event left the settle as the newest trace — 60 frames of a single settled height — and a consumer isolating "the last animation" reported "no height transition observed" on a tween it had just measured. A new trace starts only when the previous one has expired or none is running.
- **`latestTrace` selects by motion, not by recency alone.** Walk traces newest-first, take the first whose field moves by `minRange`, fall back to any variation, then to the newest. "Newest" is not enough and "newest that varies" is not either: the settle trace holds the last tween step plus the final constraint and was measured as `602,602,602,602,603,603,…` — a 1 px change, newer than the real 75→603 transition. Pass `'op'` for a fade and the default `'h'` for a resize.
- **Bump `RECORDER_VERSION` with any change to what is recorded, and the install must replace, not stack.** The recorder used to be installed once per app session (`if (window.__qytherHarness) return 'already'`), so a long-running dev app kept measuring with whatever the first harness process installed — a `selftest` after a recorder change still reported `tracesSeen: 0` and scored a merged buffer. A superseded sampler now retires on its next frame (version guard) and a new install cancels the previous loop's rAF handle (`window.__qytherRafId`). **Loops from before those two existed cannot be stopped**; restart the app once after such a bump. Getting this wrong is not subtle: two live samplers gave the buffer three frames per frame (gaps of `0,0,17 ms`) and a 584 ms hole where the tween should have been.
- **The recorder buffer is persistent and bounded, so waiters must not consume each other's events.** `recorderEvents` peeks; it does not drain. Draining made `set_mode` (25 ms poll) and `wait_for {kind:'event'}` (150 ms poll) a race where the faster poller consumed the event and the other reported it as never having happened. There is deliberately **no implicit time filter** — an event that fired between the caller's action and the wait is usually the one being waited for, and filtering by "since the wait started" discarded it while listing it in the same payload. A caller that needs only future events passes `cond.sinceMs`, captured before its action.
- **Mode changes settle on main's event, not on a poll.** `set_mode` presses `Alt+Shift+M`, then waits for the recorded `electron-window-mode-settled` (`window:modeSettled`, payload `{mode, height}` measured by main after the tween) at 25 ms, and only reports `settledBy: 'poll'` if the recorder was never installed. The reported `mainReportedHeight` alongside the renderer's `to` is a direct geometry-vs-announcement check. `wait_for {kind:'mode'}` still polls — it is a predicate API, not a settle detector.
- **A deadline arriving from JSON is coerced, never added as a string.** `Date.now() + "5000"` is concatenation, so the wait loop never terminates and the process spins forever holding its CDP socket. `cdp.positiveMs` coerces at the boundary, and the MCP handlers reject non-numeric coordinates outright rather than letting `NaN` become a dead `SendInput`.
- **Both capture scopes refuse when the window is hidden.** `Page.captureScreenshot` hangs to its timeout against a hidden window, and — more dangerously — a `desktop` grab of a hidden window's rect is not empty, it is *the desktop behind the palette*: another application's window, reported as a successful capture of this app and, via `save_frame`, onto disk.
- **A capture that returns bytes is not a capture that shows the app.** `screenshot` returns `frameStats` (`distinctColours`, `opaqueFraction`) because `bytes > 1000` passes for a uniformly transparent PNG and for a frame of the desktop showing someone else's window — the two failures the two scopes exist to catch.
- **The privacy gate matches filesystem paths, not "does this row mention the repo".** The old rule flagged the palette's own chrome row — `🌐 Search web for "x" Open in default browser Action`, containing no path and nothing personal — as a leak, so the frame write never happened. `foreignPaths` matches `C:\…`, `D:/…` and UNC paths, deliberately over-eager at whitespace so a path with spaces is cut short and the truncated prefix is still outside the repo: failing closed is the correct direction. It is pure and exported so the selftest can prove the gate can say no **without depending on what Everything has indexed**. The scan covers the rows, the selected row and the query itself, because the input field is rendered into the frame.
- **Artifacts go to `tmp/harness/` on the repo drive only**, capped at 40 frames / 150 MB, pruned oldest-first. Never `os.tmpdir()` — that is `C:`, which runs near-full on this box.
- **The server lives in `scripts/`, never in `src/`.** `src/main/services/mcp/AGENTS.md` requires `grep -rn "McpServer|StdioServerTransport" src/ --include="*.ts" --include="*.tsx"` to stay empty. Scope that grep to code; run against all files it matches the docs that ban the strings.
- **No backtick may survive inside a template literal.** The recorder and the read registry are JS source in template strings evaluated in the page; a backtick in a comment there terminates the host string and breaks the module at load.
- **Do not import `src/main/services/desktop/input-simulation.ts`.** It imports `screen` from Electron at module scope, so it cannot load under plain `node`; re-declare the handful of bindings needed instead. Its `clampToPhysicalScreen`, `getDpiScaleFactor` and `WindowsDesktopAdapter.clampToScreen` are also wrong for this use (primary-monitor-only, or physical-vs-DIP mixing).

## Work Guidance

- Adding a verb: implement it in `driver.mjs` as one flat `async (opts) => plain object` under 50 lines, add it to `cli.mjs` `VERBS` **with its `ok` predicate**, and add it to `mcp-server.mjs` `TOOLS` + `HANDLERS` only if it is safe for an untrusted caller. Input verbs must route through `native.mjs`.
- Adding a read: add a key to `cdp.mjs` `READS`. It takes no arguments. If a value needs a parameter, it is not a read — reconsider.
- Prefer reporting two truths over one convenient one: palette and desktop capture disagree on purpose (content vs compositor), and `selftest` asserts both.
- Keep `native.mjs` free of policy. Coordinates, clamping and the rect-inside-window check belong to `driver.mjs`.
- A selftest step must establish the state it depends on, or assert that precondition where the cause is visible. `ArrowDown` needs ≥2 selectable rows; waiting on `settled` does not supply them (`searching` reads *false* before the debounce starts) and waiting on `hasRows` returns on the synthetic `Search web for` action. Poll the row floor instead and report the count, so an index that cannot satisfy it fails with the reason visible instead of surfacing later as a mystery in another step.
- Do not order steps so an earlier one destroys the state a later one needs. The frame-write step clears the input, so it runs after the steps that need results on screen.

## Verification

```bash
npm run harness:preflight        # must refuse, with a named reason, on a dirty machine
npm run harness:selftest         # 18 steps; exit 0 only when all pass
npm run typecheck                # harness is .mjs, so this must be unaffected
grep -rn "McpServer|StdioServerTransport" src/    # empty
```

`selftest` needs a running app (`npm run dev`, started by a person) and drives the real UI: it hides and reveals the palette, changes window mode, types a query and writes a frame. Expect the visible window and the user's focus to move while it runs. Preflight refuses on a second instance, so if you started one yourself, stop **only your own** pid before running.

**Gate status: 18 steps, green twice in a row on 2026-10-15 against `npm run dev` (pid 19196, dpr 1.25), and green again after the audit fixes.** The order is load-bearing — see Work Guidance on not letting an earlier step destroy a later one's state:

- **The AX tree is live, and it changed what the suite can assert.** `getFullAXTree` returns 101 nodes after `Accessibility.enable`. `click by accessible role` targets `textbox "Search for files, tools, actions..."` — the step before it, `OS click focuses input`, still needs `#search-input`, and both land within 1 px of their computed point. Target the search field, not a footer button: the footer only exists in expanded mode, and a step that depends on which mode the previous step happened to leave behind is a flake, not a gate.
- **`height tween frame-smooth` keeps its budget: 7-16 distinct / ≤2 duplicate / monotonic / ≤260 ms span / ≤100 ms lead.** Do not loosen it, and do not put the tween back on a main-process timer. The page's rAF is a measured 59.9 Hz (median 16.7 ms, min 16.6, max 16.8), so a ramp cannot legitimately exceed ~11 frames in 180 ms — if the numbers look impossible, suspect the recorder (a stale sampler adding frames per frame) before suspecting the tween.
- **`reveal opacity trace` is scored, and its opacity bound is `<= 0.5`, not `<= 0.2`.** Once the trace is isolated correctly the first sample lands partway into the fade — a hidden window runs no rAF, so the sampler cannot start until the compositor does — and measured 0.393. `<= 0.5` still fails the regression that matters, a summon that pops in at full opacity (which samples 1). The old `0.2` was really asserting on the sampler's start offset. Dim-frame *count* is still deliberately not asserted: a hidden window's rAF does not run, so frame count measures Chromium's compositor start-up rather than the app, and that truncation is an **open finding** belonging in `src/renderer/hooks/useWindowReveal.ts`, not in this gate.
- **`window:shown event` drives its own hide→reveal.** It used to sit after the reveal and look in the buffer for an event that had already fired, so it passed on a leftover and exercised nothing. A wait can only be tested against an event that is genuinely in the future.
- **`privacy gate says no` is a pure-function assertion** over synthetic rows — a repo path allowed, the repo root case-insensitively allowed, a user profile path refused, another drive refused, a UNC path refused, chrome with no path not a leak. It has no dependence on an Everything index, and it is what makes `frame write behind the gate` meaningful. The old step passed on the refusal branch and wrote nothing, so the encode/mkdir/write/prune path was never exercised.
- **`per-char typing + results` asserts `>= 2` rows as an explicit precondition.** The hardcoded query it used, `desktop-hitl`, now matches nothing, which left one synthetic row and silently broke two steps: `ArrowDown` had nowhere to move and reported a working selection as broken, and the privacy gate refused the write on a pathless row. The query is derived from the repo's own directory name and **lower-cased, because the search is case-sensitive** — `Qyther` returns 0 rows where `qyther` returns 47.
- **`OS click focuses input` asserts the field took focus and cursor drift within 6 px**, not bit-exact equality. CSS centre → physical → the 16-bit normalised absolute move is a few px off by construction (measured 1 px), and the failure this must catch — mixing DPI-unaware and DPI-aware coordinates — is wrong by ~20% of the value.
- **`hide via real Escape` clears the query before it presses.** Escape is graded (`useKeyboard.ts`), so leftover text ate a press and the step declared a working ladder broken. Bounded at three presses so a stranded `[role="dialog"]` is survivable while a genuinely frozen Escape still fails.

The DOM-input guard skips comment lines and skips `cli.mjs`, which holds the pattern list; the behavioural assertions are the load-bearing proof.

### Deliberately not adopted

Both were researched and measured against this app; neither is a win here, and saying so is part of the record.

- **`Page.startScreencast` as the animation instrument.** Ack-paced and throttled (~5 fps reported headed in 2017, no FPS parameter), CPU-heavy on animating pages, and it observes compositor output rather than the DOM values the tween is actually asserted on. The in-page rAF sampler is the higher-resolution clock for a 180 ms tween, and the two researchers disagreed on whether ack-first pacing fixes the rate. Worth revisiting only if a dispute about compositor-vs-app behaviour actually arises.
- **`Emulation.setDeviceMetricsOverride` and CDP `Input.dispatch*`.** Both change what the page *believes* rather than what the OS did, which is the exact class of fake this harness exists to avoid; `dispatch*` also cannot reach a `WH_KEYBOARD_LL` hook.
